Linux Users, Groups & Permissions

Linux user management, groups, sudo, ownership, permissions, special files and practical DevOps interview scenarios.

QUESTION 01

Why does Linux use Users and Groups?

⭐⭐⭐⭐⭐ MUST KNOW

Linux uses users and groups to control who can access resources and what actions they are allowed to perform.

User ↓ Group Membership ↓ File Ownership ↓ Permissions ↓ Access
🎤 Interview Answer

"Linux uses users and groups to implement access control. Files and directories have ownership and permissions that determine which users can read, modify or execute them."

QUESTION 02

How do you check the current user?

⭐⭐⭐⭐⭐ 
whoami

The whoami command prints the username associated with the current session. 

id

The id command provides the user ID, primary group and supplementary group information.

Useful commands: 
whoami
id
groups
QUESTION 03

What is UID and GID?

⭐⭐⭐⭐⭐ MUST KNOW

Linux internally identifies users and groups using numeric IDs.

Term Meaning
UID User ID
GID Group ID 
id username

This displays the UID, primary GID and supplementary groups.

QUESTION 04

How do you create a user?

⭐⭐⭐⭐⭐ 
sudo useradd username

On many systems, administrators then configure a password:

sudo passwd username

A more user-friendly command on many Linux distributions is:

sudo adduser username
Remember:

The exact availability and behavior of adduser versus useradd depends on the Linux distribution.

QUESTION 05

How do you delete a user?

⭐⭐⭐⭐ 
sudo userdel username

To remove the user's home directory as part of deletion:

sudo userdel -r username
⚠️ Be careful

The -r option can remove the user's home directory and associated local files. Use it only when appropriate.

QUESTION 06

How do you modify a user?

⭐⭐⭐⭐ 
sudo usermod [options] username

Example: Add user to a group

sudo usermod -aG developers username

The -aG combination appends the user to supplementary groups without removing existing supplementary group memberships.

⚠️ Important

Using -G without -a can replace the user's supplementary group list.

QUESTION 07

What is a Linux group?

⭐⭐⭐⭐⭐

A group is a collection of users used to simplify access control.

Example:

Instead of giving permissions separately to 10 developers, you can create a developers group and assign permissions to the group.

QUESTION 08

How do you create a group?

⭐⭐⭐⭐ 
sudo groupadd developers

Check group membership:

groups username

Or:

id username
QUESTION 09

What are /etc/passwd, /etc/group and /etc/shadow?

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE
File Purpose
/etc/passwd User account information
/etc/group Group information
/etc/shadow Password hashes and password aging information
⚠️ Security

The shadow file contains sensitive authentication information and should be protected from unauthorized access.

QUESTION 10

What is sudo?

⭐⭐⭐⭐⭐ MUST KNOW

sudo allows an authorized user to execute commands with elevated privileges, according to the system's sudo configuration. 

sudo systemctl restart nginx
🎤 Interview Answer

"sudo allows authorized users to execute specific commands with elevated privileges without needing to log in directly as the root user."

QUESTION 11

What is root?

⭐⭐⭐⭐⭐

The root account is the traditional Linux superuser account with extremely broad administrative privileges.

Because root can modify critical system resources, normal administration should use controlled privilege escalation where possible.

⚠️ DevOps Best Practice

Avoid running everything as root. Use least privilege and sudo where appropriate.

QUESTION 12

What are File Permissions?

⭐⭐⭐⭐⭐ MUST KNOW

Linux permissions define what the owner, group and others can do with a file or directory.

Permission Meaning Numeric
r Read 4
w Write 2
x Execute 1
QUESTION 13

Explain rwx permissions

⭐⭐⭐⭐⭐ VERY COMMON 
-rwxr-xr--

The permissions are divided into three groups:

Owner → rwx Group → r-x Others → r--

Therefore:

  • Owner → read, write, execute
  • Group → read, execute
  • Others → read only
QUESTION 14

What does the first character mean?

⭐⭐⭐⭐ 
-rwxr-xr--
Character Meaning
- Regular file
d Directory
l Symbolic link

The remaining nine characters represent owner, group and other permissions.

QUESTION 15

What is chmod?

⭐⭐⭐⭐⭐ MUST KNOW

chmod changes file or directory permissions.

Symbolic

chmod u+x script.sh
chmod g+w file.txt
chmod o-r file.txt

Numeric

chmod 755 script.sh
QUESTION 16

Understand chmod 755

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

Calculate each permission group: 

7 = 4 + 2 + 1 = rwx

5 = 4 + 1 = r-x

5 = 4 + 1 = r-x

Therefore:

chmod 755 script.sh
Owner → rwx Group → r-x Others → r-x
QUESTION 17

Common Permission Values

⭐⭐⭐⭐⭐
Permission Meaning
644 Owner read/write, others read
755 Owner full access, others read/execute
700 Owner full access only
600 Owner read/write only
Common use:

Private SSH keys commonly need restrictive permissions such as 600.

QUESTION 18

What is chown?

⭐⭐⭐⭐⭐ MUST KNOW

chown changes file ownership. 

sudo chown user file.txt

Change owner and group:

sudo chown user:developers file.txt

Recursive ownership change:

sudo chown -R user:developers project/
⚠️ Caution

Recursive ownership changes can affect many files. Always verify the target path before using -R.

QUESTION 19

What is chgrp?

⭐⭐⭐⭐

chgrp changes the group ownership of a file or directory. 

sudo chgrp developers project/

In many cases, chown user:group is used when changing both owner and group together.

QUESTION 20

How do you check ownership and permissions?

⭐⭐⭐⭐⭐ 
ls -l

Example:

-rwxr-xr-- 1 nandu developers 1200 Aug 12 deploy.sh
Permissions → Owner → Group → Size → Date → File
🔥 REAL-TIME SCENARIO

Permission denied while running a script

⭐⭐⭐⭐⭐ DEVOPS FAVORITE 
./deploy.sh

If you get:

Permission denied

First inspect permissions:

ls -l deploy.sh

If execute permission is missing:

chmod +x deploy.sh

Then:

./deploy.sh
🔥 REAL-TIME SCENARIO

Application cannot write to a directory

⭐⭐⭐⭐⭐

Check: 

ls -ld /path/to/directory
id application-user

Verify:

  • Directory owner
  • Group ownership
  • Write permission
  • Application's running user
🎤 Strong Interview Answer

"I first identify which Linux user the application runs as. Then I check the directory's ownership and permissions and make the smallest required permission or ownership change."

🔥 REAL-TIME SCENARIO

Why should we avoid chmod 777?

⭐⭐⭐⭐⭐ MUST KNOW 
chmod 777 file

This gives read, write and execute permissions to owner, group and others.

⚠️ Security Risk

It grants broad access and violates least-privilege principles in many situations. Do not use 777 as a default fix for permission problems.

🎤 Interview Answer

"I avoid chmod 777 because it grants excessive permissions. Instead, I identify the required user or group and provide only the minimum permissions necessary."

QUESTION 24

What is the principle of least privilege?

⭐⭐⭐⭐⭐ DEVOPS + SECURITY

Least privilege means giving users, processes and services only the permissions they actually need.

Required Access ↓ Minimum Permission ↓ Reduced Attack Surface ↓ Better Security
DevOps Example:

If an application only needs write access to one directory, do not give it root access to the entire server.

QUESTION 25

File vs Directory Permissions

⭐⭐⭐⭐⭐ IMPORTANT
Permission File Directory
r Read file contents List directory entries
w Modify file Create/delete/rename entries, subject to other controls
x Execute program Traverse/access directory
Important:

Directory permissions behave differently from file permissions. A directory's execute permission is especially important for traversing/accessing paths.

QUESTION 26

What is umask?

⭐⭐⭐⭐

umask influences the default permissions assigned to newly created files and directories by removing permission bits from their base creation modes. 

umask

Example:

umask 022

The exact resulting permissions depend on whether a file or directory is being created and the system's base mode.

🎤 Interview Answer

"umask defines which permission bits are masked when new files and directories are created."

🔥 REAL-TIME SCENARIO

Docker / DevOps Permission Problem

⭐⭐⭐⭐⭐

A containerized application writes files to a host-mounted directory, but the application receives permission denied.

Container Process User ↓ Mounted Volume ↓ Host Directory ↓ Host Ownership / Permissions

Check the UID/GID used by the process and the ownership and permissions of the mounted directory. 

ls -ln /host/path
id
🎤 Interview Answer

"In containerized environments, I check the UID/GID of the application process and compare it with the ownership and permissions of the mounted host directory."

🎤 FINAL INTERVIEW QUESTIONS

Q: What is UID?
A: Numeric identifier assigned to a Linux user.

Q: What is GID?
A: Numeric identifier assigned to a Linux group.

Q: Difference between chmod and chown?
A: chmod changes permissions; chown changes ownership.

Q: What does 755 mean?
A: Owner has rwx; group and others have r-x.

Q: What does 644 mean?
A: Owner has rw-; group and others have r--.

Q: Why chmod 777 is bad?
A: It grants broad read/write/execute access and can create unnecessary security risk.

Q: What is sudo?
A: It allows authorized users to execute commands with elevated privileges.

Q: Where are Linux users stored?
A: Account information is commonly represented in /etc/passwd; sensitive password information is in /etc/shadow.

Q: Why are groups useful?
A: They simplify permission management for multiple users.

Q: How do you troubleshoot permission denied?
A: Check the current user, file ownership, permissions, directory traversal permissions and application runtime user before changing anything.
