Linux Processes, Services & Logs

Process management, system services, systemd, logs, background jobs, signals, resource monitoring and real-time DevOps troubleshooting.

QUESTION 01

What is a Process?

⭐⭐⭐⭐⭐ MUST KNOW

A process is a running instance of a program. When Linux executes a program, the operating system creates a process to manage its execution and resources.

Simple Example 
./application

When the application starts running, Linux creates a process for it.

🎤 Interview Answer

"A process is a running instance of a program. Linux assigns resources and a process ID to each running process."

QUESTION 02

What is PID?

⭐⭐⭐⭐⭐ MUST KNOW

PID stands for Process ID. Linux assigns a unique process identifier to each running process. 

ps
Example 
PID     COMMAND
1245    nginx
2480    java

Here 1245 and 2480 are process IDs.

🎤 Interview Answer

"PID is the unique identifier assigned by Linux to a running process. It is commonly used to inspect or manage that process."

COMMAND 03

How do you check running processes?

⭐⭐⭐⭐⭐ VERY COMMON 
ps

A commonly used detailed command is: 

ps aux

To find a specific process: 

ps aux | grep nginx
Useful fields
Field Meaning
USER User running the process
PID Process ID
%CPU CPU usage
%MEM Memory usage
COMMAND Command/process
COMMAND 04

top & htop

⭐⭐⭐⭐⭐ DEVOPS MUST KNOW

top provides a live view of running processes and system resource usage. 

top

If installed, htop provides a more interactive process-monitoring interface. 

htop
Use case

If a server becomes slow, use top to identify processes consuming excessive CPU or memory.

🎤 Interview Answer

"I use top or htop for real-time process and resource monitoring, and ps for a snapshot of running processes."

QUESTION 06

What is a Zombie Process?

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

A zombie process is a process that has finished execution but still has an entry in the process table because its parent has not yet collected its exit status.

Child Process ↓ Finishes Execution ↓ Exit Status Remains ↓ Parent Has Not Collected It ↓ Zombie
🎤 Interview Answer

"A zombie is a terminated child process whose exit status has not yet been collected by its parent process."

COMMAND 07

How do you terminate a process?

⭐⭐⭐⭐⭐ MUST KNOW

The kill command sends a signal to a process. 

kill PID

For example: 

kill 2480
Force termination 
kill -9 2480

SIGKILL immediately terminates the process and cannot be caught or handled by the process.

⚠️ Important

Do not use kill -9 as the first option. Prefer a normal termination signal when possible so the application has an opportunity to clean up resources.

QUESTION 08

Important Linux Signals

⭐⭐⭐⭐
Signal Number Purpose
SIGTERM 15 Request graceful termination
SIGKILL 9 Force termination
SIGHUP 1 Hangup; meaning depends on application
SIGSTOP 19 Stop process
SIGCONT 18 Continue stopped process
🎤 Interview Tip

"SIGTERM is generally preferred for graceful shutdown. SIGKILL is used when a process does not terminate normally."

QUESTION 09

Foreground vs Background Process

⭐⭐⭐⭐

A foreground process occupies the current terminal session. A background process can continue while the shell is available for other commands.

Run in background

./application &

Show jobs

jobs

Move process to background

bg

Bring process to foreground

fg
🎤 Interview Answer

"A foreground process uses the current terminal, while a background process runs without blocking the shell from accepting other commands."

COMMAND 10

nohup

⭐⭐⭐⭐

nohup allows a command to continue running after the terminal session is closed, subject to the application's behavior and environment. 

nohup ./application &

Output is commonly redirected to nohup.out if not otherwise redirected.

⚠️ Production Note

For production services, systemd, containers or orchestration platforms are generally preferable to manually keeping processes alive with nohup.

QUESTION 11

What is a Service?

⭐⭐⭐⭐⭐ MUST KNOW

A service is a long-running program that provides functionality to other applications, users or system components.

Examples
  • SSH service
  • Nginx
  • Docker daemon
  • Database service
  • Application service
🎤 Interview Answer

"A service is a long-running process that provides a specific system or application function and can commonly be managed by a service manager such as systemd."

COMMAND 12

systemctl

⭐⭐⭐⭐⭐ DEVOPS MUST KNOW

systemctl is used to interact with systemd-managed services and units on systems using systemd.

Check status

systemctl status nginx

Start service

sudo systemctl start nginx

Stop service

sudo systemctl stop nginx

Restart service

sudo systemctl restart nginx

Reload configuration

sudo systemctl reload nginx

Enable at boot

sudo systemctl enable nginx

Disable at boot

sudo systemctl disable nginx
QUESTION 13

start vs enable

⭐⭐⭐⭐⭐ VERY COMMON
Command Meaning
start Start service now
enable Configure service to start automatically at boot
restart Stop and start service
reload Reload configuration without a full restart when supported
stop Stop service
🎤 Interview Answer

"systemctl start starts a service immediately, while systemctl enable configures it to start automatically during boot."

QUESTION 14

What is systemd?

⭐⭐⭐⭐⭐ MUST KNOW

systemd is a system and service manager used by many modern Linux distributions.

It manages services, startup, dependencies, units and system state.

Boot ↓ systemd ↓ Units / Services ↓ Applications
🎤 Interview Answer

"systemd is a system and service manager used by many Linux distributions to initialize the system and manage services, units and dependencies."

QUESTION 15

What are Linux Logs?

⭐⭐⭐⭐⭐ MUST KNOW

Logs record events generated by the operating system, services and applications. They are essential for troubleshooting, auditing and monitoring.

Common log locations 
/var/log/

Examples may include: 

/var/log/syslog
/var/log/messages
/var/log/auth.log

Exact files vary by Linux distribution and configuration.

COMMAND 16

journalctl

⭐⭐⭐⭐⭐ DEVOPS MUST KNOW

journalctl is used to query logs collected by the systemd journal.

View logs

journalctl

View logs for a service

journalctl -u nginx

Follow logs live

journalctl -u nginx -f

Recent logs

journalctl -u nginx -n 100

Logs since boot

journalctl -b
🎤 Interview Answer

"I use journalctl to inspect systemd journal logs. For example, journalctl -u service-name helps investigate why a service failed or restarted."

COMMAND 17

tail & grep for Log Troubleshooting

⭐⭐⭐⭐⭐ VERY COMMON

Last lines

tail -n 50 /var/log/syslog

Follow log file

tail -f /var/log/syslog

Search errors

grep "ERROR" application.log

Combine commands

tail -f application.log | grep ERROR
DevOps Usage

During deployment, you can follow application logs in real time and search for errors to identify startup failures.

🔥 TROUBLESHOOTING 18

Service Failed to Start

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE
Service Failed ↓ systemctl status ↓ journalctl -u service ↓ Check Configuration ↓ Check Port ↓ Check Permissions ↓ Fix ↓ Restart

Commands

systemctl status nginx

journalctl -u nginx -n 100

ss -tulpn
🎤 Strong Interview Answer

"If a service fails to start, I first check systemctl status, then inspect journalctl logs for the exact error. I also verify configuration, permissions, dependencies and whether the required port is already in use."

🔥 TROUBLESHOOTING 19

Port Already in Use

⭐⭐⭐⭐⭐ DEVOPS SCENARIO

If an application cannot start because its port is already occupied, identify the process using that port. 

ss -tulpn | grep 8080

Then inspect the process: 

ps aux | grep 8080
Typical situation

Application A is already listening on port 8080. Application B tries to bind to the same port and fails.

🔥 TROUBLESHOOTING 20

High CPU Usage

⭐⭐⭐⭐⭐ VERY COMMON
High CPU ↓ top / htop ↓ Identify PID ↓ ps ↓ Check Application ↓ Inspect Logs ↓ Take Corrective Action 
top

ps aux --sort=-%cpu | head
🎤 Strong Interview Answer

"For high CPU usage, I first identify the process consuming CPU using top or ps. Then I investigate its logs and workload before deciding whether the issue requires configuration changes, scaling, restart or application-level investigation."

🔥 TROUBLESHOOTING 21

High Memory Usage

⭐⭐⭐⭐⭐ 
free -h
ps aux --sort=-%mem | head

Use free -h to inspect memory availability and ps to identify processes consuming significant memory.

DevOps Scenario

If a Java application repeatedly consumes memory and gets killed, investigate JVM configuration, application behavior, container limits and system memory pressure.

QUESTION 22

Disk Usage: df vs du

⭐⭐⭐⭐⭐ MUST KNOW

df

df -h

Shows filesystem-level disk space usage.

du

du -sh /var/log/*

Shows disk usage of files/directories.

Command Use
df -h Filesystem free/used space
du -sh Directory/file space usage
🔥 TROUBLESHOOTING 23

Disk Full Because of Logs

⭐⭐⭐⭐⭐ DEVOPS FAVORITE
Application Logs ↓ Disk Usage Increases ↓ df -h ↓ Find Large Directories ↓ du -sh ↓ Check Log Rotation ↓ Clean / Rotate Safely 
df -h

du -sh /var/log/*
⚠️ Important

Do not blindly delete active application or system logs in production. Investigate log rotation, retention and the service that is generating excessive logs.

QUESTION 24

Process vs Service

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE
Process Service
Running instance of a program Long-running system/application function
Has a PID Can be managed by service manager
Can be temporary Usually designed to provide ongoing functionality
🎤 Interview Answer

"A process is an executing instance of a program, while a service is typically a long-running component managed by a service manager such as systemd."

🔥 REAL-TIME DEVOPS SCENARIO

Application Deployment Troubleshooting

⭐⭐⭐⭐⭐ MUST PRACTICE

Suppose you deployed a Java application as a Linux service and users report that the application is unavailable.

Deployment ↓ systemctl status app ↓ Is Service Running? ↓ journalctl -u app ↓ Application Logs ↓ Check Port ↓ ss -tulpn ↓ curl localhost:8080 ↓ Network / Firewall ↓ Application Available

Commands

systemctl status app

journalctl -u app -n 100

ss -tulpn | grep 8080

curl http://localhost:8080

df -h

free -h

top
🎤 Strong Interview Answer

"I would start with the service status, inspect systemd logs, verify that the application is listening on the expected port, test the endpoint locally with curl, and then check system resources, firewall and network connectivity."
