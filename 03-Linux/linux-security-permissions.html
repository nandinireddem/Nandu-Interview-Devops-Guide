Linux Security & Permissions

Users, groups, file permissions, chmod, chown, sudo, umask, special permissions, ACL, SSH security and real-time DevOps troubleshooting.

QUESTION 01

What is Linux Security?

⭐⭐⭐⭐⭐ MUST KNOW

Linux security controls who can access files, directories, processes and system resources and what actions they are allowed to perform.

User ↓ Authentication ↓ Authorization ↓ Permissions ↓ Resource Access
💡 DevOps Example

An application should be able to read its configuration files, but it should not have permission to modify sensitive system files.

🎤 Interview Answer

"Linux security uses users, groups, permissions, ownership and privilege controls to restrict access to system resources and protect applications and data."

QUESTION 02

What is a Linux User?

⭐⭐⭐⭐⭐ MUST KNOW

A user is an identity under which processes and commands run. Linux associates each user with a UID, or User ID.

View current user 
whoami
View user identity 
id
List users 
cat /etc/passwd
🎤 Interview Answer

"A Linux user is an identity used to authenticate and control access to system resources. Each user has a unique UID."

QUESTION 03

What is the root user?

⭐⭐⭐⭐⭐ VERY COMMON

The root user is the Linux superuser with extensive privileges over the operating system. 

whoami

If the output is: 

root

the current shell is running as the root user.

⚠️ Security Principle

Avoid using root unnecessarily. Use the least privilege required to perform an operation.

🎤 Interview Answer

"Root is the Linux superuser with administrative privileges. For security, administrative access should be limited and used only when necessary."

QUESTION 04

What is a Linux Group?

⭐⭐⭐⭐⭐ MUST KNOW

A group is a collection of users that can share permissions to files, directories and other resources.

Check groups of current user 
groups
Detailed identity 
id
Users ↓ Group ↓ Shared Permissions ↓ Resources
🎤 Interview Answer

"Linux groups allow administrators to manage permissions for multiple users collectively instead of configuring permissions individually."

QUESTION 05

Linux File Permissions

⭐⭐⭐⭐⭐ MUST KNOW

Linux permissions control what the owner, group and other users can do with a file or directory. 

ls -l

Example:

-rwxr-xr--
Permission Meaning Numeric Value
r Read 4
w Write 2
x Execute 1
QUESTION 06

How do you read rwxr-xr-x?

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE
rwx Owner ↓ r-x Group ↓ r-x Others
Section Permission
Owner rwx
Group r-x
Others r-x
🎤 Interview Answer

"The first permission set belongs to the owner, the second to the group and the third to others. In rwxr-xr-x, the owner has read, write and execute permissions, while group and others have read and execute permissions."

COMMAND 07

chmod

⭐⭐⭐⭐⭐ MUST KNOW

chmod changes the permissions of files and directories.

Symbolic Mode

chmod u+x script.sh
chmod g+w file.txt
chmod o-r file.txt

Numeric Mode

chmod 755 script.sh
chmod 644 file.txt
Number Permissions
7 rwx
6 rw-
5 r-x
4 r--
0 ---
🎤 Interview Answer

"chmod is used to modify file and directory permissions. Numeric permissions represent read, write and execute values using 4, 2 and 1."

QUESTION 08

What does chmod 755 mean?

⭐⭐⭐⭐⭐ VERY COMMON
7 → rwx ↓ 5 → r-x ↓ 5 → r-x

Therefore: 

Owner  → rwx
Group  → r-x
Others → r-x
Common use

Executable scripts may commonly use 755 when they need to be executed by users other than the owner.

QUESTION 09

What does chmod 644 mean?

⭐⭐⭐⭐ 
6 → rw-
4 → r--
4 → r--

So: 

Owner  → read + write
Group  → read
Others → read
Common use

Regular text or configuration files may commonly use a 644-style permission when they do not need to be executable.

COMMAND 10

chown

⭐⭐⭐⭐⭐ MUST KNOW

chown changes file or directory ownership.

Change owner 
sudo chown nandu file.txt
Change owner and group 
sudo chown nandu:devops file.txt
Recursive ownership change 
sudo chown -R nandu:devops /app
⚠️ Be careful with -R

Recursive ownership changes affect everything below the specified directory. Always verify the path before using it.

🎤 Interview Answer

"chown changes the owner and group ownership of files and directories. It is commonly used to ensure applications have the correct ownership for accessing their files."

COMMAND 11

chgrp

⭐⭐⭐

chgrp changes the group ownership of a file or directory. 

sudo chgrp devops file.txt
Memory Trick

chown → Change owner
chgrp → Change group

QUESTION 12

What is sudo?

⭐⭐⭐⭐⭐ MUST KNOW

sudo allows an authorized user to execute a command with elevated privileges. 

sudo systemctl restart nginx
sudo apt update
🎤 Interview Answer

"sudo allows authorized users to execute specific commands with elevated privileges without logging in directly as the root user."

QUESTION 13

/etc/sudoers

⭐⭐⭐⭐

The sudoers configuration defines which users or groups are allowed to execute commands with elevated privileges.

Safely edit sudo configuration 
sudo visudo
⚠️ Important

Do not casually edit sudo configuration with a normal text editor. Syntax mistakes can cause serious administrative problems.

QUESTION 14

What is umask?

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

umask controls the default permission bits that are removed when new files and directories are created. 

umask
Example 
umask 022

A commonly encountered 022 umask results in: 

New file       → 644
New directory  → 755
🎤 Interview Answer

"umask defines which permission bits are masked when new files and directories are created. It helps control their default permissions."

QUESTION 15

Special Permissions

⭐⭐⭐⭐

Linux supports special permission bits that provide additional access-control behavior.

Permission Purpose
SUID Executable runs with owner's privileges
SGID Executable/group inheritance behavior
Sticky Bit Controls deletion in shared directories
Common example 
ls -ld /tmp

The /tmp directory commonly has the sticky bit.

QUESTION 16

What is Sticky Bit?

⭐⭐⭐⭐⭐

The sticky bit on a shared directory restricts users from deleting or renaming files owned by other users, subject to the system's permission model. 

ls -ld /tmp

You may see a permission pattern containing: 

drwxrwxrwt

The t represents the sticky bit.

🎤 Interview Answer

"The sticky bit is commonly used on shared directories so users cannot freely delete or rename files belonging to other users."

QUESTION 17

What is ACL?

⭐⭐⭐⭐

ACL stands for Access Control List. It provides more granular permissions than the traditional owner-group-other model.

View ACL 
getfacl file.txt
Set an ACL entry 
setfacl -m u:nandu:r file.txt
🎤 Interview Answer

"ACL provides fine-grained access control by allowing additional users or groups to receive specific permissions beyond the traditional owner, group and others model."

QUESTION 18

What is SSH?

⭐⭐⭐⭐⭐ MUST KNOW

SSH, or Secure Shell, is a protocol used to securely connect to remote systems and execute commands. 

ssh user@server-ip
Using a private key 
ssh -i key.pem user@server-ip
Local Machine ↓ SSH ↓ Remote Server ↓ Authentication ↓ Shell Access
🎤 Interview Answer

"SSH is a secure protocol used for remote login and command execution. In cloud environments it is commonly used by administrators and DevOps engineers to access Linux servers."

QUESTION 19

SSH Key-Based Authentication

⭐⭐⭐⭐⭐ DEVOPS MUST KNOW

SSH key authentication uses a public-private key pair instead of a password.

Private Key ↓ Client ↓ Public Key ↓ Server ↓ Authentication

The private key should remain secret, while the public key can be placed on the server.

Common key location 
~/.ssh/id_rsa
~/.ssh/id_ed25519
Authorized public keys 
~/.ssh/authorized_keys
🔐 Security Rule

Never share your private SSH key. Store it securely and protect its permissions.

QUESTION 20

Common SSH Permission Problem

⭐⭐⭐⭐⭐ REAL-TIME

SSH may reject a private key if its permissions are too open. 

chmod 400 key.pem

or, depending on the environment and security requirements: 

chmod 600 key.pem
🎤 Interview Answer

"If SSH reports that a private key is too open, I would verify the key's ownership and permissions and restrict access so that unauthorized users cannot read the private key."

QUESTION 21

File vs Directory Permissions

⭐⭐⭐⭐⭐ MUST KNOW
Permission File Directory
Read Read file contents List directory entries
Write Modify file Create/delete/rename entries subject to other permissions
Execute Execute program/script Access/traverse directory
🎤 Interview Answer

"Read, write and execute have different practical meanings on files and directories. On a directory, execute permission is especially important because it allows traversal and access to entries."

🔥 REAL-TIME DEVOPS SCENARIO

Application cannot read its configuration file

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE
Application Error ↓ ls -l config-file ↓ Check Owner ↓ Check Group ↓ Check Permissions ↓ Check Parent Directory ↓ Fix Ownership/Permissions ↓ Test Application 
ls -l /app/config/application.yml

id appuser

namei -l /app/config/application.yml

Then, if appropriate: 

sudo chown appuser:appgroup /app/config/application.yml
sudo chmod 640 /app/config/application.yml
⚠️ Don't simply use chmod 777

Fix the actual ownership or permission requirement instead of giving everyone unrestricted access.

🎤 Strong Interview Answer

"I would first inspect the file ownership and permissions, then verify the application's user and group. I would also check permissions on the parent directories. I would make the smallest permission or ownership change necessary and then test again."

QUESTION 22

Why should you avoid chmod 777?

⭐⭐⭐⭐⭐ VERY COMMON

777 gives read, write and execute permissions to the owner, group and others. 

777 → rwxrwxrwx
🚨 Security Risk

Giving everyone write and execute access can allow unauthorized modification or execution and increase the attack surface.

🎤 Interview Answer

"I avoid chmod 777 because it grants excessive permissions to everyone. I follow the principle of least privilege and grant only the permissions required by the application or user."

COMMAND 23

User & Group Management

⭐⭐⭐⭐
Create user 
sudo useradd nandu
Create group 
sudo groupadd devops
Add user to group 
sudo usermod -aG devops nandu
Verify 
id nandu
⚠️ Important

Use -aG when adding supplementary groups so existing supplementary group memberships are not unintentionally replaced.

COMMAND 24

Password Management

⭐⭐⭐
Set or change password 
sudo passwd nandu
Lock account 
sudo passwd -l nandu
Unlock account 
sudo passwd -u nandu
QUESTION 25

Linux Security Best Practices

⭐⭐⭐⭐⭐ DEVOPS MUST KNOW
  • Follow the principle of least privilege.
  • Avoid unnecessary root access.
  • Use SSH keys where appropriate.
  • Protect private SSH keys.
  • Avoid chmod 777.
  • Keep systems and packages updated.
  • Use strong authentication practices.
  • Restrict unnecessary network access.
  • Monitor logs and authentication activity.
  • Use service-specific users where appropriate.
🎤 Interview Answer

"I follow least privilege, minimize root access, secure SSH authentication, protect private keys, avoid excessive permissions, keep systems updated and monitor logs for suspicious activity."

🔥 REAL-TIME TROUBLESHOOTING

Permission Denied — What Will You Check?

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE
Permission Denied ↓ whoami / id ↓ ls -l target ↓ Check Owner ↓ Check Group ↓ Check rwx ↓ Check Parent Directories ↓ Check ACL ↓ Fix Minimum Required Permission 
whoami
id
ls -l file.txt
namei -l /path/to/file
getfacl file.txt
🎤 Strong Answer

"First I identify the user running the command. Then I check the file's owner, group and permissions. I also verify permissions on parent directories and check ACLs if necessary. Finally, I apply the minimum required permission or ownership change."
