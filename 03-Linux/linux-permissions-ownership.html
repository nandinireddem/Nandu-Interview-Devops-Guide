Linux Permissions & Ownership

Linux file permissions, ownership, chmod, chown, chgrp, rwx, numeric permissions, umask and real-world DevOps scenarios.

QUESTION 01

What are Linux File Permissions?

⭐⭐⭐⭐⭐ MUST KNOW

Linux file permissions control who can read, modify or execute a file or directory.

The three basic permissions are:

→ r = Read
→ w = Write
→ x = Execute

💡 Example 
-rwxr-xr--

This permission string tells us which operations are allowed for the owner, group and others.

🎤 Interview Answer

"Linux permissions control access to files and directories. The basic permissions are read, write and execute, and they are assigned separately to the owner, group and other users."

QUESTION 02

Linux File Ownership

⭐⭐⭐⭐⭐ MUST KNOW

Every Linux file and directory has an owner and an associated group.

File ↓ Owner + Group ↓ Permissions ↓ User Access
💡 Check ownership 
ls -l

Example output:

-rw-r--r-- 1 nandu devops 1200 app.log

Here:

Owner → nandu
Group → devops

🎤 Interview Answer

"Linux associates each file with an owner and a group. Permissions are then defined for the owner, group members and other users."

QUESTION 03

How do you check permissions?

⭐⭐⭐⭐⭐ VERY COMMON

Use the ls -l command. 

ls -l app.sh

Example:

-rwxr-xr-- 1 nandu devops 2048 Aug 12 app.sh
Part Meaning
- File type
rwx Owner permissions
r-x Group permissions
r-- Others permissions
nandu Owner
devops Group
QUESTION 04

What do r, w and x mean?

⭐⭐⭐⭐⭐ MUST KNOW
Permission File Directory
r Read file contents List directory contents
w Modify file Create/delete/rename entries
x Execute file Enter/access directory
🧠 Important:

Execute permission on a directory means you can access/traverse that directory. Directory permissions behave differently from file permissions.

🎤 Interview Answer

"For files, read allows viewing contents, write allows modifying contents and execute allows running the file. For directories, read allows listing entries, write allows modifying directory entries and execute allows traversing or accessing the directory."

QUESTION 05

Owner, Group and Others

⭐⭐⭐⭐⭐ MUST KNOW

Linux permissions are divided into three categories.

Owner ↓ Group ↓ Others
Category Meaning
Owner User who owns the file
Group Users belonging to the associated group
Others All other users
Example 
-rwxr-x---

Owner → rwx
Group → r-x
Others → ---

COMMAND 06

chmod — Change Permissions

⭐⭐⭐⭐⭐ MUST KNOW

The chmod command changes permissions on files and directories.

💡 Symbolic Mode 
chmod u+x script.sh

chmod g+w file.txt

chmod o-r file.txt

chmod a+x script.sh
Symbol Meaning
u User / Owner
g Group
o Others
a All
🎤 Interview Answer

"chmod is used to modify Linux file permissions. It supports symbolic notation such as u, g, o and a, as well as numeric permission notation."

QUESTION 07

Numeric Permissions in Linux

⭐⭐⭐⭐⭐ VERY COMMON

Linux permissions can also be represented using numeric values.

Permission Value
Read (r) 4
Write (w) 2
Execute (x) 1

The values are added together for each permission group.

💡 Example: 755 
7 = 4 + 2 + 1 = rwx

5 = 4 + 1 = r-x

5 = 4 + 1 = r-x

Therefore: 

755 = rwxr-xr-x
💡 Example: 644 
6 = 4 + 2 = rw-

4 = r--

4 = r--

Therefore: 

644 = rw-r--r--
🎤 Interview Answer

"In numeric Linux permissions, read is 4, write is 2 and execute is 1. The values are added for owner, group and others. For example, 755 represents rwxr-xr-x and 644 represents rw-r--r--."

QUESTION 08

Common Permission Values

⭐⭐⭐⭐⭐ MUST KNOW
Value Permission Typical Usage
777 rwxrwxrwx Full access to everyone — usually avoid
755 rwxr-xr-x Executable scripts/directories
700 rwx------ Owner only
644 rw-r--r-- Regular files
600 rw------- Private/sensitive files
⚠️ Important

Avoid blindly using chmod 777. It grants read, write and execute permissions to everyone and can create security risks.

COMMAND 09

chown — Change Ownership

⭐⭐⭐⭐⭐ MUST KNOW

The chown command changes the owner and optionally the group of a file or directory.

💡 Examples 
sudo chown nandu app.log

sudo chown nandu:devops app.log

sudo chown -R nandu:devops /opt/app

The -R option applies the ownership change recursively.

🎤 Interview Answer

"chown is used to change the owner of a file or directory. It can also change the associated group, and the -R option applies the change recursively."

COMMAND 10

chgrp — Change Group Ownership

⭐⭐⭐

The chgrp command changes the group associated with a file or directory. 

sudo chgrp devops app.log

sudo chgrp -R devops /opt/app
🎤 Interview Answer

"chgrp is used to change the group ownership of a file or directory."

QUESTION 11

whoami and id

whoami

id

QUESTION 12

What is umask?

⭐⭐⭐⭐ INTERVIEW

umask defines the default permission restrictions applied when new files and directories are created.

💡 Check current umask 
umask

A common value is: 

0022

The exact resulting permissions depend on the system's default base permissions and the umask value.

🎤 Interview Answer

"umask defines default permission restrictions for newly created files and directories. It prevents certain permission bits from being granted by default."

QUESTION 13

How do you make a script executable?

⭐⭐⭐⭐⭐ VERY COMMON

Use chmod +x. 

chmod +x deploy.sh

./deploy.sh

You can verify it using: 

ls -l deploy.sh
🎤 Interview Answer

"I would add execute permission using chmod +x and then execute the script using ./script-name.sh."

QUESTION 14

Why are SSH private key permissions important?

⭐⭐⭐⭐⭐ AWS / DEVOPS FAVORITE

SSH private keys contain sensitive authentication material and should not be accessible to other users.

💡 Common permission 
chmod 400 my-key.pem

Then connect: 

ssh -i my-key.pem ec2-user@SERVER-IP
⚠️ Important

If an SSH private key is too permissive, SSH may reject it for security reasons. Always protect private keys appropriately.

🎤 Interview Answer

"SSH private keys should have restrictive permissions so that other users cannot read them. A common practice is chmod 400 or another appropriately restrictive permission depending on the environment."

🔥 REAL-TIME DEVOPS SCENARIO

Application cannot read its configuration file

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

Suppose an application is running on a Linux server but cannot read its configuration file.

Check User ↓ Check File ↓ Check Ownership ↓ Check Permissions ↓ Fix Ownership / Permissions ↓ Test Application
Step 1 — Identify current user 
whoami
id
Step 2 — Check file permissions 
ls -l /opt/app/config.yaml
Step 3 — Change ownership if required 
sudo chown appuser:appgroup /opt/app/config.yaml
Step 4 — Set appropriate permissions 
sudo chmod 640 /opt/app/config.yaml
Step 5 — Verify 
ls -l /opt/app/config.yaml
🎤 Strong Interview Answer

"First I would identify which user the application is running as. Then I would inspect the file's ownership and permissions using ls -l. If required, I would correct the owner or group using chown and set the minimum required permissions using chmod. I would then test the application again."

QUESTION 15

What is the Principle of Least Privilege?

⭐⭐⭐⭐⭐ SECURITY MUST KNOW

The principle of least privilege means giving users, processes and applications only the permissions they actually need.

❌ Bad Practice 
chmod 777 application.conf
✅ Better Approach 
chmod 640 application.conf

Then assign the appropriate owner and group.

🎤 Interview Answer

"Least privilege means granting only the minimum permissions required for a user or application to perform its task. This reduces the security impact of accidental or unauthorized access."

TROUBLESHOOTING

🎯 Permission Denied — What would you check?

⭐⭐⭐⭐⭐ DEVOPS FAVORITE

When a Linux command returns "Permission denied", I would inspect the current user, file ownership, permissions and directory access. 

whoami

id

ls -l file.txt

ls -ld /path/to/directory

Then, depending on the requirement: 

sudo chown user:group file.txt

sudo chmod 640 file.txt
🎤 Strong Interview Answer

"For a permission denied issue, I would first identify the current user and groups, then inspect the file and parent directory permissions. I would verify ownership and only make the minimum required permission or ownership change. I would avoid blindly granting broad permissions such as 777."
