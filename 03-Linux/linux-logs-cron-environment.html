Linux Logs, Cron & Environment

The final Linux module: logs, troubleshooting, cron jobs, environment variables, shell basics and practical DevOps usage.

QUESTION 01

What are Linux Logs?

⭐⭐⭐⭐⭐ MUST KNOW

Linux logs record events generated by the operating system, services, applications and other components. They are essential for troubleshooting.

Problem
↓
Check Status
↓
Check Logs
↓
Identify Error
↓
Fix Root Cause
🎤 Interview Answer

"Linux logs provide information about system and application events. I use them to investigate failures, authentication problems, service issues and unexpected behavior."

QUESTION 02

Where are Linux Logs stored?

⭐⭐⭐⭐⭐

Traditional Linux systems commonly store many logs under: 

/var/log/

Examples you may encounter include: 

/var/log/syslog
/var/log/messages
/var/log/auth.log
/var/log/secure
/var/log/kern.log
Important:

Exact log files depend on the Linux distribution and its logging configuration. Modern systems may rely heavily on systemd's journal.

QUESTION 03

How do you read a log file?

⭐⭐⭐⭐⭐

Read entire file

cat /var/log/syslog

Read page by page

less /var/log/syslog

Show last lines

tail /var/log/syslog

Follow new log entries

tail -f /var/log/syslog

Search inside a log

grep "error" /var/log/syslog
🔥 DevOps Favorite

tail -f is extremely useful when watching an application log while reproducing a problem.

QUESTION 04

What is journalctl?

⭐⭐⭐⭐⭐ MUST KNOW

journalctl is used to query and inspect logs collected by systemd's journal. 

journalctl

View logs for a service

journalctl -u nginx

Follow service logs

journalctl -u nginx -f

Show recent logs

journalctl --since "1 hour ago"

Show current boot logs

journalctl -b
🎤 Interview Answer

"I use journalctl to inspect systemd journal logs, especially when troubleshooting services managed by systemd."

QUESTION 05

What is dmesg?

⭐⭐⭐⭐

dmesg displays messages from the kernel ring buffer and can help investigate kernel and hardware-related events. 

dmesg

For readable timestamps on systems supporting the option: 

dmesg -T
Use cases:

Hardware detection, driver messages, kernel events and some boot/device troubleshooting.

QUESTION 06

How do you troubleshoot a failed service?

⭐⭐⭐⭐⭐ REAL-TIME

Suppose nginx is not working.

systemctl status
↓
journalctl
↓
Configuration Check
↓
Port Check
↓
Fix
↓
Restart 
systemctl status nginx
journalctl -u nginx --no-pager
ss -lntp

Then validate the configuration if the service supports a config test command before restarting.

🎤 Strong Interview Answer

"I first check the service status, then inspect its logs, verify configuration and dependencies, check whether the expected port is available, fix the root cause and restart the service."

QUESTION 07

What is Cron?

⭐⭐⭐⭐⭐ MUST KNOW

Cron is a time-based job scheduling mechanism commonly used to run commands or scripts automatically at specified times.

Schedule
↓
Cron
↓
Command / Script
↓
Automatic Execution
🎤 Interview Answer

"Cron is used to schedule recurring tasks such as backups, cleanup scripts, reports and maintenance jobs."

QUESTION 08

What is Crontab?

⭐⭐⭐⭐⭐

A crontab contains scheduled commands for a user.

Open current user's crontab

crontab -e

List current user's cron jobs

crontab -l

Remove current user's crontab

crontab -r
⚠️ Careful:

crontab -r removes the user's crontab. Do not run it unless you intentionally want to remove the scheduled jobs.

QUESTION 10

Common Cron Examples

⭐⭐⭐⭐⭐

Every minute

* * * * * /path/to/script.sh

Every day at midnight

0 0 * * * /path/to/script.sh

Every day at 2:30 AM

30 2 * * * /path/to/script.sh

Every Sunday at 3:00 AM

0 3 * * 0 /path/to/script.sh

Every 5 minutes

*/5 * * * * /path/to/script.sh
QUESTION 11

Important Cron Pitfall

⭐⭐⭐⭐⭐ DEVOPS

Cron runs with a limited environment compared with an interactive shell. A script that works manually may fail under cron because commands, paths or environment variables are different.

Better: 
/usr/bin/python3 /opt/scripts/backup.py

Using an explicit executable path can make scheduled jobs more predictable.

Always use absolute paths where appropriate and capture output/error logs for important jobs.

QUESTION 12

What is an Environment Variable?

⭐⭐⭐⭐⭐ MUST KNOW

An environment variable is a named value made available to a process through its environment. 

echo $HOME

Common examples: 

HOME
PATH
USER
SHELL
PWD
LANG
🎤 Interview Answer

"Environment variables provide configuration values to processes without requiring those values to be hard-coded into the program."

QUESTION 13

How do you view Environment Variables?

⭐⭐⭐⭐⭐

Print one variable

echo $PATH

Show exported environment

env

Another commonly used command

printenv

Inspect shell variables and functions too

set
Remember:

env and printenv primarily show environment variables, while set can include shell variables and functions.

QUESTION 14

How do you create an Environment Variable?

⭐⭐⭐⭐⭐

Shell variable

APP_ENV=production

Export it to child processes

export APP_ENV=production

Verify

echo $APP_ENV
Important:

A shell variable does not automatically become part of the environment inherited by child processes. export makes it an exported environment variable.

QUESTION 15

What is PATH?

⭐⭐⭐⭐⭐ MUST KNOW

PATH is a colon-separated list of directories that the shell searches when you execute a command without specifying its full path. 

echo $PATH

Example structure: 

/usr/local/bin:/usr/bin:/bin
Example:

When you run python3, the shell searches directories listed in PATH for an executable named python3.

QUESTION 16

How do you find the location of a command?

⭐⭐⭐⭐ 
which python3

You can also use: 

command -v python3

For shell command resolution, command -v is often a portable and useful choice.

QUESTION 17

What is .bashrc?

⭐⭐⭐⭐⭐

~/.bashrc is a shell startup configuration file commonly used by interactive Bash shells.

It can contain:

  • Aliases
  • Functions
  • Environment setup
  • PATH modifications
  • Shell configuration

After modifying it, you can reload it in the current shell: 

source ~/.bashrc
Important:

Startup files differ depending on the shell and whether the shell is interactive or login. Do not assume every shell uses .bashrc.

QUESTION 18

What is Shell?

⭐⭐⭐⭐⭐ MUST KNOW

A shell is a command interpreter that provides an interface for interacting with the operating system.

ShellExample
BashCommon Linux shell
shTraditional shell interface
ZshInteractive shell used on many systems

Check the current user's configured shell: 

echo $SHELL
QUESTION 19

Useful Shell Basics for DevOps

⭐⭐⭐⭐⭐

Command substitution

echo "Today is $(date)"

Variable

NAME="Nandu"
echo $NAME

Exit status

echo $?

An exit status of 0 generally indicates success, while a non-zero status generally indicates some form of failure.

Pipe

ps aux | grep nginx

Redirect output

command > output.txt

Append output

command >> output.txt

Redirect errors

command 2> error.log

Redirect output and errors

command > output.log 2>&1

🔥 REAL-TIME SCENARIO

Script Works Manually but Fails in Cron

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

Possible reasons:

  • Different PATH
  • Missing environment variables
  • Relative paths
  • Different working directory
  • Permissions
  • Different user

Use absolute paths and log output. 

/usr/bin/python3 /opt/scripts/job.py >> /var/log/job.log 2>&1
🎤 Interview Answer

"Cron has a different execution environment, so I verify PATH, environment variables, permissions, user context and absolute paths, then capture stdout and stderr for troubleshooting."

🔥 REAL-TIME SCENARIO

Command: "command not found"

⭐⭐⭐⭐⭐

Check whether the command exists: 

command -v kubectl
which kubectl

Then inspect: 

echo $PATH

If the executable exists outside PATH, either use its full path or configure PATH appropriately.

🔥 REAL-TIME SCENARIO

Application Cannot Read an Environment Variable

⭐⭐⭐⭐⭐ DEVOPS 
echo $APP_ENV
env | grep APP_ENV

If the variable exists in your interactive shell but not in the application, check how the application is started.

For systemd services, inspect the service configuration and its environment rather than assuming your interactive shell's variables are inherited.

Linux Final Cheat Sheet

Logs → Troubleshoot system and application events.

/var/log → Common location for traditional log files.

journalctl → Query systemd journal logs.

dmesg → Kernel ring-buffer messages.

tail -f → Follow new lines in a log.

cron → Schedule recurring tasks.

crontab -e → Edit user's scheduled jobs.

Environment Variable → Configuration/value available to a process.

export → Export a shell variable to child processes.

PATH → Directories searched for executable commands.

.bashrc → Common Bash interactive-shell configuration file.

$? → Exit status of the previous command.

| → Pipe output from one command into another.

> → Redirect/overwrite output.

>> → Append output.

2> → Redirect standard error.

🎤 FINAL LINUX INTERVIEW QUESTIONS

Q: Where do Linux logs commonly exist?
A: Many traditional logs are under /var/log, while systemd systems commonly use the journal.

A: A command used to query systemd journal logs.

Q: How do you troubleshoot a failed systemd service?
A: Check systemctl status, inspect journalctl -u, verify configuration, dependencies, permissions and ports.

Q: What is cron?
A: A mechanism for scheduling recurring commands or scripts.

Q: What is crontab?
A: A user's scheduled-job configuration.

Q: Why can a cron job fail even though the script works manually?
A: Cron may have a different environment, PATH, user, working directory or permissions.

Q: What is an environment variable?
A: A named value made available to a process through its environment.

Q: What is PATH?
A: A list of directories searched for executable commands.

Q: What does export do?
A: It places a shell variable into the environment inherited by child processes.

Q: What does $? mean?
A: The exit status of the previous command.

Q: How do you troubleshoot "command not found"?
A: Verify the executable exists, inspect PATH and use command -v or the executable's full path.
