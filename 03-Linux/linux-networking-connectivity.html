Linux Networking & Connectivity

Network interfaces, IP addresses, routing, DNS, ports, ping, curl, ss, hostname, /etc/hosts, troubleshooting and real-time DevOps scenarios.

QUESTION 01

What is Linux Networking?

⭐⭐⭐⭐⭐ MUST KNOW

Linux networking allows a server to communicate with other systems, applications and network services using interfaces, IP addresses, routes, ports and network protocols.

Application ↓ TCP / UDP ↓ IP ↓ Network Interface ↓ Network ↓ Remote Server
🎤 Interview Answer

"Linux networking provides the mechanisms required for a system to communicate with other systems using network interfaces, IP addressing, routing, ports and network protocols."

QUESTION 02

What is an IP Address?

⭐⭐⭐⭐⭐ MUST KNOW

An IP address identifies a device or network interface on an IP network and allows systems to communicate with each other.

IPv4 Example

192.168.1.10

Private IP

Private IP addresses are commonly used inside internal networks. For example: 

10.0.0.10
172.16.1.10
192.168.1.10
🎤 Interview Answer

"An IP address identifies a network interface and allows systems to communicate across an IP network."

COMMAND 03

How do you check the IP address in Linux?

⭐⭐⭐⭐⭐ MUST KNOW 
ip addr

A shorter commonly used form: 

ip a

To view a particular interface: 

ip addr show eth0
Useful related command 
ip link

Shows network interfaces and their state.

QUESTION 04

What is Routing?

⭐⭐⭐⭐⭐ DEVOPS MUST KNOW

Routing determines where network packets should be sent to reach their destination.

View routing table 
ip route
Application ↓ Destination IP ↓ Routing Table ↓ Next Hop / Interface ↓ Destination
🎤 Interview Answer

"Routing determines the path or next hop used to deliver packets toward their destination. Linux maintains a routing table that can be inspected using ip route."

QUESTION 05

What is a Default Route?

⭐⭐⭐⭐

A default route is used when no more specific route exists for the destination. 

ip route

You may see something similar to: 

default via 192.168.1.1 dev eth0
Meaning

Traffic for destinations not covered by more specific routes is sent through the configured default gateway.

COMMAND 06

What is ping?

⭐⭐⭐⭐⭐ MUST KNOW

ping is commonly used to test IP-level reachability and observe round-trip response time using ICMP. 

ping 8.8.8.8
ping google.com
⚠️ Important

A failed ping does not always mean the application or server is down. ICMP may be blocked by a firewall or security policy.

🎤 Interview Answer

"I use ping as a basic connectivity test. However, I don't rely on ping alone because ICMP may be blocked even when application traffic is working."

QUESTION 07

What is a Port?

⭐⭐⭐⭐⭐ MUST KNOW

A port identifies a network service or endpoint on a host. TCP and UDP use port numbers to distinguish services.

Service Common Port
SSH 22
HTTP 80
HTTPS 443
DNS 53
MySQL 3306
PostgreSQL 5432
🎤 Interview Answer

"A port identifies a network service on a host. For example, SSH commonly uses port 22 and HTTPS commonly uses port 443."

COMMAND 08

How do you check listening ports?

⭐⭐⭐⭐⭐ DEVOPS MUST KNOW 
ss -tuln

A more detailed view: 

ss -tulpn
Option Meaning
-t TCP
-u UDP
-l Listening
-n Numeric addresses/ports
-p Show process information when permitted
DevOps Example

If an application is expected to listen on port 8080: 

ss -tulpn | grep 8080
COMMAND 09

What is curl?

⭐⭐⭐⭐⭐ VERY COMMON

curl is a command-line tool used to communicate with URLs and test HTTP/HTTPS endpoints. 

curl http://localhost:8080
curl -I https://example.com
DevOps Usage

After deploying an application, curl can be used to verify that an HTTP endpoint responds correctly.

🎤 Interview Answer

"I use curl to test HTTP or HTTPS connectivity and verify whether an application endpoint is responding as expected."

COMMAND 10

wget

⭐⭐⭐

wget is commonly used to download files or retrieve resources over HTTP, HTTPS and other supported protocols. 

wget https://example.com/file.zip
Memory Trick

curl → Test/communicate with endpoints
wget → Commonly download files

QUESTION 11

What is DNS?

⭐⭐⭐⭐⭐ MUST KNOW

DNS, or Domain Name System, translates domain names into IP addresses and can provide other DNS records.

google.com ↓ DNS Resolver ↓ IP Address ↓ Server Connection
Example 
google.com → IP address
🎤 Interview Answer

"DNS translates human-readable domain names into IP addresses so clients can locate network services."

COMMAND 12

How do you troubleshoot DNS?

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

nslookup

nslookup google.com

dig

dig google.com

These commands help inspect DNS resolution and responses.

DevOps Scenario

If: 

curl https://example.com

fails because the hostname cannot be resolved, check DNS resolution using: 

nslookup example.com
dig example.com
COMMAND 13

hostname

⭐⭐⭐

The hostname command displays or works with the system's host name. 

hostname
hostname -I
Useful distinction

hostname → system name
hostname -I → configured IP addresses

QUESTION 14

/etc/hosts

⭐⭐⭐⭐⭐ DEVOPS MUST KNOW

The /etc/hosts file provides local hostname-to-IP mappings. 

cat /etc/hosts

Example: 

127.0.0.1 localhost
10.0.1.20 app-server
DevOps Usage

It can be useful for controlled local hostname resolution and testing, although production DNS architecture should be designed appropriately.

QUESTION 15

/etc/resolv.conf

⭐⭐⭐⭐

This file commonly contains DNS resolver configuration such as nameserver information, although on modern Linux systems it may be managed dynamically by another service. 

cat /etc/resolv.conf
Typical entry 
nameserver 8.8.8.8

The actual resolver configuration depends on the Linux distribution and network management system.

QUESTION 16

netstat vs ss

⭐⭐⭐

netstat is a traditional networking command, while ss is the modern tool commonly preferred on Linux systems. 

netstat -tuln
ss -tuln
🎤 Interview Answer

"ss is generally preferred on modern Linux systems for inspecting sockets and listening ports, while netstat is an older commonly known tool."

QUESTION 17

TCP vs UDP

⭐⭐⭐⭐⭐ MUST KNOW
TCP UDP
Connection-oriented Connectionless
Reliable delivery No built-in delivery guarantee
Ordered byte stream Datagrams
More protocol overhead Lower overhead
Common examples

HTTP/HTTPS commonly use TCP-based connections, while DNS can use both UDP and TCP depending on the situation.

🎤 Interview Answer

"TCP provides reliable, connection-oriented communication, while UDP is connectionless and has lower protocol overhead but does not provide TCP's delivery guarantees."

QUESTION 18

Firewall & Network Access

⭐⭐⭐⭐⭐ DEVOPS MUST KNOW

A firewall controls which network traffic is allowed or denied based on configured rules.

Client ↓ Network Firewall / Security Group ↓ Server ↓ Application Port
Real-Time Example

An application listens on port 8080, but the firewall blocks incoming traffic to that port. The service can be running correctly while clients still cannot connect.

🎤 Interview Answer

"If a service is running but unreachable, I check the service binding and port first, then firewall or security-group rules, routing and network connectivity."

🔥 TROUBLESHOOTING 19

Connection Refused

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

A connection refused error often means the destination host is reachable but no service is accepting the connection on that port, or a device is actively rejecting it.

Connection Refused ↓ Check Application ↓ Check Listening Port ↓ ss -tulpn ↓ Check Bind Address ↓ Check Firewall ↓ Test Again 
ss -tulpn | grep 8080
curl http://localhost:8080
🔥 TROUBLESHOOTING 20

Connection Timeout

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

A timeout often indicates that traffic is not receiving a response within the expected period.

Possible causes include:

  • Firewall blocking traffic
  • Security group/network ACL rules
  • Routing problems
  • Network path failure
  • Service not reachable
  • Incorrect IP or port
ping server-ip
ip route
ss -tulpn
curl -v http://server-ip:8080
🔥 TROUBLESHOOTING 21

DNS Resolution Failure

⭐⭐⭐⭐⭐

If a hostname cannot be resolved, investigate DNS configuration before assuming the application itself is down.

Hostname ↓ DNS Lookup ↓ No IP ↓ Check DNS ↓ nslookup / dig ↓ Resolver Configuration 
nslookup example.com
dig example.com
cat /etc/resolv.conf
🔥 REAL-TIME DEVOPS SCENARIO

Application is running but users cannot access it

⭐⭐⭐⭐⭐ VERY IMPORTANT
Application Running? ↓ Check Process ↓ Check Listening Port ↓ Check IP / Bind Address ↓ Check Local curl ↓ Check Firewall / Security Group ↓ Check Route ↓ Check DNS ↓ Test From Client

Useful Commands

ps aux | grep application
ss -tulpn
ip addr
ip route
curl http://localhost:8080
curl http://server-ip:8080
nslookup app.example.com
🎤 Strong Interview Answer

"I would troubleshoot layer by layer. First I verify that the application process is running and listening on the expected port. Then I test locally with curl, verify the server IP and route, inspect firewall or security-group rules, and finally check DNS and connectivity from the client."

QUESTION 22

Simple Network Troubleshooting Flow

⭐⭐⭐⭐⭐ MUST REMEMBER
1. Is the application running? ↓ 2. Is the port listening? ↓ 3. Can localhost access it? ↓ 4. Is the IP correct? ↓ 5. Is routing correct? ↓ 6. Is firewall/security group allowing traffic? ↓ 7. Does DNS resolve? ↓ 8. Can the client connect?
