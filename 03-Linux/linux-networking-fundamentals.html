Linux Networking Fundamentals

IP addresses, interfaces, ports, DNS, routing, connectivity testing, network troubleshooting and practical DevOps scenarios.

QUESTION 02

What is an IP Address?

⭐⭐⭐⭐⭐ MUST KNOW

An IP address identifies a network interface or endpoint on an IP network.

IPv4 Example

192.168.1.10

IPv6 Example

2001:db8::10
TypeExample
IPv4192.168.1.10
IPv62001:db8::10
QUESTION 03

How do you check the IP address?

⭐⭐⭐⭐⭐ VERY COMMON 
ip addr

A commonly used shorter form is: 

ip a

This displays network interfaces and their assigned addresses.

Modern command:

Prefer the ip command for current Linux administration. Older systems may also contain commands such as ifconfig.

QUESTION 04

What is a Network Interface?

⭐⭐⭐⭐

A network interface is the software-visible connection through which a Linux system communicates over a network.

Examples commonly include: 

eth0
ens5
enp0s3
lo

The exact interface name depends on the system.

Loopback

lo

The loopback interface is used for communication within the local system. Its commonly used IPv4 address is 127.0.0.1.

QUESTION 05

How do you check network interfaces?

⭐⭐⭐⭐⭐ 
ip link

For addresses and interfaces together: 

ip addr

To inspect a specific interface: 

ip addr show eth0
QUESTION 06

What is a MAC Address?

⭐⭐⭐⭐

A MAC address is a hardware/link-layer address associated with a network interface. 

ip link

The output contains a value such as: 

link/ether 02:42:ac:11:00:02
🎤 Interview Answer

"A MAC address identifies a network interface at the data-link layer, while an IP address is used for communication at the network layer."

A default gateway is the router used when traffic does not have a more specific route in the routing table. 

ip route

QUESTION 08

What is a Routing Table?

⭐⭐⭐⭐⭐ DEVOPS FAVORITE

A routing table tells Linux where network traffic should be sent. 

ip route

Typical information includes:

  • Destination network
  • Gateway
  • Network interface
  • Route metric
🎤 Interview Answer

"The routing table determines where packets should be forwarded based on their destination."

QUESTION 09

What is DNS?

⭐⭐⭐⭐⭐ MUST KNOW

DNS stands for Domain Name System. It translates domain names into IP addresses and can provide other DNS records.

google.com
↓
DNS Lookup
↓
IP Address
↓
Server

Without DNS, users and applications would often need to use IP addresses directly instead of domain names.

QUESTION 10

How do you test DNS resolution?

⭐⭐⭐⭐⭐ 
nslookup example.com

Another commonly used command: 

dig example.com

On systems using systemd-resolved, you may also encounter: 

resolvectl status
QUESTION 11

What is /etc/hosts?

⭐⭐⭐⭐⭐

/etc/hosts provides local hostname-to-IP mappings. 

127.0.0.1 localhost
192.168.1.20 app-server

The local hosts file can be useful for testing or simple local name resolution.

⚠️ Important

Changes to /etc/hosts affect the local system and do not create a global DNS record.

QUESTION 12

What is a Port?

⭐⭐⭐⭐⭐ MUST KNOW

A port identifies a network service endpoint on a host.

ServiceCommon Port
SSH22
HTTP80
HTTPS443
DNS53
FTP21
MySQL3306
PostgreSQL5432
Remember:

The port numbers above are common defaults, not guarantees that a service must always use those ports.

QUESTION 13

How do you check listening ports?

⭐⭐⭐⭐⭐ DEVOPS MUST KNOW 
ss -tulnp

Common flags:

  • -t → TCP
  • -u → UDP
  • -l → Listening
  • -n → Numeric output
  • -p → Process information where permitted
Example: 
ss -lntp

Useful when checking whether an application is actually listening on the expected TCP port.

QUESTION 14

What is ping?

⭐⭐⭐⭐⭐ VERY COMMON

ping tests basic IP connectivity by sending ICMP Echo Requests and waiting for replies. 

ping 8.8.8.8

To stop continuous output: 

Ctrl + C
Important:

A failed ping does not automatically mean the host is down. ICMP may be blocked by a firewall or security policy.

QUESTION 15

What is curl?

⭐⭐⭐⭐⭐ DEVOPS FAVORITE

curl is commonly used to transfer data and test HTTP/HTTPS endpoints. 

curl https://example.com

To inspect response headers: 

curl -I https://example.com
DevOps Use:

Use curl to verify whether an application endpoint is responding and to inspect HTTP responses during troubleshooting.

QUESTION 16

What is traceroute?

⭐⭐⭐⭐

Traceroute helps identify the network path taken toward a destination by showing intermediate hops. 

traceroute example.com

On some Linux distributions you may need to install the command first.

Use case:

Useful when investigating where packets may be experiencing routing or connectivity problems.

QUESTION 17

TCP vs UDP

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE
TCP UDP
Connection-oriented Connectionless
Reliable ordered delivery No built-in delivery guarantee
More protocol overhead Lower overhead
Common for HTTP/HTTPS and SSH Common for DNS and streaming/real-time use cases
🎤 Interview Answer

"TCP provides connection-oriented and reliable ordered delivery, while UDP is connectionless and has lower protocol overhead but does not provide TCP's delivery guarantees."

QUESTION 18

What is localhost?

⭐⭐⭐⭐

localhost refers to the local machine. 

127.0.0.1

IPv6 loopback: 

::1
Example: 
curl http://localhost:8080

This tests a service listening on port 8080 on the same machine.

🔥 REAL-TIME SCENARIO

Application is not reachable on its port

⭐⭐⭐⭐⭐ DEVOPS FAVORITE

Suppose an application should be running on port 8080. Start troubleshooting from the server itself. 

ss -lntp | grep 8080
curl http://localhost:8080

If it is not listening:

  • Check application/service status
  • Check application logs
  • Verify configuration

If it works locally but not remotely, investigate:

  • Firewall
  • Cloud security group
  • Network ACL
  • Routing
  • Listening address

DNS works differently than IP connectivity

⭐⭐⭐⭐⭐

If this works: 

ping 8.8.8.8

but this fails: 

ping example.com

the problem may involve DNS resolution rather than basic IP connectivity. 

nslookup example.com
dig example.com
🎤 Interview Approach

"I separate the problem into layers. First I test IP connectivity, then DNS resolution, then the destination port and finally the application itself."

Container Networking — Basic Concept

⭐⭐⭐⭐⭐

Containers have their own networking model and may communicate through container networks, host networking or published ports, depending on configuration.

Client
↓
Host Port
↓
Container Port
↓
Application

For example, a web application listening on container port 8080 might be published to a host port such as 80. 

docker run -p 80:8080 image-name

This means host port 80 is published to container port 8080.

QUESTION 22

What is a Firewall?

⭐⭐⭐⭐⭐ MUST KNOW

A firewall controls network traffic according to configured rules.

Linux environments may use tools such as: 

ufw
firewalld
nftables

Cloud environments may additionally use provider-level network controls such as security groups and network ACLs.

🎤 Interview Answer

"A firewall filters network traffic according to rules and helps control which connections are allowed or denied."

Linux Networking Cheat Sheet

IP Address → Identifies an endpoint/interface on an IP network.

Network Interface → Connection used for network communication.

MAC Address → Link-layer address of a network interface.

Default Gateway → Next-hop router for traffic without a more specific route.

Routing Table → Determines where packets should be sent.

DNS → Resolves domain names to IP addresses and other records.

Port → Identifies a service endpoint.

ping → Basic ICMP connectivity test.

curl → HTTP/API testing and data transfer.

ss → Inspect sockets and listening ports.

TCP → Reliable, connection-oriented transport.

UDP → Connectionless, lower-overhead transport.

localhost → Local machine.

Least-layer troubleshooting → Interface → Route → Connectivity → DNS → Port → Application.

🎤 FINAL INTERVIEW QUESTIONS

Q: How do you check an IP address?
A: ip addr.

Q: How do you check the routing table?
A: ip route.

Q: How do you check listening ports?
A: ss -lntp.

Q: What is DNS?
A: A system that resolves domain names and provides other DNS records.

Q: What is the difference between TCP and UDP?
A: TCP is connection-oriented and provides reliable ordered delivery; UDP is connectionless with lower overhead.

Q: What does ping test?
A: Basic IP connectivity using ICMP, where permitted.

Q: How do you troubleshoot an application that is not reachable?
A: Check the application, listening port, local connectivity, firewall/security rules, routing and DNS.

Q: If IP works but domain name does not, what do you check?
A: DNS configuration and name resolution.

Q: If an application works on localhost but not from another machine?
A: Check the listening address, firewall, cloud security rules, routing and published/exposed port.
