DevSecOps Security Tools

Interview-focused guide covering security scanning, vulnerability detection, secret detection, code quality, container security, IaC security and DevSecOps integration into CI/CD pipelines.

⭐⭐⭐⭐⭐ MOST IMPORTANT INTERVIEW QUESTIONS

Q1. What is DevSecOps?

Interview Answer:
DevSecOps is the practice of integrating security throughout the software development and DevOps lifecycle instead of performing security only at the end.

The goal is to detect and fix security issues early, automate security checks and make security a shared responsibility across development, operations and security teams.

Code → Build → Scan → Test → Container Scan → Deploy → Monitor

Q2. What are the major types of security scanning?

Interview Answer:
Common security scanning categories include:
  • SAST — Static Application Security Testing
  • DAST — Dynamic Application Security Testing
  • SCA — Software Composition Analysis
  • Secret Scanning
  • Container Image Scanning
  • IaC Security Scanning

Q3. What is SAST?

Interview Answer:
SAST analyzes application source code or compiled code without executing the application to identify security vulnerabilities.

Examples include insecure coding patterns, SQL injection risks, hard-coded credentials and unsafe APIs.

Example Tool: SonarQube

Q4. What is DAST?

Interview Answer:
DAST tests a running application from the outside to identify runtime security vulnerabilities.

Unlike SAST, DAST does not primarily inspect the source code. It interacts with the deployed application.

Q5. What is SCA?

Interview Answer:
Software Composition Analysis identifies vulnerabilities and licensing issues in third-party libraries and dependencies used by an application.

⭐⭐⭐⭐⭐ Trivy

Q6. What is Trivy?

Interview Answer:
Trivy is an open-source security scanner commonly used to detect vulnerabilities in container images, filesystems, Git repositories, Kubernetes configurations and infrastructure-as-code.

Why is Trivy commonly used in DevSecOps?

  • Easy to integrate into CI/CD pipelines
  • Scans Docker images
  • Detects OS package vulnerabilities
  • Detects application dependency vulnerabilities
  • Supports secret scanning
  • Supports IaC and Kubernetes scanning

Example

trivy image nginx:latest
Real-time point:
A pipeline can scan a Docker image with Trivy before pushing it to a production container registry.

⭐⭐⭐⭐⭐ Gitleaks

Q7. What is Gitleaks?

Interview Answer:
Gitleaks is a secret-scanning tool used to detect sensitive information such as passwords, API keys, tokens and credentials accidentally committed to source code repositories.

Example

gitleaks detect

Why is secret scanning important?

A developer may accidentally commit an AWS access key or database password. If that secret reaches Git, attackers may potentially use it.

Best practice: Never store credentials directly in source code. Use a secrets manager or CI/CD secret store.

⭐⭐⭐⭐ Hadolint

Q8. What is Hadolint?

Interview Answer:
Hadolint is a Dockerfile linter that checks Dockerfiles for common mistakes and best-practice violations.

Example

hadolint Dockerfile

It can identify issues such as inefficient instructions, missing version pinning and Dockerfile best-practice violations.

⭐⭐⭐⭐⭐ SonarQube

Q9. What is SonarQube?

Interview Answer:
SonarQube is a code quality and security analysis platform that detects bugs, vulnerabilities, code smells and maintainability issues.

What does SonarQube provide?

  • Code quality analysis
  • Security vulnerability detection
  • Code smell detection
  • Quality Gates
  • Coverage reporting
  • Technical debt analysis

Typical CI/CD Flow

Code → Build → Test → SonarQube Scan → Quality Gate → Deploy

⭐⭐⭐⭐⭐ Container Security

Q10. How do you secure Docker images?

Interview Answer:
  1. Use minimal base images.
  2. Keep base images updated.
  3. Scan images for vulnerabilities.
  4. Do not store secrets inside images.
  5. Run containers as non-root where possible.
  6. Use trusted images.
  7. Pin important dependencies.
  8. Scan images before deployment.

Example Pipeline

Build Image
↓
Hadolint
↓
Trivy Image Scan
↓
Push to Registry
↓
Deploy

⭐⭐⭐⭐ IaC Security

Q11. Why should Infrastructure as Code be scanned?

IaC scanning identifies insecure configurations before infrastructure is deployed.

Examples include publicly exposed resources, overly permissive IAM policies and insecure network configurations.

Common tools include Checkov, tfsec and Trivy's IaC scanning capabilities.

⭐⭐⭐⭐⭐ REAL-TIME INTERVIEW SCENARIOS

Scenario 1 — Trivy finds a critical vulnerability

How would you respond?
  • Check the affected package.
  • Identify the vulnerable base image or dependency.
  • Upgrade to a patched version.
  • Rebuild the image.
  • Run Trivy again.
  • Only push/deploy after the required security gate passes.

Scenario 2 — AWS key accidentally committed to Git

Response:
  1. Immediately revoke or rotate the exposed credential.
  2. Check whether the credential was used.
  3. Remove the secret from the repository history if appropriate.
  4. Use a secrets manager going forward.
  5. Add Gitleaks to CI/CD to prevent recurrence.

Scenario 3 — SonarQube Quality Gate fails

Do not bypass the gate blindly. First inspect the reported bugs, vulnerabilities, security hotspots and code-quality issues. Fix the required issues and rerun the pipeline.
