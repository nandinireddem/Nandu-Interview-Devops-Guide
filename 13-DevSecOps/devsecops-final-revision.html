DevSecOps Final Revision

High-priority interview revision covering security concepts, tools, pipeline integration and real-time troubleshooting.

⭐⭐⭐⭐⭐ 1. What is DevSecOps?

DevSecOps means integrating security throughout the software development and delivery lifecycle instead of treating security as a separate final-stage activity.
Plan → Code → Build → Test → Secure → Deploy → Monitor
Remember: Security is continuous.

⭐⭐⭐⭐⭐ 2. DevOps vs DevSecOps

DevOps DevSecOps
Development + Operations collaboration Development + Security + Operations collaboration
Automated delivery Automated delivery with security controls
Security may be added separately Security is integrated throughout the lifecycle

⭐⭐⭐⭐⭐ 6. What is a Security Gate?

A security gate is a policy checkpoint that determines whether a pipeline can continue.

Example:
If an image contains a critical vulnerability and the organization's policy blocks critical vulnerabilities, the pipeline fails and the image is not promoted.

⭐⭐⭐⭐⭐ 7. What happens when Trivy finds a Critical CVE?

  1. Identify the CVE and affected package.
  2. Check severity and impact.
  3. Check for a patched version.
  4. Update dependency or base image.
  5. Rebuild image.
  6. Scan again.
  7. Promote only when security policy is satisfied.

Important: Never expose credentials in source code, logs or pipeline output.

⭐⭐⭐⭐⭐ 9. How do you manage CI/CD Secrets?

  • GitHub Secrets
  • Jenkins Credentials
  • AWS Secrets Manager
  • HashiCorp Vault
"I avoid hard-coded credentials and use protected secret-management mechanisms with least-privilege access."

⭐⭐⭐⭐⭐ 10. Least Privilege

Least privilege means giving users, applications and CI/CD systems only the permissions they actually need. 

CI/CD Pipeline
      |
      └── IAM Role
             |
             ├── Required ECR access
             └── Required deployment access

Avoid giving a pipeline unrestricted administrator permissions when they are not required.

⭐⭐⭐⭐ 11. Shift Left Security

Shift-left security means identifying and fixing security issues as early as possible in the software development lifecycle.
Developer → Code Scan → Dependency Scan → Build → Container Scan → Deploy
Goal: Find problems earlier when they are generally easier and cheaper to fix.

⭐⭐⭐⭐ 12. False Positive

A false positive occurs when a security tool reports a problem that is not actually a security issue in the application's context.

Correct Approach

  1. Validate the finding.
  2. Understand the affected component.
  3. Check the evidence.
  4. Document the analysis.
  5. Use an approved exception process if appropriate.

⭐⭐⭐⭐ 13. How Do You Secure Docker?

  • Use trusted and maintained base images.
  • Keep images updated.
  • Scan images for vulnerabilities.
  • Avoid running containers as root when possible.
  • Do not hard-code secrets in Dockerfiles.
  • Use minimal images where practical.
  • Do not expose unnecessary ports.

⭐⭐⭐⭐ 14. How Do You Secure Kubernetes?

  • Use RBAC.
  • Follow least privilege.
  • Secure Secrets.
  • Restrict container privileges.
  • Use NetworkPolicies where appropriate.
  • Scan container images.
  • Keep Kubernetes components updated.
  • Monitor cluster activity.

⭐⭐⭐⭐ 15. How Do You Secure Terraform?

  • Scan Terraform code before deployment.
  • Review IAM permissions.
  • Avoid hard-coded credentials.
  • Protect Terraform state.
  • Use remote state with appropriate access controls.
  • Review security-sensitive changes.

⭐⭐⭐⭐⭐ 16. Real-Time Interview Scenario

Question:

"Your pipeline passed all security checks but production still has a security incident. What would you do?"

Answer:
"I would first contain the incident and assess its scope. Then I would identify the attack vector, affected resources and whether credentials or application vulnerabilities were involved. I would apply the required remediation, verify the fix and monitor the environment. Finally, I would identify which preventive control was missing and improve the CI/CD or runtime security process."
