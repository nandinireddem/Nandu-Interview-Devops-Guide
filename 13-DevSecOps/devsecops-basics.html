DevSecOps Basics

Security integrated into every stage of the software delivery lifecycle. Interview-focused concepts, terminology and practical examples.

⭐⭐⭐⭐⭐ 1. What is DevSecOps?

DevSecOps means integrating security practices into the DevOps lifecycle instead of treating security as a separate activity performed only at the end.

Plan
↓
Code
↓
Build
↓
Test
↓
Security
↓
Deploy
↓
Monitor
Interview Answer:
"DevSecOps is an approach where security is integrated throughout the software development and delivery lifecycle. Instead of finding security issues only before production, we identify and fix them as early as possible using automated security checks in the development and CI/CD process."

⭐⭐⭐⭐⭐ 2. DevOps vs DevSecOps

DevOps DevSecOps
Focuses on development, operations and automation. Adds security as an integral part of the lifecycle.
Security may be handled separately. Security is shared across teams.
Security checks may happen later. Security checks are shifted earlier.
CI/CD automation. CI/CD + automated security controls.
Simple way to remember:
DevOps = Development + Operations + Automation
DevSecOps = Development + Security + Operations + Automation

⭐⭐⭐⭐⭐ 3. What is Shift-Left Security?

Shift-left security means moving security checks earlier in the software development lifecycle.

Traditional
Code → Build → Test → Deploy → Security

Shift Left
Security → Code → Build → Test → Deploy

The objective is to identify vulnerabilities when they are cheaper and easier to fix.

Interview Answer:
"Shift-left security means introducing security activities as early as possible in the SDLC. For example, we can scan source code, dependencies, secrets, Dockerfiles and infrastructure definitions before they reach production."

⭐⭐⭐⭐⭐ 4. Why is DevSecOps Important?

  • Detects vulnerabilities earlier.
  • Reduces security risks.
  • Automates security checks.
  • Reduces the cost of fixing vulnerabilities.
  • Improves compliance and governance.
  • Protects applications and infrastructure.
  • Reduces the possibility of insecure deployments.

⭐⭐⭐⭐⭐ 6. What is SAST?

SAST — Static Application Security Testing analyzes application source code or compiled code without executing the application.

It can identify security weaknesses during development or CI.

Example

A developer pushes code → CI pipeline runs SAST → vulnerability is detected → pipeline can fail based on the configured policy.

Common example: SonarQube.

⭐⭐⭐⭐⭐ 7. What is DAST?

DAST — Dynamic Application Security Testing tests a running application from the outside.

SAST: Tests code.
DAST: Tests a running application.

A commonly used DAST tool is OWASP ZAP.

⭐⭐⭐⭐⭐ 8. What is SCA?

SCA — Software Composition Analysis scans third-party libraries and dependencies for known vulnerabilities.

For example, if an application uses a vulnerable version of a dependency, SCA can identify the vulnerability.

⭐⭐⭐⭐⭐ 9. SAST vs DAST vs SCA

Type What it checks When
SAST Source/application code During development/build
DAST Running application During testing
SCA Third-party dependencies During development/build

⭐⭐⭐⭐⭐ 10. Container Security

Container images can contain vulnerable packages, outdated operating system components or insecure configurations.

A tool such as Trivy can scan container images. 

trivy image nginx:latest
Interview Point:
"I would scan container images before deployment and configure the CI/CD pipeline to block images that exceed the organization's defined vulnerability threshold."

⭐⭐⭐⭐⭐ 11. Secrets Management

Passwords, API keys, tokens and private credentials should never be committed directly into source control.

Bad Practice

AWS_ACCESS_KEY_ID="AKIA..."
AWS_SECRET_ACCESS_KEY="..."

Better Approach

  • Environment variables
  • GitHub Secrets
  • AWS Secrets Manager
  • HashiCorp Vault
  • Kubernetes Secrets with appropriate protection

Tools such as Gitleaks can detect accidentally committed secrets.

⭐⭐⭐⭐⭐ 12. What is IaC Security?

Infrastructure-as-Code security means scanning infrastructure definitions for insecure configurations before deployment.

Examples include Terraform, Kubernetes YAML and CloudFormation.

Typical checks can identify things such as overly permissive access, public resources or insecure configuration.

⭐⭐⭐⭐⭐ 15. What Happens When a Security Scan Fails?

  1. The security tool detects a vulnerability.
  2. The pipeline evaluates the configured policy.
  3. If the vulnerability violates the policy, the security gate fails.
  4. The deployment can be blocked.
  5. The developer/team investigates the vulnerability.
  6. The issue is fixed or formally approved according to organizational policy.
  7. The pipeline is executed again.
Do not automatically fail every pipeline for every low-severity finding. Organizations normally define severity thresholds and exception processes.

⭐⭐⭐⭐⭐ 16. DevSecOps vs Security Team

DevSecOps does not mean removing security teams.

Instead, security becomes a shared responsibility while security teams continue to provide expertise, policies, governance, risk management and advanced security practices.
