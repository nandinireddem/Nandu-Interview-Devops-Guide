⭐⭐⭐⭐⭐ 1. What is a Docker Registry?

Q. What is a Docker registry?

A Docker registry is a service that stores and distributes container images. Developers and CI/CD pipelines can push images to a registry, while servers or orchestration platforms can pull those images for deployment.

Examples

  • Docker Hub
  • Amazon Elastic Container Registry (ECR)
  • Google Artifact Registry
  • Azure Container Registry
  • GitHub Container Registry
  • Self-hosted Docker Registry

⭐⭐⭐⭐⭐ 4. Docker Image Tagging

Q. Why do we tag Docker images?

Tags identify different versions or variants of an image. They allow CI/CD pipelines and deployment systems to reference a specific image version.

Tag syntax

registry/namespace/repository:tag

Example

docker tag myapp:latest nandinireddem/myapp:v1.0

The docker tag command creates another reference to the same image. It does not rebuild the image.

Verify

docker images

⭐⭐⭐⭐⭐ 7. Public vs Private Registry

Public Private
Images can be publicly accessible Access is restricted
Useful for public/open-source images Preferred for proprietary application images
Lower access-control requirements Requires authentication and authorization
DevOps scenario: A company has a proprietary application image. The image should not be publicly downloadable. The team should use a private registry such as a private ECR repository and configure the deployment environment with appropriate permissions to pull the image.

⭐⭐⭐⭐⭐ 8. Docker Registry Authentication

Q. Why is authentication required?

Private registries require authentication so that only authorized users, systems or workloads can push and/or pull images.

Docker Hub

docker login

Logout

docker logout

Security best practices

  • Do not hard-code registry passwords in Dockerfiles.
  • Do not commit registry credentials to Git.
  • Use CI/CD secret management.
  • Use short-lived credentials where supported.
  • Apply least-privilege permissions.
  • Use private repositories for proprietary images.

⭐⭐⭐⭐⭐ 9. AWS ECR

Q. What is Amazon ECR?

Amazon Elastic Container Registry (ECR) is a managed AWS container registry used to store, manage and deploy container images.

Why use ECR?

  • Private container image storage
  • AWS IAM integration
  • Works with ECS
  • Works with EKS
  • Works with CI/CD pipelines
  • Supports image scanning features
  • Integrates with AWS infrastructure

⭐⭐⭐⭐⭐ 10. AWS ECR Push Workflow

Step 1 — Create ECR repository

aws ecr create-repository \
    --repository-name myapp \
    --region ap-south-1

Step 2 — Authenticate Docker to ECR

aws ecr get-login-password \
    --region ap-south-1 |
docker login \
    --username AWS \
    --password-stdin \
    <ACCOUNT_ID>.dkr.ecr.ap-south-1.amazonaws.com

Step 3 — Build image

docker build -t myapp:v1.0 .

Step 4 — Tag image

docker tag myapp:v1.0 \
<ACCOUNT_ID>.dkr.ecr.ap-south-1.amazonaws.com/myapp:v1.0

Step 5 — Push

docker push \
<ACCOUNT_ID>.dkr.ecr.ap-south-1.amazonaws.com/myapp:v1.0

⭐⭐⭐⭐⭐ 13. Image Tagging Strategy

Bad approach

myapp:latest

Using only latest makes it harder to identify exactly which version was deployed.

Better approaches

myapp:v1.0.0

myapp:2026-08-12

myapp:build-152

myapp:git-a83f21c

Recommended production concept

Use immutable, traceable image references whenever possible. A deployment should be able to identify exactly which application build is running.

⭐⭐⭐⭐⭐ 14. Why Avoid Using latest in Production?

The latest tag is mutable. A new image can be pushed with the same tag, meaning the same deployment configuration can resolve to a different image later.
Example: Today: 
myapp:latest → version 1.0
Later: 
myapp:latest → version 1.1
The tag stayed the same, but the image changed. A production deployment is easier to audit when it references a specific immutable version or image digest.

⭐⭐⭐⭐⭐ 15. Image Digest

Q. What is an image digest?

An image digest is a content-based identifier for a specific image manifest. It can be used to reference an exact image version rather than relying only on a mutable tag.

Example

myapp@sha256:abcdef123456...

Tag vs Digest

Tag Digest
Human-friendly name Content-based identifier
Can be moved to another image Identifies a specific image manifest
Easy for releases Useful for exact, reproducible references

⭐⭐⭐⭐ 16. Image Pull Policy

Why does image pulling matter?

Deployment platforms need to determine when an image should be downloaded from the registry rather than using a locally cached image.

Kubernetes example

image: myrepo/myapp:v1.0
imagePullPolicy: IfNotPresent

The exact image-pull behavior depends on the configured image reference and pull policy.

For production deployments, prefer versioned image references instead of relying on mutable tags such as latest.

⭐⭐⭐⭐ 18. What Happens During docker push?

Docker authenticates to the registry, checks which image layers are already present remotely, and uploads the layers and image metadata that the registry does not already have.
Local Image
↓
Registry Authentication
↓
Compare Layers
↓
Upload Missing Layers
↓
Upload Manifest / Metadata
↓
Registry Stores Image

Important point

Docker images consist of layers. If the registry already contains a layer, it generally does not need to upload the same layer again.

⭐⭐⭐⭐ 19. What Happens During docker pull?

Docker contacts the registry, retrieves the image manifest and downloads the required layers that are not already available locally.
docker pull
↓
Registry
↓
Image Manifest
↓
Required Layers
↓
Local Image
↓
Container

⭐⭐⭐⭐⭐ 20. Registry Security

Important practices

  • Use private repositories for proprietary images.
  • Use least-privilege IAM permissions.
  • Protect registry credentials.
  • Enable image vulnerability scanning where available.
  • Scan images before deployment.
  • Use trusted base images.
  • Keep base images updated.
  • Do not embed secrets in images.
  • Use immutable versioning where possible.
  • Restrict who can push production images.
A Docker image should not contain passwords, API keys, AWS access keys, private keys or other secrets. Anything baked into an image can potentially be extracted by someone who can access the image.

⭐⭐⭐⭐⭐ 21. Real-Time Scenario: Docker Push Denied

Problem: You run: 
docker push username/myapp:v1.0
and receive an authorization or access-denied error.

Check

  1. Are you logged in?
  2. Is the repository name correct?
  3. Do you have permission to push?
  4. Is the registry URL correct?
  5. Are you using the correct AWS account/region for ECR?
  6. Does the repository exist?

Docker Hub

docker login

docker push username/myapp:v1.0

ECR

Verify ECR authentication and IAM permissions.

⭐⭐⭐⭐⭐ 22. Real-Time Scenario: ECS Cannot Pull Image

An ECS task starts but fails because it cannot pull the private image from ECR.

Possible causes

  • Incorrect image URI
  • Incorrect image tag
  • Image does not exist in ECR
  • Task execution role lacks required ECR permissions
  • Network connectivity problem
  • Wrong AWS region
  • Repository access issue

Investigation

aws ecr describe-images \
    --repository-name myapp \
    --region ap-south-1
Interview answer: "I would first verify the image URI, repository, tag and region. Then I would check whether the image exists in ECR and verify the ECS task execution role and its permissions to pull the image. Finally, I would check the task and service events for the exact pull failure."

⭐⭐⭐⭐⭐ 23. Real-Time Scenario: Image Exists Locally but Deployment Fails

A Docker image runs successfully on your laptop, but ECS or Kubernetes cannot deploy it.

Check

  • Was the image actually pushed to the registry?
  • Is the deployment using the correct registry URI?
  • Is the tag correct?
  • Can the workload authenticate to the registry?
  • Is the image architecture compatible with the target?
  • Are network and IAM permissions correct?
"Works on my machine" does not mean the production environment can pull the same image. The registry, authentication, architecture, network and deployment configuration must also be correct.

⭐⭐⭐⭐ 25. Why Use Commit SHA as Image Tag?

A Git commit SHA provides a unique reference to a source-code revision. Using it as an image tag improves traceability between source code, CI builds and deployed containers.

Benefits

  • Traceability
  • Easy rollback
  • Better debugging
  • Clear CI/CD history
  • Reduced ambiguity compared with latest

⭐⭐⭐⭐ 26. Registry Cleanup

Why clean old images?

Container registries can accumulate old image versions, increasing storage usage and making repository management harder.

Good practice

  • Define an image retention policy.
  • Keep required production versions.
  • Remove obsolete development images.
  • Use lifecycle policies where supported.
  • Never delete images that active deployments still depend on.
For ECR, lifecycle policies can automatically expire images based on rules such as image age or the number of images retained.

🎯 If the Interviewer Says: "Explain Docker Registry"

"A Docker registry is a service used to store and distribute container images. In a typical DevOps workflow, the developer pushes code to Git, and the CI pipeline builds and tests the Docker image. After security scanning, the pipeline tags the image with a unique version such as the Git commit SHA and pushes it to a private registry such as Amazon ECR. During deployment, platforms such as ECS or Kubernetes pull the required image from the registry using the appropriate permissions. For production, I prefer traceable versioned image tags or image digests instead of relying only on the latest tag. I would also use private repositories, least-privilege access, image scanning and lifecycle policies to improve security and registry management."
