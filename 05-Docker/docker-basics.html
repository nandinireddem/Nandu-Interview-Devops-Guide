⭐⭐⭐⭐⭐ 1. What is Docker?

Q. What is Docker?

Docker is a containerization platform used to package an application and its dependencies into a portable image that can run consistently across different environments.

Why do we use Docker?

  • Consistent application environments
  • Fast application startup
  • Application isolation
  • Portable deployments
  • Efficient resource usage
  • Easy CI/CD integration
  • Microservices deployment
  • Scalable application packaging
Interview answer:

"Docker is a containerization platform that packages applications and their dependencies into portable images. These images can be used to create isolated containers, providing consistency across development, testing and production environments."

⭐⭐⭐⭐⭐ 2. Containers vs Virtual Machines

Containers Virtual Machines
Share the host OS kernel Each VM normally includes a guest OS
Lightweight Heavier
Start quickly Usually slower startup
Lower resource overhead Higher resource overhead
Good for application isolation Provides stronger full OS-level isolation
Container image contains application and dependencies VM image includes an entire operating system
Virtual Machine
Application ↓ Libraries ↓ Guest OS ↓ Hypervisor ↓ Host OS

Container
Application ↓ Libraries ↓ Container ↓ Docker Engine ↓ Host OS

Important interview point

Containers are not simply "small virtual machines". They use OS-level isolation and share the host kernel, while VMs virtualize hardware and run guest operating systems.

⭐⭐⭐⭐⭐ 3. Docker Architecture

Docker uses a client-server architecture. The Docker CLI communicates with the Docker daemon, which manages Docker objects such as images, containers and networks.

↓

Docker Client

The Docker client is the command-line interface used to send commands to the Docker daemon.

Docker Daemon

The Docker daemon manages Docker objects such as containers, images, networks and volumes and performs requested operations.

Docker Engine

Docker Engine is the technology used to build and run containers. It includes the Docker daemon, API and supporting container runtime components.

Docker Registry

A registry stores and distributes container images. Docker Hub is a popular public registry, while organizations can also use private registries.

⭐⭐⭐⭐⭐ 4. Docker Image

Q. What is a Docker image?

A Docker image is an immutable, versioned package used as the template for creating containers. It contains the application, dependencies and filesystem layers required by the container.

Image characteristics

  • Read-only template
  • Versionable
  • Portable
  • Made of filesystem layers
  • Can create multiple containers

⭐⭐⭐⭐⭐ 5. Docker Container

Q. What is a container?

A container is a running or stopped instance created from a Docker image. It provides an isolated environment in which an application and its dependencies can execute.

Image vs Container

Image Container
Template Instance created from the template
Immutable filesystem layers Has a writable container layer
Used to create containers Runs the application
Can be stored in a registry Normally runs on a host

⭐⭐⭐⭐⭐ 6. Docker Image Layers

Docker images are built using layers. Each Dockerfile instruction that creates filesystem changes can contribute to an image layer. 

FROM ubuntu

RUN apt-get update

RUN apt-get install -y nginx

COPY app /app
Layer 4 → Application files
Layer 3 → Nginx installation
Layer 2 → Package metadata / changes
Layer 1 → Base image
↓
Docker Image

Why are layers useful?

  • Image reuse
  • Build caching
  • Faster builds when cache is valid
  • Reduced storage through shared layers
A change to an earlier Dockerfile instruction can invalidate the cache for subsequent instructions, potentially making later build steps execute again.

⭐⭐⭐⭐⭐ 9. What happens when you run docker run?

Example

docker run nginx

High-level flow

  1. Docker checks whether the image exists locally.
  2. If required, Docker pulls the image from a registry.
  3. A container is created from the image.
  4. Filesystem and networking are configured.
  5. The container's configured process is started.
Interview answer:

"When I execute docker run, Docker checks for the requested image. If it is unavailable locally, Docker pulls it from the configured registry. It then creates the container, configures its runtime environment and starts the container's main process."

⭐⭐⭐⭐⭐ 10. Docker Port Mapping

Example

docker run -p 8080:80 nginx
Browser
↓
Host Port 8080
↓
Container Port 80
↓
Nginx
The format is HOST_PORT:CONTAINER_PORT. Port publishing makes a container port reachable through the specified host port.
EXPOSE in a Dockerfile documents an intended container port; it does not by itself publish the port to the host.

⭐⭐⭐⭐⭐ 11. Docker Environment Variables

Example

docker run -e APP_ENV=production myapp
Environment variables allow configuration to be supplied to the container without hard-coding environment-specific values into the application image.

Important DevOps principle

Do not put passwords, API keys or cloud credentials directly inside Dockerfiles or images. Use appropriate secret-management mechanisms.

⭐⭐⭐⭐⭐ 12. Container Isolation

Containers provide process, filesystem and network isolation using Linux kernel features.

Important technologies

  • Namespaces — isolate processes and system resources
  • cgroups — control and account for resource usage
  • Union / layered filesystems — support image layers

Namespaces

Namespaces provide isolated views of resources such as processes, network interfaces, mounts and hostnames.

cgroups

Control groups allow resource usage such as CPU and memory to be controlled and monitored for processes.

⭐⭐⭐⭐⭐ 15. Real-Time Scenario: "It works on my machine"

Problem: An application works correctly on a developer's laptop but fails in the test or production environment.

Docker approach: Package the application together with its runtime dependencies into an image and use the same image across environments.
Interview answer:

"Containerization helps reduce environment differences by packaging the application and its dependencies into a consistent image. The same tested image can then move through CI/CD environments."

⭐⭐⭐⭐⭐ 16. Real-Time Scenario: Container exits immediately

Problem: A container starts and immediately stops.

First checks:
  • Check container status
  • Check container logs
  • Inspect the configured command
  • Check environment variables
  • Verify application startup errors
docker ps -a

docker logs <container>

docker inspect <container>
A container normally remains running only while its main process is running. If that process exits, the container stops.

⭐⭐⭐⭐⭐ 17. Real-Time Scenario: Container cannot be reached

Problem: The application is running inside a container but cannot be reached from the browser.

Check:
  • Is the container running?
  • Is the application listening on the expected container port?
  • Was the host port published?
  • Are host firewall/security rules allowing the port?
  • Is the application bound to the correct interface?
docker ps

docker logs <container>

docker inspect <container>

🎯 If the Interviewer Says: "Explain Docker in 1 Minute"

" Docker is a containerization platform used to package an application and its dependencies into a portable image. That image can be used to create containers that run consistently across different environments. Docker uses a client-server architecture where the Docker CLI communicates with the Docker daemon. Images can be stored in container registries such as Docker Hub or Amazon ECR. Compared with virtual machines, containers are generally more lightweight because they share the host operating system kernel. In DevOps, Docker is commonly used in CI/CD to build a consistent application image, scan it, push it to a registry and deploy the same tested artifact across environments. Important Docker concepts include images, containers, Dockerfiles, networking, volumes, Compose, security and container troubleshooting."
