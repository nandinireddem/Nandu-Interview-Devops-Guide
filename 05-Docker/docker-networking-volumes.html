Docker networking, ports, DNS, container communication, bridge networks, volumes, bind mounts and practical DevOps interview scenarios.

⭐⭐⭐⭐⭐ DOCKER NETWORKING & STORAGE — MUST KNOW

Containers are isolated by default, but real applications usually need containers to communicate with each other and persist data. Docker networking provides communication, while volumes and mounts provide persistent storage.

⭐⭐⭐⭐⭐ 1. What is Docker Networking?

Docker networking allows containers to communicate with each other, the host machine and external networks.

Why is networking required?

  • Application container needs database access
  • Frontend needs backend API
  • Backend needs Redis
  • Containers need DNS-based service discovery
  • Applications need controlled external connectivity

⭐⭐⭐⭐⭐ 2. Docker Network Types

Network Purpose
bridge Default network for containers on a Docker host.
host Container shares the host's network namespace.
none Disables normal container networking.
Custom bridge Allows controlled communication and Docker DNS between containers.
Overlay Used for communication across multiple Docker hosts, commonly with orchestrated environments.

Useful commands

docker network ls

⭐⭐⭐⭐⭐ 3. Why use a Custom Bridge Network?

A custom bridge network provides better isolation and allows containers on that network to communicate using container names. 
docker network create app-network

docker run -d \
  --name backend \
  --network app-network \
  nginx

docker run -d \
  --name frontend \
  --network app-network \
  nginx
Interview scenario: Suppose a backend application connects to MySQL. Instead of hardcoding a container IP address, place both containers on the same custom network and connect using the database container name. Example: 
DB_HOST=mysql
Docker's embedded DNS can resolve the container/service name.

⭐⭐⭐⭐⭐ 4. Docker DNS

Q. How do containers find each other?

Containers connected to the same user-defined network can generally communicate using container or service names instead of relying on manually assigned IP addresses. 
docker network create app-network

docker run -d \
  --name mysql \
  --network app-network \
  mysql

docker run -d \
  --name backend \
  --network app-network \
  my-backend

The backend can use mysql as the database hostname when the containers are attached to the same user-defined network.

Do not design applications around hardcoded container IP addresses. Container IPs can change when containers are recreated.

⭐⭐⭐⭐⭐ 5. Docker Port Mapping

Q. What is port mapping?

Port mapping connects a port on the Docker host to a port exposed by a container. 
docker run -d -p 8080:80 nginx

⭐⭐⭐⭐ 6. EXPOSE vs -p

EXPOSE -p
Documents the intended container port. Publishes/maps a port from host to container.
Does not by itself publish the port. Makes the service reachable through the published host port. 
EXPOSE 8080
docker run -p 8080:8080 my-app
Interview answer: EXPOSE documents which port the application listens on inside the container. -p actually publishes a host port to the container port.

⭐⭐⭐⭐ 7. Host Network

With host networking, the container uses the host's network stack instead of getting a separate network namespace in the usual way. 
docker run --network host nginx
Host networking reduces network isolation and is not the default choice for normal application containers. Use it only when there is a clear requirement.

⭐⭐⭐⭐⭐ 8. Why do Docker Containers Need Persistent Storage?

A container's writable layer is tied to the container lifecycle. If the container is removed, data stored only there should not be treated as durable application storage.
Example: A MySQL container stores database files inside its container filesystem. If the container is deleted and recreated without persistent storage, the database data can be lost.

⭐⭐⭐⭐⭐ 9. Docker Volume vs Bind Mount

Named Volume Bind Mount
Managed by Docker. Uses a specific host filesystem path.
Good for persistent application data. Useful when host files need to be directly shared.
Docker manages the storage location. User controls the host path.

Named volume

docker volume create app-data

docker volume ls

docker volume inspect app-data

docker run -d \
  --name mysql \
  -v app-data:/var/lib/mysql \
  mysql

Bind mount

docker run -d \
  -v C:\myapp:/app \
  my-image

⭐⭐⭐⭐⭐ 10. Important Volume Commands

docker volume ls

docker volume create my-volume

docker volume inspect my-volume

docker volume rm my-volume

docker volume prune
Be careful with docker volume prune. It can remove unused volumes and permanently delete data stored in them.

⭐⭐⭐⭐ 11. Read-Only Mounts

A mount can be made read-only when the container should be able to read data but should not modify it. 

docker run -v app-data:/data:ro my-image
This can be useful when a container only needs to consume configuration or shared data and should not have write access.

⭐⭐⭐⭐⭐ 12. Real-Time Scenario: Backend + Database

Requirement: Run a backend application and MySQL database as separate containers.

Solution: Create a custom network for communication and a named volume for database persistence. 
docker network create app-network

docker volume create mysql-data

docker run -d \
  --name mysql \
  --network app-network \
  -v mysql-data:/var/lib/mysql \
  mysql

docker run -d \
  --name backend \
  --network app-network \

⭐⭐⭐⭐⭐ 13. Networking Troubleshooting

Problem: Container cannot reach another container

docker ps

docker inspect <container>

docker network ls

docker network inspect <network>

Check:

  • Are both containers running?
  • Are they attached to the same network?
  • Is the hostname correct?
  • Is the application actually listening on the expected port?
  • Is the service binding to the correct interface?
  • Are host firewall or security rules involved?

⭐⭐⭐⭐⭐ 14. Port Troubleshooting

Problem: Application works inside the container but cannot be accessed from the host. 
docker ps

docker port <container>

docker logs <container>

docker exec -it <container> sh

Then verify the application is listening on the expected container port and that the required host-to-container port mapping exists.

⭐⭐⭐⭐ 15. Volume Troubleshooting

docker volume ls

docker volume inspect my-volume

docker inspect <container>

Check:

  • Is the correct volume attached?
  • Is the mount path correct?
  • Does the container user have permission?
  • Is the mount read-only?
  • Is the application writing to the expected directory?

🎯 Explain Docker Networking & Volumes in an Interview

" Docker networking allows containers to communicate with each other, the host and external networks. For application architectures, I would normally create a custom network so containers can communicate using service or container names instead of hardcoded IP addresses. Port publishing such as 8080:80 maps a host port to a container port. For persistent data, I would use Docker volumes instead of relying only on the container's writable layer. Named volumes are managed by Docker, while bind mounts map a specific host directory. For example, in a backend and MySQL setup, both containers can share a custom network while MySQL uses a persistent volume for its data. During troubleshooting I would check the container status, logs, network configuration, port mappings, DNS/name resolution and volume mounts."
