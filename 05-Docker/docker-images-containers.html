Interview-focused guide covering Docker images, containers, layers, lifecycle, storage, logs, inspection, resource usage, troubleshooting and real-time DevOps scenarios.

⭐⭐⭐⭐⭐ DOCKER IMAGES & CONTAINERS — MUST KNOW

Docker images and containers are among the most frequently discussed Docker concepts in DevOps interviews. You should understand not only the commands but also what happens internally when a container starts.

⭐⭐⭐⭐⭐ 1. What is a Docker Image?

A Docker image is an immutable, read-only template containing the application code, dependencies, libraries, configuration and filesystem layers required to create a container.

Interview answer

A Docker image is a packaged application environment. It contains everything required to run the application except the running container process itself.

Example

docker pull nginx

docker images

⭐⭐⭐⭐⭐ 2. What is a Docker Container?

A container is a running or stopped instance of a Docker image. It provides an isolated environment for running application processes. 
docker run nginx

docker ps

docker ps -a
Image
↓
docker run
↓
Container
↓
Application Process

Important point

An image is a template. A container is an instance created from that template.

⭐⭐⭐⭐⭐ 3. Docker Image vs Container

Image Container
Read-only template Running/stopped instance of an image
Used to create containers Used to run applications
Immutable Has a writable container layer
Can be stored in registry Runs on Docker Engine
Example: nginx:latest Example: running nginx container

⭐⭐⭐⭐⭐ 4. Docker Image Layers

Docker images are built from layers. Each Dockerfile instruction that creates filesystem changes can contribute a layer to the image. Layers are cached and reused when possible. 
FROM ubuntu

RUN apt-get update

RUN apt-get install -y nginx

COPY index.html /var/www/html/
Base Image
↓
Package Layer
↓
Application Layer
↓
Docker Image

Why are layers important?

  • Image reuse
  • Build caching
  • Faster builds
  • Reduced storage through shared layers
  • Efficient image distribution

⭐⭐⭐⭐⭐ 5. What is the Container Writable Layer?

When a container starts, Docker adds a writable layer above the read-only image layers. Changes made inside the container are stored in this writable layer unless persistent storage is used.
The writable container layer is not the correct place for important persistent application data.

Production solution

Use volumes or external storage for data that must survive container replacement.

⭐⭐⭐⭐⭐ 7. What happens when you run docker run?

docker run -d --name web -p 8080:80 nginx

Conceptually Docker:

  1. Checks whether the image exists locally.
  2. Pulls the image from a registry if required.
  3. Creates a container from the image.
  4. Adds the writable container layer.
  5. Configures networking.
  6. Applies the port mapping.
  7. Starts the container's main process.
Interview answer:

"docker run is a high-level command that creates and starts a container from an image, including configuration such as ports, environment variables, volumes and networking."

⭐⭐⭐⭐ 8. Foreground vs Detached Mode

Foreground

docker run nginx

The terminal remains attached to the container process.

Detached

docker run -d nginx

The container runs in the background.

Attach

docker attach <container>
Be careful with docker attach. Depending on the process and terminal handling, exiting the attached session can affect the foreground process.

⭐⭐⭐⭐⭐ 9. docker exec vs docker attach

docker exec docker attach
Runs a new command inside a running container Attaches to the container's existing main process
Commonly used for troubleshooting Used to interact with the main process 
docker exec -it web /bin/bash

docker exec -it web sh
For production troubleshooting, docker exec is commonly more useful because it allows you to run a separate diagnostic command without replacing or directly controlling the main process.

⭐⭐⭐⭐⭐ 10. Docker Inspect

docker inspect provides detailed low-level information about Docker objects such as containers, images, networks and volumes. 
docker inspect web

docker inspect nginx

docker inspect web --format '{{.NetworkSettings.IPAddress}}'

What can you investigate?

  • Container configuration
  • Environment variables
  • Mounts
  • Network settings
  • Container IP
  • Port bindings
  • Image information

⭐⭐⭐⭐⭐ 11. Container Logs

docker logs --since 10m web

Production scenario

The application is returning errors after deployment. First check: 
docker ps

docker inspect web
Then investigate the application, network, configuration and dependencies.

⭐⭐⭐⭐⭐ 13. Container Resource Limits

Containers can be configured with resource constraints to prevent one workload from consuming excessive host resources. 

docker run -d \
  --name web \
  --memory=512m \
  --cpus=1 \
  nginx
DevOps scenario: One container consumes excessive CPU and memory, affecting other applications on the host. Resource limits can reduce the blast radius, while the root cause should still be investigated.

⭐⭐⭐⭐⭐ 15. Environment Variables

docker run -d \
  --name app \
  -e APP_ENV=production \
  nginx

Check environment

docker inspect app
Do not use ordinary environment variables as the preferred long-term solution for highly sensitive production secrets. Use an appropriate secret-management mechanism.

⭐⭐⭐⭐ 16. Container Naming

docker run -d --name my-nginx nginx

docker ps

docker stop my-nginx

docker start my-nginx

docker rm my-nginx

Explicit names make operational commands easier and clearer.

⭐⭐⭐⭐ 17. Copy Files To/From Containers

docker cp file.txt web:/tmp/file.txt

docker cp web:/var/log/app.log ./app.log
Useful during troubleshooting when you need to temporarily extract a file from a container for investigation.

⭐⭐⭐⭐ 18. docker diff

docker diff shows filesystem changes made inside a container compared with its original image state. 
docker diff web

It can show added, changed and deleted files.

⭐⭐⭐ 19. docker commit

docker commit creates a new image from a container's current filesystem state. 
docker commit web my-custom-image:v1
In normal DevOps workflows, prefer rebuilding an image from a Dockerfile rather than manually committing container changes. Dockerfiles provide reproducibility and version-controlled builds.

⭐⭐⭐⭐ 20. Removing Containers and Images

docker stop web

docker rm web

docker rmi nginx:latest

Force removal

docker rm -f web
Be careful with removal commands in production. Verify the target container and understand whether persistent data is stored outside the container.

⭐⭐⭐⭐ 21. Docker Prune

docker container prune

docker image prune

docker network prune

docker volume prune

docker system prune
Prune commands remove unused Docker objects. Always understand what will be deleted before using them on an important host.

⭐⭐⭐⭐⭐ 23. Container Exited — What Do You Check?

First check the container status and exit code, then inspect the logs and configuration. 
docker ps -a

docker inspect <container>

docker logs <container>
A common reason is that the container's main process completed or crashed. Containers remain alive only while their main process is running.

⭐⭐⭐⭐⭐ 24. Why does a container stop when the application exits?

A container is fundamentally tied to its main process. When the container's primary process exits, the container stops. 
docker run ubuntu echo "Hello"

docker ps -a

The command completes, so there is no long-running foreground process keeping the container alive.

⭐⭐⭐⭐⭐ 25. Why shouldn't important data be stored only inside a container?

Containers are replaceable. Recreating or removing a container can remove data stored only in its writable layer.
Container
↓
Application
↓
Volume / External Storage
↓
Persistent Data

Persistent data should be stored using Docker volumes or appropriate external storage depending on the application architecture.

⭐⭐⭐⭐⭐ 26. Image Naming and Tags

Part Meaning

Avoid relying on latest for controlled production deployments. Explicit version tags or immutable image references make deployments easier to reproduce.

⭐⭐⭐⭐⭐ 28. Why are immutable images important?

An immutable deployment uses a specific image version rather than changing the contents of a running container manually.

This improves reproducibility, rollback and debugging.

Instead of manually modifying a production container: 
myapp:v1
   ↓
myapp:v2
   ↓
myapp:v3
Deploy a new tested image version and replace the old container.

🎯 Explain Docker Images & Containers in 1 Minute

"A Docker image is an immutable template containing the application, dependencies and filesystem layers required to run an application. A container is an instance of that image with a writable layer and a running process. When I run a container, Docker creates the container, configures its networking and storage, and starts its main process. For troubleshooting, I commonly use docker ps -a, docker logs, docker inspect, docker stats and docker exec. For production workloads, I avoid storing important data only in the container writable layer and use persistent storage. I also prefer versioned images instead of relying on latest so that deployments are reproducible and rollbacks are easier."
