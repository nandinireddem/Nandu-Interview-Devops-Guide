Git Remote & GitHub

Remote repositories, GitHub, origin, upstream, push, pull, fetch, tracking branches and practical DevOps workflows.

⭐⭐⭐⭐⭐ GIT & GITHUB — DEVOPS MUST KNOW

Git is primarily the version control system, while GitHub is a platform that hosts Git repositories and provides collaboration features such as pull requests, code reviews, issues and CI/CD integration.

Understanding how local Git repositories communicate with remote repositories is essential for DevOps interviews.

1. What is a Remote Repository?

A remote repository is a Git repository hosted at another location, usually on a server or cloud platform such as GitHub.

Example

Local Repository
      |
      | git push
      ↓
Remote Repository
      |
   GitHub

The local repository contains your working copy and Git history, while the remote repository allows teams to share and collaborate on the project.

Interview-ready answer:

"A remote repository is a Git repository hosted on a remote server or platform such as GitHub. Developers use commands like push, pull and fetch to exchange changes between the local and remote repositories."

2. What is GitHub?

GitHub is a cloud-based platform for hosting and collaborating on Git repositories.

GitHub provides features such as:

  • Repository hosting
  • Pull requests
  • Code reviews
  • Issues
  • GitHub Actions
  • Access control
  • Branch protection
  • Collaboration
Important: Git and GitHub are not the same thing.

Git = distributed version control system
GitHub = platform for hosting and collaborating around Git repositories

3. What is the difference between Git and GitHub?

Git GitHub
Version control system Git repository hosting and collaboration platform
Runs locally Cloud/web platform
Tracks changes Hosts repositories and enables collaboration
Works from command line Provides web UI, APIs and collaboration features

4. How do you check configured remote repositories?

git remote -v

Example

origin  https://github.com/user/project.git (fetch)
origin  https://github.com/user/project.git (push)

This shows the remote name and its fetch/push URLs.

5. What is origin in Git?

origin is the conventional default name given to a remote repository when it is cloned or when a remote is added using that name.

Example

git remote -v

origin  https://github.com/user/project.git (fetch)
origin  https://github.com/user/project.git (push)
Interview-ready answer:

"Origin is simply a commonly used name for a Git remote. It is not a special server or protocol; it is a remote name that points to a repository URL."

6. How do you add a remote repository?

git remote add origin https://github.com/user/project.git

This connects the local repository to the specified remote repository using the name origin.

Verify

git remote -v

7. How do you remove a remote?

git remote remove origin

This removes the remote configuration from the local repository. It does not delete the remote repository itself.

8. What is git push?

git push sends commits from the local repository to a remote repository.

Example

git push origin main

This pushes the local main branch to the main branch on the remote named origin.

Local Commit
↓
git push
↓
Remote Repository

9. What is git fetch?

git fetch downloads changes and references from a remote repository without automatically merging those changes into the current working branch.

Example

git fetch origin

After fetching, you can inspect the remote changes before deciding what to merge or rebase.

10. What is git pull?

git pull retrieves changes from a remote repository and integrates them into the current branch.

Typical concept

git pull

≈

git fetch
+
integration step

The exact integration behavior depends on the configured Git settings and options; it can involve a merge or rebase.

11. Difference between git fetch and git pull

git fetch git pull
Downloads remote updates Downloads and integrates updates
Does not automatically update current branch Updates the current branch through integration
Safer for inspecting changes first Convenient for regular synchronization
Interview answer:

"Fetch downloads remote changes without integrating them into my current branch. Pull downloads the changes and then integrates them into the current branch."

12. How do you push a new local branch to GitHub?

git switch -c feature/login

git add .

git commit -m "Add login feature"

git push -u origin feature/login

The -u option establishes an upstream tracking relationship between the local and remote branch.

13. What is an upstream branch?

An upstream branch is the remote branch that a local branch tracks by default for operations such as push and pull.

Example

git push -u origin feature/login

After this, the local feature/login branch tracks origin/feature/login.

Later, you can often simply use: 

git push
git pull

14. What does git clone do?

git clone creates a local copy of a remote Git repository, including its Git history and remote-tracking information.

Example

git clone https://github.com/user/project.git

After cloning, Git normally configures the remote repository under the name origin.

15. What is a remote-tracking branch?

A remote-tracking branch is a local reference that represents the state of a branch on a remote repository.

Example

origin/main
origin/development
origin/feature/login

These references are updated when Git communicates with the remote, for example through git fetch.

16. How do you see remote branches?

git branch -r

To see both local and remote branches: 

git branch -a

17. What is upstream in Git?

In Git workflows, upstream can refer to the original repository from which a fork was created. It is also commonly used as a remote name.

Fork workflow example

origin   → your GitHub fork
upstream → original project repository

This is especially common in open-source development.

18. Origin vs Upstream

Remote Common Meaning
origin Your primary remote repository or fork
upstream Original repository in a fork-based workflow
These names are conventions, not fixed Git keywords. You can technically name remotes differently.

20. Real-Time DevOps Scenario: Developer pushes code

A developer completes a feature locally and needs to share it with the team. 
git status

git add .

git commit -m "Add payment validation"

git push -u origin feature/payment

The branch becomes available on GitHub, where the developer can open a pull request for review.

21. Real-Time DevOps Scenario: Get latest changes before starting work

A developer wants to synchronize their local main branch with the latest remote changes. 

git switch main

git fetch origin

git pull origin main

In a team workflow, the exact synchronization strategy may use merge or rebase according to the team's Git policy.

22. What should you do if git push is rejected?

A push can be rejected when the remote branch contains commits that are not present in the local branch.

Typical message

! [rejected] main -> main
! [rejected] non-fast-forward

Basic approach

git fetch origin

git pull origin main

# Resolve conflicts if required

git push origin main
Do not blindly use git push --force on a shared branch. Understand the reason for rejection first.

23. What is a non-fast-forward push?

A non-fast-forward rejection usually means the remote branch has advanced and the local branch does not contain those remote commits. Git rejects the push to prevent accidentally overwriting remote history.

24. How do you rename a remote?

git remote rename origin upstream

This changes the remote name locally.

Check

git remote -v

25. How do you change a remote URL?

git remote set-url origin https://github.com/user/new-project.git

This is useful when a repository moves or the remote URL needs to be changed.
