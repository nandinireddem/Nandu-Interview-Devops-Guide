Git Reset, Revert & Reflog

Recover mistakes, undo commits safely, restore files and understand Git history using reset, revert, restore and reflog.

⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

1. What is git reset?

Interview Answer:

git reset moves the current branch pointer to another commit and can also modify the staging area and working directory depending on the reset mode.

It is mainly used to undo local commits or unstage changes. 

git reset HEAD~1

This moves the current branch back by one commit using the default mixed reset.

Important:

Be very careful with reset on shared branches because it can rewrite branch history.

⭐⭐⭐⭐⭐ MUST KNOW

2. What are the three types of git reset?

The three commonly discussed reset modes are:

  • --soft
  • --mixed
  • --hard
Reset HEAD Staging Area Working Directory
--soft Moves Preserved Preserved
--mixed Moves Reset Preserved
--hard Moves Reset Reset
⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

3. What is git reset --soft?

Interview Answer:

A soft reset moves HEAD to the specified commit but keeps the changes staged. 

git reset --soft HEAD~1

The last commit is removed from the branch history, but its changes remain staged so they can be recommitted.

Use case:

Useful when you want to modify or combine recent commits without losing the changes.

⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

4. What is git reset --mixed?

Interview Answer:

A mixed reset moves HEAD and resets the staging area, but it keeps the changes in the working directory. 

git reset --mixed HEAD~1

This is also the default behavior when no reset mode is specified. 

git reset HEAD~1
Remember:

The files are not deleted. The changes simply become unstaged.

⭐⭐⭐⭐⭐ DANGEROUS / MUST KNOW

5. What is git reset --hard?

Interview Answer:

A hard reset moves HEAD, resets the staging area and resets the working directory to match the target commit. 

git reset --hard HEAD~1
⚠️ Be Careful:

Uncommitted changes can be permanently lost when using --hard.

Do not use it blindly, especially on important work.

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

6. Explain reset --soft, --mixed and --hard in simple terms.

SOFT
Commit removed
Changes staged
MIXED
Commit removed
Changes unstaged
HARD
Commit removed
Changes discarded
Easy memory trick:

Soft → Keep staged
Mixed → Keep files
Hard → Throw away local changes

⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

7. What is git revert?

Interview Answer:

git revert creates a new commit that reverses the changes introduced by an earlier commit.

Unlike reset, revert does not remove the original commit from the shared history. 

git revert abc123
Production-Friendly:

Revert is generally safer for shared branches because it preserves the existing history and adds a new commit that undoes the change.

⭐⭐⭐⭐⭐ MUST KNOW

8. What is the difference between git reset and git revert?

git reset git revert
Moves branch pointer Creates a new commit
Can rewrite history Preserves existing history
Useful for local changes Safer for shared branches
Can remove commits from branch history Original commit remains visible
Can discard working-tree changes with --hard Does not simply erase the original commit
Interview Shortcut:

Reset = move history.

Revert = create a new commit that undoes history.

⭐⭐⭐⭐⭐ DEVOPS FAVORITE

9. If a bad commit is already pushed to production, would you use reset or revert?

Interview Answer:

I would generally prefer git revert because the commit has already been shared and possibly deployed.

Revert preserves the existing history and creates a new commit that reverses the bad change. 

git revert <bad-commit-id>

git push origin main
Production principle:

For a shared branch, prefer a history-preserving rollback such as revert rather than rewriting the branch with reset.

⭐⭐⭐⭐⭐ REAL-TIME SCENARIO

10. You committed the wrong changes locally. What would you do?

If the commit has not been pushed and I want to keep the changes, I can use a soft or mixed reset depending on whether I want the changes staged or unstaged. 

git reset --soft HEAD~1

Or:

git reset HEAD~1
⭐⭐⭐⭐⭐ REAL-TIME SCENARIO

11. You accidentally committed a password or secret. What should you do?

Interview Answer:

First, I would treat the secret as compromised and rotate or revoke it immediately.

Then I would remove it from the repository and follow the team's secret-remediation process.

Important:

Simply deleting the secret in a later commit does not necessarily remove it from Git history.

For sensitive credentials, history cleanup may also be required, depending on where the secret was exposed.

⭐⭐⭐⭐⭐ MUST KNOW

12. What is git restore?

Interview Answer:

git restore is used to restore files in the working tree or staging area.

It separates file restoration tasks from the older git checkout command. 

git restore app.py

Restore a staged file back to the working tree:

git restore --staged app.py
Remember:

git restore is mainly about restoring file contents and staging state, while git reset can move the branch pointer.

⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

13. What is git reflog?

Interview Answer:

Git reflog records updates to local references such as HEAD and branch pointers.

It can help recover commits or branch positions that are no longer reachable through the normal branch history. 

git reflog
Important:

Reflog is extremely useful when you accidentally reset, rebase, or move a branch pointer and need to find the previous position.

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

14. Can you recover a commit after git reset --hard?

Yes, often you can if the commit is still available in the local reflog.

First check: 

git reflog

Find the previous commit ID and reset back to it if appropriate: 

git reset --hard <commit-id>
Important:

Recovery is not guaranteed forever. Git eventually prunes unreachable objects according to repository maintenance and retention behavior.

⭐⭐⭐⭐⭐ REAL-TIME SCENARIO

15. You accidentally ran git reset --hard HEAD~3. What would you do?

Interview Answer:
  1. Do not panic.
  2. Check the reflog.
  3. Identify the previous HEAD position.
  4. Verify the commit.
  5. Move the branch back to the correct commit.
git reflog

# Find the previous HEAD

git reset --hard <previous-commit-id>
⭐⭐⭐⭐⭐ MUST KNOW

16. What does HEAD mean in Git?

Interview Answer:

HEAD is a reference that normally points to the currently checked out branch or commit.

When you make a new commit, the branch and HEAD move forward. 

A --- B --- C
            ↑
           HEAD
            |
           main
⭐⭐⭐⭐ IMPORTANT

17. What does HEAD~1 mean?

HEAD~1 means the first parent of the current commit, which is commonly the previous commit in a normal linear history. 

A --- B --- C
            ↑
           HEAD

HEAD~1 = B

HEAD~2 = A
⭐⭐⭐⭐ IMPORTANT

18. What is the difference between git restore and git reset?

git restore git reset
Restores file contents Can move branch pointer
Can unstage files Can change staging state
Does not normally move branch history Can rewrite branch history
Useful for file-level recovery Useful for commit-level/local history changes
⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

19. Can you reset a pushed commit?

Technically, yes, but resetting a pushed commit changes the local branch history and usually requires a force push to update the remote branch.

⚠️ Production Warning:

Avoid rewriting shared branch history just to remove a pushed commit. For a bad shared commit, git revert is usually the safer approach.

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

20. What is git revert HEAD?

It creates a new commit that reverses the changes introduced by the current HEAD commit. 

git revert HEAD
⭐⭐⭐⭐ IMPORTANT

21. How do you undo the latest commit but keep the changes?

Use a soft reset: 

git reset --soft HEAD~1

The commit is removed from the branch history while the changes remain staged.

⭐⭐⭐⭐ IMPORTANT

22. How do you undo the latest commit and keep the files but unstage them?

git reset HEAD~1

This is the default mixed reset.

⭐⭐⭐⭐⭐ DANGEROUS COMMAND

23. How do you completely remove the latest local commit and its changes?

git reset --hard HEAD~1
⚠️ Warning:

This can discard uncommitted changes. Verify the working tree before using it.

⭐⭐⭐⭐⭐ DEVOPS SCENARIO

24. A deployment commit broke production. What is the safest Git rollback approach?

Interview Answer:

If the bad commit is already part of a shared production branch, I would normally create a revert commit rather than rewrite the shared history. 

git revert <bad-commit>

git push origin main

Then the CI/CD pipeline can validate and deploy the rollback, according to the team's process.

⭐⭐⭐⭐⭐ REAL-TIME DEVOPS SCENARIO

25. A developer says "I deleted my commit with reset --hard." How would you investigate?

I would first inspect the local reflog: 

git reflog

Then I would identify the commit that existed before the reset and verify it before recovering it.

⭐⭐⭐⭐⭐ INTERVIEW TRAP

26. Does git revert delete the original commit?

No.

The original commit remains in the history. Revert creates another commit whose changes reverse the original commit. 

A --- B --- C --- R

C = Bad commit
R = Revert commit
⭐⭐⭐⭐ IMPORTANT

27. Does git reset delete a commit permanently?

Reset can make a commit unreachable from the current branch, but that does not always mean the commit immediately disappears from the local repository.

The reflog may still contain the previous reference, allowing recovery for some time.

⭐⭐⭐⭐⭐ REAL-TIME SCENARIO

28. A developer accidentally reset the wrong branch. What should they do first?

First: stop making more destructive changes.

Then check: 

git reflog

Identify the previous branch position and recover it carefully.

Good interview wording:

"I would first inspect reflog instead of immediately running more reset commands, because reflog can show the previous HEAD positions."

🧠 QUICK COMMAND REVISION

Git Recovery Command Cheat Sheet

# Undo latest commit, keep changes staged
git reset --soft HEAD~1

# Undo latest commit, keep changes unstaged
git reset HEAD~1

# Undo latest commit and discard local changes
git reset --hard HEAD~1

# Undo a shared commit safely
git revert <commit-id>

# Restore a working-tree file
git restore app.py

# Unstage a file
git restore --staged app.py

# View local reference history
git reflog

# View commit history
git log --oneline --graph --all
🎯 FINAL COMPARISON

Reset vs Revert vs Restore vs Reflog

Command Main Purpose
reset Move branch pointer / change staging and working tree depending on mode
revert Create a new commit that reverses an earlier commit
restore Restore file contents or unstage files
reflog Find previous local HEAD/reference positions for recovery
