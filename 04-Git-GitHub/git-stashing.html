Git Stashing

Temporarily save uncommitted changes, switch branches safely, restore work and handle practical DevOps scenarios.

⭐⭐⭐⭐⭐ GIT STASH — MUST KNOW

Git stash is used when you have uncommitted changes in your working directory but need to temporarily switch to another branch or perform another Git operation.

Instead of committing unfinished work, you can temporarily store those changes using git stash and restore them later.

1. What is Git Stash?

Git stash temporarily saves your uncommitted changes and cleans the working directory so you can work on something else.

Basic command

git stash
Uncommitted Changes
↓
git stash
↓
Changes Temporarily Stored
↓
Clean Working Directory
Interview-ready answer:

"Git stash temporarily stores my uncommitted changes and gives me a clean working directory. I can later restore those changes using commands such as git stash pop or git stash apply."

2. Why do we use Git Stash?

A common situation is that you are working on one feature and suddenly need to switch to another branch.

Example

feature/login
     |
     | Uncommitted changes
     ↓
Urgent production bug
     |
     ↓
Need to switch to main / hotfix branch

Instead of creating an unnecessary commit, you can stash the unfinished changes. 

git stash

git switch main

3. What does git stash do?

git stash

By default, Git saves changes to tracked files that are modified or staged and restores the working tree to a clean state.

Important: ordinary git stash does not include untracked files by default.

4. How do you see your stashes?

git stash list

Example

stash@{0}: WIP on feature/login
stash@{1}: WIP on main
stash@{2}: WIP on feature/payment

The most recent stash is normally referenced as stash@{0}.

5. How do you restore stashed changes?

There are two commonly used commands:

git stash apply

git stash pop
Command Behavior
git stash apply Restores the stash but keeps it in the stash list
git stash pop Restores the stash and removes it from the stash list if applied successfully

6. Difference between git stash apply and git stash pop?

The key difference is whether the stash remains in the stash list. 
git stash apply

→ Restore changes
→ Keep stash
git stash pop

→ Restore changes
→ Remove stash if successfully applied
Interview answer:

"I use git stash apply when I want to restore the changes but keep the stash as a backup. I use git stash pop when I want to restore the changes and remove that stash entry after successful application."

7. How do you stash with a message?

git stash push -m "Login feature work"

A descriptive message makes it easier to identify a stash later.

Check it

git stash list

8. How do you stash untracked files?

Use the -u option. 
git stash -u

This includes untracked files in the stash.

Remember:

git stash → tracked changes
git stash -u → tracked + untracked changes

9. How do you stash ignored files too?

git stash -a

The -a option includes ignored files as well as tracked and untracked files.

Command Includes
git stash Tracked changes
git stash -u Tracked + untracked
git stash -a Tracked + untracked + ignored

10. How do you apply a specific stash?

git stash list

git stash apply stash@{1}

This applies the specific stash instead of the latest one.

11. How do you remove a specific stash?

git stash drop stash@{1}

This removes that stash entry.

12. How do you delete all stashes?

git stash clear
This permanently removes all stash entries from the repository's stash list. Use it carefully.

13. Can you create a branch from a stash?

Yes. Git provides git stash branch for this purpose. 
git stash branch feature/login stash@{0}

Git creates a new branch starting from the commit where the stash was originally created and then attempts to apply the stash.

14. What is git stash show?

git stash show

It shows a summary of the changes contained in a stash.

More detailed view

git stash show -p

The -p option displays the actual patch/diff.

15. Does git stash create a commit?

Git stash internally stores the stashed state using Git objects, but from the developer's workflow perspective it is not a normal branch commit that you push to GitHub.

A stash is primarily a temporary local storage mechanism for uncommitted work.

16. Is Git stash shared with the team?

No. Git stash is normally local to your repository.

A stash is not pushed to GitHub using git push. If another developer needs your work, create a proper commit and push it through the normal Git workflow.

Do not use Git stash as a replacement for Git commits when work needs to be shared with the team.

17. What happens if stash apply causes conflicts?

A stash can conflict with changes already present in the target branch.

Typical workflow

git stash apply

# Conflict occurs

git status

# Resolve conflicted files

git add .

# Continue your normal workflow

The conflict must be resolved manually just like other Git conflicts.

18. Real-Time Scenario: Urgent production bug

You are working on a new feature but your manager asks you to fix a production issue immediately. 

# Current feature work

git status

# Temporarily save unfinished changes

git stash push -m "WIP login feature"

# Move to the required branch

git switch main

# Fix production issue

git add .
git commit -m "Fix production issue"

git push origin main

After the urgent work is complete, return to the feature branch. 

git switch feature/login

git stash pop
Your unfinished feature work can now be restored and continued.

19. Real-Time Scenario: Multiple stashes

git stash push -m "Login UI"
git stash push -m "Payment API"
git stash push -m "Monitoring changes"

View them

git stash list

You can then choose the required stash using its reference. 

git stash apply stash@{1}

20. When should you NOT use Git stash?

  • When work needs to be shared with teammates
  • When the changes represent a meaningful completed unit
  • When you need a permanent history of the work
  • When the work should be reviewed through a pull request
Use a proper Git commit when the work should become part of the project history.

21. Git Stash vs Git Commit

Git Stash Git Commit
Temporary storage Permanent project history
Normally local Can be pushed to remote
Useful for unfinished work Useful for meaningful changes
Not normally shared with team Can be shared through GitHub

22. DevOps Interview Scenario: You have uncommitted changes but need to pull latest code. What do you do?

First determine whether the local changes are ready to commit. If they are unfinished, temporarily stash them. 
git status

git stash push -m "WIP"

git pull origin main

git stash pop

If conflicts occur while applying the stash, resolve them before continuing.

Better real-world answer:

"I first check whether my changes can be committed safely. If they are incomplete, I can stash them, synchronize with the remote branch, and then restore the work. In a team environment I also follow the repository's merge/rebase policy."

23. Common Git Stash Commands

Command Purpose
git stash Stash tracked changes
git stash push -m "message" Create named stash
git stash -u Include untracked files
git stash -a Include ignored files too
git stash list List stashes
git stash show Show stash summary
git stash show -p Show stash diff
git stash apply Apply latest stash and keep it
git stash pop Apply latest stash and remove it if successful
git stash drop Remove a stash
git stash clear Remove all stashes
git stash branch branch-name Create branch from stash
