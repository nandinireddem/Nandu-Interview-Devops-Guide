Git Merge Conflicts

Understand why merge conflicts occur, how Git identifies them, and how to resolve them safely in real DevOps environments.

⭐⭐⭐⭐⭐ DEVOPS MUST KNOW

Merge conflicts are one of the most common practical Git interview topics. In real projects, multiple developers may modify the same file at the same time. Git may not be able to automatically decide which change should be kept.

A DevOps engineer should know how to identify, resolve, verify and safely complete a conflicted merge.

1. What is a Git Merge Conflict?

A merge conflict occurs when Git cannot automatically combine changes from two branches because the same part of a file has been changed differently.

Simple Example

main branch
    |
    A
    |
    B  ← Version 1

feature branch
    |
    A
    |
    C  ← Version 2

Both changed the same lines.

Git cannot decide which version should be kept.
Interview-ready answer:

"A merge conflict occurs when Git cannot automatically combine changes from different branches, usually because the same lines or nearby parts of a file were modified differently. We manually resolve the conflict, stage the resolved file and complete the merge."

2. Why do Merge Conflicts occur?

Conflicts commonly occur when two branches modify the same lines of the same file differently.

Example

Developer A changes:

PORT=8080

Developer B changes the same line to:

PORT=9090

When Git tries to merge both branches, it cannot automatically choose between 8080 and 9090.

3. Does every merge create a conflict?

No. Most merges can be completed automatically by Git. A conflict occurs only when Git cannot determine which change should be preserved.

Example

Developer A → file1.txt
Developer B → file2.txt

Different files
      ↓
Git can usually merge automatically

If both developers modify the same section of the same file, a conflict may occur.

4. How do you reproduce a merge conflict?

Start from the main branch:

git switch main

git switch -c feature-a

Modify the same line in a file and commit:

git add .
git commit -m "Change configuration"

Create another branch from the original main:

git switch main
git switch -c feature-b

Modify the same line differently and commit again.

Now try to merge one branch into the other:

git switch feature-a

git merge feature-b

Git may report a merge conflict.

5. What does Git show when a conflict occurs?

Git marks the conflicting section inside the file.

Conflict Markers

<<<<<<< HEAD

PORT=8080

=======

PORT=9090

>>>>>>> feature-b

Meaning

Marker Meaning
<<<<<<< HEAD Current branch changes
======= Separator between changes
>>>>>>> feature-b Incoming branch changes

6. How do you check which files have conflicts?

git status

Git identifies files that are currently in a conflicted state.

Example

On branch feature-a

You have unmerged paths.

Unmerged paths:
    both modified:   app.py
Interview tip:

The first command you should normally run after seeing a merge conflict is:

git status

7. How do you resolve a merge conflict?

1. Check status
↓
2. Open conflicted file
↓
3. Decide which changes to keep
↓
4. Remove conflict markers
↓
5. Test the code
↓
6. git add
↓
7. Complete merge

Step 1 — Check status

git status

Step 2 — Open the conflicted file

Look for the conflict markers.

Step 3 — Choose the correct content

Keep the correct version or combine both changes if required.

Step 4 — Remove conflict markers

The final file must not contain: 

<<<<<<<
=======
>>>>>>>

Step 5 — Test

Run the appropriate application tests before completing the merge.

Step 6 — Stage the resolved file

git add app.py

Step 7 — Complete the merge

git commit

8. What is the purpose of git add after resolving a conflict?

After manually resolving a conflict, Git needs to know that the file has been resolved. Running git add stages the resolved version and marks the conflict as resolved. 
git add app.py

git status

9. Can you abort a merge conflict?

Yes. If you do not want to continue with the merge, you can abort it. 
git merge --abort

This attempts to return the working tree to the state it had before the merge started.

Important:

Do not blindly delete or overwrite files to solve a conflict. First understand what changes are present and use Git's merge state safely.

10. What is the difference between resolving and aborting a merge?

Action Purpose
Resolve conflict Keep or combine the required changes and complete the merge
git merge --abort Cancel the current merge attempt

11. How do you check whether conflicts are resolved?

git status

After resolving all conflicts and staging the files, Git should no longer show them as unmerged.

Then verify the changes

git diff --cached

This lets you inspect what is staged before completing the merge.

12. What happens if you run git commit before resolving conflicts?

Git normally prevents the merge from being completed while unmerged files remain. You must resolve the conflicts and stage the resolved files first. 
git status

# resolve conflicts

git add .

git commit

13. Can a merge conflict happen during git pull?

Yes. A git pull typically fetches remote changes and then integrates them into the current branch. If the local and remote changes conflict, Git can report a merge conflict.

Example

git pull origin main

# conflict occurs

git status

# resolve files

git add .

git commit

14. How can you reduce merge conflicts in a team?

  • Keep branches short-lived.
  • Pull the latest changes regularly.
  • Communicate before modifying heavily shared files.
  • Keep commits small and focused.
  • Use pull requests and code reviews.
  • Run CI tests before merging.
  • Avoid unnecessary large changes in shared files.
DevOps perspective:

Good Git practices reduce conflicts, but they cannot completely eliminate them in a collaborative development environment.

15. Real-Time DevOps Scenario: Production deployment conflict

Suppose two developers are working on an application. Developer A changes the Kubernetes deployment configuration. Developer B changes the same deployment file for a different environment. Both create pull requests. When the second branch is merged, Git reports a conflict.

DevOps Resolution

git switch feature-a

git pull origin main

# Resolve conflict

git status

# Edit the file

git add deployment.yaml

# Run tests

git commit

git push

The pull request can then be reviewed again before merging.

16. What is the safest approach when resolving a conflict?

Understand → Resolve → Test → Stage → Review → Commit

Never resolve conflicts simply by choosing "ours" or "theirs" without understanding the business or application requirement.

17. What are "ours" and "theirs" in a merge conflict?

During a normal merge:

ours generally refers to the current branch.

theirs generally refers to the branch being merged in.

Git can provide options such as: 

git checkout --ours file.txt
git checkout --theirs file.txt

Modern Git also supports restore-style workflows, but these commands should be used carefully because they can discard changes.

Interview point: Do not say "always choose ours" or "always choose theirs." The correct choice depends on which change is required.
