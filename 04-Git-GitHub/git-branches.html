Git Branches & Merging

Git branches, switching, merging, fast-forward merge, three-way merge, conflicts and real-time DevOps workflows.

⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

1. What is a Git branch?

Interview Answer:

A Git branch is a movable pointer to a sequence of commits. It allows developers to work on different features or fixes independently without directly affecting the main branch.

In simple terms, a branch provides an isolated line of development. 

main
  |
  A
  |
  B
  |
  C

We can create a feature branch from the current commit: 

git branch feature-login
Interview Point:

Branches are mainly used to isolate development work such as features, bug fixes and release work.

⭐⭐⭐⭐⭐ MUST KNOW

2. Why do we use Git branches?

Interview Answer:

We use branches so multiple developers can work on different features or fixes independently.

This reduces the risk of directly changing production or main development code. 

main
 |
 +---- feature-login
 |
 +---- feature-payment
 |
 +---- bugfix
DevOps Example:

One developer works on a login feature while another fixes a production bug. Both can work on separate branches and later merge their completed changes into the appropriate branch.

⭐⭐⭐⭐⭐ MUST KNOW

3. How do you create a new branch?

Interview Answer:

We can create a branch using git branch. 

git branch feature-login

This creates the branch but does not switch to it.

To create and switch to a branch:

git switch -c feature-login
⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

4. How do you switch between branches?

Interview Answer:

Modern Git recommends git switch for changing branches. 

git switch feature-login

Older Git workflows commonly use:

git checkout feature-login
Remember:

git switch is specifically designed for branch switching, while git checkout has multiple uses.

⭐⭐⭐⭐⭐ MUST KNOW

5. How do you create and switch to a branch in one command?

git switch -c feature-login

Older syntax:

git checkout -b feature-login
⭐⭐⭐⭐⭐ MUST KNOW

6. How do you list Git branches?

List local branches:

git branch

List local and remote branches:

git branch -a

List remote branches:

git branch -r
⭐⭐⭐⭐ IMPORTANT

7. How do you rename a branch?

Rename the current branch: 

git branch -m new-name

Rename another local branch: 

git branch -m old-name new-name
⭐⭐⭐⭐ IMPORTANT

8. How do you delete a Git branch?

Delete a merged local branch: 

git branch -d feature-login

Force delete a branch: 

git branch -D feature-login
Interview Point:

-d performs a safer deletion and normally refuses to delete a branch whose changes have not been merged.

-D forces the deletion.

⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

9. What is Git merge?

Interview Answer:

Git merge combines changes from one branch into another branch.

For example, after completing a feature, we can merge the feature branch into the main branch. 

git switch main

git merge feature-login
⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

10. Explain a typical feature branch workflow.

  1. Start from the main branch.
  2. Create a feature branch.
  3. Develop the feature.
  4. Commit the changes.
  5. Push the branch to the remote repository.
  6. Create a Pull Request.
  7. Review and test the changes.
  8. Merge into the target branch.
git switch main

git pull origin main

git switch -c feature-login

# Make changes

git add .

git commit -m "Add login feature"

git push -u origin feature-login
⭐⭐⭐⭐⭐ MUST KNOW

11. What is a fast-forward merge?

Interview Answer:

A fast-forward merge occurs when the target branch has not received any new commits after the feature branch was created.

Git can simply move the target branch pointer forward without creating an additional merge commit.

A
→
B
→
C

Feature branch contains the latest commits.

↓
main pointer moves forward
⭐⭐⭐⭐⭐ MUST KNOW

12. What is a three-way merge?

Interview Answer:

A three-way merge occurs when both the target branch and the feature branch have diverged after a common ancestor.

Git uses three commits to perform the merge:

  • Common ancestor
  • Tip of the current branch
  • Tip of the branch being merged
        feature
           C
          /
A ---- B
          \
           D
          main

Because both branches contain different commits after the common ancestor, Git may create a merge commit.

⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

13. What is a merge conflict?

Interview Answer:

A merge conflict occurs when Git cannot automatically determine which changes should be kept while combining branches.

This commonly happens when two branches modify the same part of the same file differently. 

<<<<<<< HEAD
production configuration
=======
development configuration
>>>>>>> feature

The developer must manually decide which version should remain.

⭐⭐⭐⭐⭐ DEVOPS FAVORITE

14. How do you resolve a merge conflict?

Interview Answer:
  1. Identify the conflicted files.
  2. Open the files and inspect conflict markers.
  3. Choose or combine the correct changes.
  4. Remove the conflict markers.
  5. Stage the resolved file.
  6. Complete the merge commit if required.
git status

# Fix the conflicted file

git add app.py

git commit -m "Resolve merge conflict"
Important:

Never blindly accept changes during a production conflict. Understand which code should actually be preserved.

⭐⭐⭐⭐⭐ MUST KNOW

15. What is the difference between git merge and git rebase?

git merge git rebase
Combines branch histories Replays commits on top of another base
Can create a merge commit Usually creates a linear history
Preserves existing commit topology Rewrites commit history
Generally safer for shared branches Should be used carefully on shared branches
Interview Shortcut:

Merge = combine histories.
Rebase = move/replay commits onto a new base.

⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

16. How do you push a new branch to GitHub?

After creating and committing the branch locally, use: 

git push -u origin feature-login

The -u option establishes the upstream relationship, making future pushes and pulls easier.

⭐⭐⭐⭐ IMPORTANT

17. What is the difference between a local branch and a remote branch?

Local Branch Remote-Tracking Branch
Exists in the local repository Represents the state of a branch on a remote
Example: main Example: origin/main
Used for local development Used to track remote branch state
⭐⭐⭐⭐⭐ DEVOPS SCENARIO

18. Why should developers avoid directly working on the main branch?

Interview Answer:

Direct development on main can introduce incomplete, untested or unstable changes into the shared branch.

Feature branches allow changes to be developed, tested, reviewed and validated before merging.

Feature Branch
↓
Code Review
↓
CI Tests
↓
Main
⭐⭐⭐⭐⭐ REAL-TIME DEVOPS SCENARIO

19. How would you handle a production bug while working on a feature?

Interview Answer:

I would not mix the production fix with my unfinished feature. I would create a separate bug-fix or hotfix branch from the appropriate production branch. 

git switch main

git pull origin main

git switch -c hotfix-login

# Fix the issue

git add .

git commit -m "Fix login production issue"

git push -u origin hotfix-login

Then the change can go through review, testing and deployment.

⭐⭐⭐⭐⭐ CI/CD SCENARIO

20. How are Git branches used in CI/CD?

Interview Answer:

Different branches can trigger different CI/CD workflows depending on the organization's branching strategy.

feature/*
↓
Build + Test
develop
↓
Integration Environment
main
↓
Production Pipeline
Example:

A feature branch may run unit tests and security scans. A merge into main may trigger the production deployment pipeline, depending on the organization's CI/CD design.

🔥 REAL-TIME SCENARIO

21. You are on the wrong branch and have uncommitted changes. What should you do?

First, I would check the status and decide whether the changes should be committed or temporarily stashed. 

git status
git stash

Then switch to the correct branch:

git switch correct-branch

If needed, restore the changes:

git stash pop
🔥 REAL-TIME SCENARIO

22. What happens if two developers modify the same lines?

Git may detect a merge conflict when their branches are merged. The conflicting file must be reviewed manually and the correct changes selected before the merge can be completed.
