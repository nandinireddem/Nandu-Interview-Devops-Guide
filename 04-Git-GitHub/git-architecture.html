Git Architecture

Working Directory, Staging Area, Local Repository, Remote Repository, HEAD and the complete Git workflow.

⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

1. Explain Git Architecture.

Interview Answer:

Git architecture describes how Git manages our code from the time we modify a file until the changes are stored in a remote repository.

The main areas are:

  1. Working Directory
  2. Staging Area
  3. Local Repository
  4. Remote Repository
Working Directory
Modify files
→
Staging Area
git add
→
Local Repository
git commit
→
Remote Repository
git push
⭐⭐⭐⭐⭐ MUST KNOW

2. What is the Working Directory?

Interview Answer:

The Working Directory is the actual folder where we work on our project files.

When we create, modify or delete files, those changes initially exist in the Working Directory.

Example: 
project/
│
├── app.py
├── Dockerfile
└── README.md

Suppose we modify app.py. The modified file exists in the Working Directory, but it is not yet staged or committed.

⭐⭐⭐⭐⭐ MUST KNOW

3. What is the Staging Area?

Interview Answer:

The Staging Area is an intermediate area where we select the changes that should be included in the next commit.

We move changes from the Working Directory to the Staging Area using git add. 

git add app.py

Now app.py is staged and ready to be committed.

💡 Interview Point:

The staging area gives developers control over exactly which changes should be included in the next commit.

⭐⭐⭐⭐⭐ MUST KNOW

4. What is the Local Repository?

Interview Answer:

The Local Repository is the Git repository stored on the developer's local machine.

When we execute git commit, staged changes are recorded in the local repository. 

git add .
git commit -m "Add application changes"

The commit is created locally. It has not necessarily been sent to GitHub yet.

⭐⭐⭐⭐⭐ MUST KNOW

5. What is the Remote Repository?

Interview Answer:

A Remote Repository is a Git repository hosted on another system or service, such as GitHub.

It allows developers to share code and collaborate with other team members. 

git push origin main

This sends local commits to the remote repository.

⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

6. Explain the complete Git workflow.

Interview Answer:

A typical Git workflow starts with modifying files in the Working Directory.

Then we stage the required changes using git add, create a commit using git commit, and finally send the commit to the Remote Repository using git push.

Working Directory
↓ git add
Staging Area
↓ git commit
Local Repository
↓ git push
Remote Repository 
# 1. Check changes
git status

# 2. Stage changes
git add .

# 3. Create commit
git commit -m "Update application"

# 4. Send to GitHub
git push origin main
⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

7. What happens internally when you run git add?

Interview Answer:

When we run git add, Git takes the current version of the selected changes from the Working Directory and places them into the Staging Area.

It tells Git which changes should be included in the next commit. 

git add app.py

Working Directory
       ↓
    git add
       ↓
Staging Area
⭐⭐⭐⭐⭐ VERY FREQUENTLY ASKED

8. What happens when you run git commit?

Interview Answer:

git commit takes the staged changes and records them as a new commit in the Local Repository. 

git commit -m "Add login functionality"

A commit is created with a unique commit ID/hash.

⭐⭐⭐⭐⭐ MUST KNOW

9. What is the difference between git add and git commit?

git add git commit
Moves changes to staging area Records staged changes
Does not create a commit Creates a new commit
Working Directory → Staging Staging → Local Repository 
git add .
git commit -m "Add feature"
⭐⭐⭐⭐⭐ MUST KNOW

10. What is the difference between git commit and git push?

git commit git push
Creates a commit locally Sends commits to remote repository
Does not require internet Normally requires access to remote
Local operation Remote synchronization operation
Remember:

Commit = save the version locally.
Push = send the commits to the remote repository.

⭐⭐⭐⭐⭐ MUST KNOW

11. What is HEAD in Git?

Interview Answer:

HEAD is a reference that points to the current location in the Git history, normally the latest commit of the currently checked-out branch. 

main
  ↓
HEAD
  ↓
Latest Commit

If we switch to another branch, HEAD normally moves to that branch.

⭐⭐⭐⭐ IMPORTANT

12. What is the .git directory?

Interview Answer:

The .git directory contains Git's internal repository metadata.

It stores information required for commits, branches, references, configuration and Git's object database. 

my-project/
│
├── app.py
├── README.md
│
└── .git/
⚠️ Important:

Deleting the .git directory removes the Git repository metadata from that project directory.

⭐⭐⭐⭐ IMPORTANT

13. Why does Git use a staging area?

Interview Answer:

The staging area allows us to choose exactly which changes should go into the next commit.

This helps developers create clean and meaningful commits. 

app.py
README.md
config.yml

git add app.py README.md
git commit -m "Update application documentation"

Here, only the selected files are included in the commit.

⭐⭐⭐⭐ IMPORTANT

⭐⭐⭐⭐⭐ DEVOPS FAVORITE

15. How does Git fit into a DevOps CI/CD pipeline?

Interview Answer:

Git usually acts as the source-control system for the DevOps pipeline. A developer pushes code to GitHub, which can trigger a CI/CD pipeline.

Developer
↓
Git / GitHub
↓
CI Pipeline
↓
Build & Test
↓
Docker Image
↓
Deployment
Real-time Example:

A developer pushes a change to GitHub. GitHub Actions or Jenkins detects the change, runs tests, builds the application or Docker image and continues the deployment pipeline.

🔥 REAL-TIME SCENARIO

16. You committed a change but haven't pushed it. Where is it?

The commit exists in the Local Repository. It has not yet reached the Remote Repository. 

Working Directory
       ↓
Staging Area
       ↓
Local Repository  ← Commit exists here
       
Remote Repository ← Not updated yet

To send it to the remote repository: 

git push origin main
🔥 REAL-TIME SCENARIO

17. A developer says "I committed my code, so why can't my teammate see it?"

Interview Answer:

Because git commit only stores the changes in the developer's local repository.

The developer must push the commit to the remote repository. 

git push origin main

The teammate can then fetch or pull the updated changes.
