ArgoCD with Helm & Kustomize

How ArgoCD works with Helm charts and Kustomize configurations, including interview questions and real-time deployment flow.

⭐⭐⭐⭐⭐ 1. Why Use Helm or Kustomize with ArgoCD?

ArgoCD does not require every Kubernetes resource to be stored as plain YAML. It can work with configuration tools such as Helm and Kustomize.

Git Repository
↓
Helm / Kustomize
↓
ArgoCD Repo Server
↓
Generated Kubernetes Manifests
↓
Kubernetes Cluster
Interview Answer:
ArgoCD can use Helm and Kustomize as manifest generation tools. The Repo Server processes the source configuration and produces the Kubernetes manifests that ArgoCD deploys.

⭐⭐⭐⭐⭐ 2. What is Helm?

Helm is a package manager for Kubernetes. It allows applications to be packaged and deployed using reusable charts and configurable values.

Important Helm Concepts

  • Chart → Package containing Kubernetes resources.
  • values.yaml → Default configuration values.
  • templates → Kubernetes manifest templates.
  • Release → A deployed instance of a Helm chart.
Interview Answer:
Helm simplifies Kubernetes application packaging and deployment by using reusable charts and configurable values.

│
├── Chart.yaml
├── values.yaml

Remember:
Chart.yaml → Chart metadata
values.yaml → Configuration values
templates/ → Kubernetes resource templates

⭐⭐⭐⭐⭐ 5. Example ArgoCD Application Using Helm

apiVersion: argoproj.io/v1alpha1
kind: Application

metadata:
  name: my-app
  namespace: argocd

spec:
  project: default

  source:
    repoURL: https://github.com/example/gitops-repo.git
    targetRevision: main
    path: helm/my-app

    helm:
      valueFiles:
        - values.yaml

  destination:
    server: https://kubernetes.default.svc
    namespace: my-app

The path points to the Helm chart and the helm section provides Helm-specific configuration.

⭐⭐⭐⭐⭐ 6. What is Kustomize?

Kustomize is a Kubernetes-native configuration customization tool. It allows teams to customize Kubernetes YAML without using templates in the same way Helm does.

Interview Answer:
Kustomize allows Kubernetes manifests to be customized using overlays and patches while keeping a common base configuration.

⭐⭐⭐⭐ 9. Helm vs Kustomize

Helm Kustomize
Package manager for Kubernetes. Kubernetes configuration customization tool.
Uses charts and templates. Uses bases, overlays and patches.
Uses values for configuration. Uses overlays and patches for customization.
Useful for packaging reusable applications. Useful for environment-specific configuration.
Can manage application releases. Focuses on customizing Kubernetes manifests.

⭐⭐⭐⭐⭐ 10. Helm vs Kustomize — Interview Answer

Interview Answer:

Helm is a Kubernetes package manager that uses charts, templates and values to package and configure applications.

Kustomize is a Kubernetes-native customization tool that uses bases, overlays and patches to customize existing manifests.

In ArgoCD, both can be used as sources for generating the manifests that are ultimately synchronized to Kubernetes.

⭐⭐⭐⭐ 11. Can ArgoCD Deploy Helm Charts?

Yes.

ArgoCD can deploy applications from Helm chart sources and can use Helm values to customize deployments.

Important:
ArgoCD uses Helm primarily for manifest generation. ArgoCD itself manages the desired Kubernetes state and synchronization.

⭐⭐⭐⭐ 12. Can ArgoCD Deploy Kustomize?

Yes.

ArgoCD can detect a Kustomize application and generate the final manifests before synchronization.

⭐⭐⭐⭐⭐ 15. What Happens When values.yaml Changes?

  1. Developer changes a value in values.yaml.
  2. The change is committed to Git.
  3. ArgoCD detects the new Git revision.
  4. Repo Server renders the Helm chart using the updated values.
  5. ArgoCD compares the generated manifests with live resources.
  6. The Application becomes OutOfSync if a difference exists.
  7. ArgoCD synchronizes the new configuration.
  8. Kubernetes updates the application.

⭐⭐⭐⭐⭐ 16. What Happens When a Kustomize Overlay Changes?

  1. Developer modifies an environment overlay.
  2. Change is pushed to Git.
  3. ArgoCD detects the new revision.
  4. Repo Server processes the Kustomize configuration.
  5. Final manifests are generated.
  6. ArgoCD compares desired and live state.
  7. Resources are synchronized.
  8. Application health is monitored.
