ArgoCD Final Revision

Complete interview-focused revision covering GitOps, ArgoCD architecture, Applications, Projects, RBAC, synchronization, troubleshooting and real-time production scenarios.

⭐⭐⭐⭐⭐ 1. What is ArgoCD?

Interview Answer:
ArgoCD is a declarative GitOps continuous delivery tool for Kubernetes. It continuously compares the desired state stored in Git with the live state in Kubernetes and reconciles differences.
Git Repository
↓
Desired State
↓
ArgoCD
↓
Kubernetes Cluster
↓
Actual State
↓
Reconciliation

⭐⭐⭐⭐⭐ 2. What is GitOps?

GitOps is an operational model where Git acts as the source of truth for infrastructure and application configuration.

Developer
↓
Git Commit
↓
Pull Request
↓
Git Repository
↓
ArgoCD
↓
Kubernetes
↓
Application
Key Point:
Instead of manually changing Kubernetes resources, desired changes are committed to Git and the GitOps controller reconciles the cluster.

⭐⭐⭐⭐⭐ 3. ArgoCD Architecture

Component Purpose
API Server Handles API requests, CLI and UI communication.
Application Controller Monitors applications and reconciles desired state with live state.
Repo Server Connects to repositories and generates Kubernetes manifests.
Redis Provides caching used by ArgoCD components.
Dex Server Can support identity integration for authentication.
ApplicationSet Controller Generates and manages applications from templates and generators.

⭐⭐⭐⭐⭐ 6. Sync Status vs Health Status

Sync Status Health Status
Shows whether desired and live configuration match. Shows whether resources are functioning correctly.
Synced / OutOfSync Healthy / Degraded / Progressing
Important Interview Point:
An application can be Synced but Degraded. ArgoCD may have successfully applied the desired configuration while the Kubernetes workload itself is unhealthy.

⭐⭐⭐⭐⭐ 9. What is an AppProject?

An AppProject provides a logical and security boundary for ArgoCD applications.

It Can Restrict:

  • Git repositories.
  • Destination clusters.
  • Namespaces.
  • Resource types.
  • Project roles.

⭐⭐⭐⭐⭐ 10. ArgoCD RBAC

ArgoCD RBAC controls what users and groups are allowed to do inside ArgoCD.

Action Example
get View an application.
create Create an application.
update Modify an application.
delete Delete an application.
sync Synchronize an application.

⭐⭐⭐⭐⭐ 12. ArgoCD RBAC vs Kubernetes RBAC

ArgoCD RBAC Kubernetes RBAC
Controls access to ArgoCD actions. Controls access to Kubernetes API resources.
Controls Application operations. Controls Pods, Deployments, Services, etc.
Configured through ArgoCD authorization. Uses Role, ClusterRole and bindings.

⭐⭐⭐⭐⭐ 13. Sync Waves

Sync waves allow resources to be deployed in a specific order.

Wave 0
Namespace / Configuration
↓

↓

Interview Answer:
Sync waves are useful when certain Kubernetes resources need to be created before other resources.

⭐⭐⭐⭐ 14. Hooks

ArgoCD hooks allow Kubernetes resources such as Jobs to run at specific stages of the synchronization lifecycle.

Common lifecycle stages include:

  • PreSync
  • Sync
  • PostSync
  • SyncFail

⭐⭐⭐⭐⭐ 17. OutOfSync Troubleshooting

argocd app get my-app
argocd app diff my-app

Compare the desired state with the live state and determine what resource changed.

Typical Causes:
Manual kubectl changes, Git changes, generated manifest differences, missing resources or incorrect configuration.

⭐⭐⭐⭐⭐ 18. SyncFailed Troubleshooting

  1. Read the ArgoCD error.
  2. Identify the failing resource.
  3. Check Kubernetes events.
  4. Check permissions.
  5. Validate the manifest.
  6. Fix the source configuration.
  7. Retry synchronization.
kubectl get events -A
kubectl describe <resource>

⭐⭐⭐⭐⭐ 19. Degraded Application

If an application is Degraded, investigate the underlying Kubernetes resources. 

kubectl get pods -A
kubectl describe pod <pod-name>
kubectl logs <pod-name>
Remember:
Synced ≠ Healthy

⭐⭐⭐⭐⭐ 20. Production Deployment Failure

↓
Production Deployment
↓
Application Failure
↓
Check Logs + Events
↓
Identify Bad Change
↓

Recovery
Interview Answer:
In a production failure, I first identify the failing resource and restore service safely. If the incident was caused by a recent Git change, I can revert that change so Git returns to a known-good state, then verify that ArgoCD reconciles the cluster successfully.

🧠 24. 30-Second Interview Answer

"ArgoCD is a declarative GitOps continuous delivery tool for Kubernetes. It uses Git as the source of truth and continuously compares the desired state in Git with the live state in Kubernetes. Its Application Controller performs reconciliation, while the Repo Server generates manifests from sources such as YAML, Helm and Kustomize. ArgoCD supports automated synchronization, self-healing, RBAC and Projects, which help implement secure and reliable Kubernetes deployments."
