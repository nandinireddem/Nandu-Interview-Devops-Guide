ArgoCD Architecture

Understand the main ArgoCD components, their responsibilities, communication flow and how Git changes reach Kubernetes.

⭐⭐⭐⭐⭐ 1. ArgoCD Architecture Overview

ArgoCD follows a GitOps architecture where Git stores the desired application state and ArgoCD continuously works to keep the Kubernetes cluster aligned with that state.

👨‍💻 Developer
↓
📦 Git Repository
↓
🔄 ArgoCD
↓
☸️ Kubernetes API Server
↓
🚀 Application Resources
Interview Answer:
ArgoCD continuously monitors the desired state stored in Git, compares it with the live state of Kubernetes and reconciles the differences through the Kubernetes API.

⭐⭐⭐⭐⭐ 2. Main ArgoCD Components

Component Responsibility
API Server Provides the API used by the ArgoCD Web UI, CLI and other clients. Handles application and project operations.
Application Controller Monitors applications, compares desired and live state, detects drift and performs reconciliation.
Repo Server Connects to Git repositories and generates Kubernetes manifests from YAML, Helm, Kustomize and other supported sources.
Redis Used primarily as a caching layer to improve ArgoCD performance.
Dex Optional identity provider integration component used for authentication with external identity systems.
ApplicationSet Controller Automates creation and management of multiple ArgoCD Applications.

⭐⭐⭐⭐⭐ 3. ArgoCD API Server

The API Server is the main entry point for users and external clients. The ArgoCD Web UI and CLI communicate with the API Server.

Responsibilities

  • Provides ArgoCD APIs.
  • Handles requests from the Web UI.
  • Handles requests from the CLI.
  • Provides application information.
  • Supports authentication and authorization.
  • Handles application and project operations.
Interview Answer:
The ArgoCD API Server acts as the interface between users or clients and ArgoCD services. The UI and CLI communicate with it to manage and inspect applications.

⭐⭐⭐⭐⭐ 4. Application Controller

The Application Controller is the most important component for reconciliation.

Git Desired State
↓
Application Controller
↕
Kubernetes API
↓
Live State

Main Responsibilities

  • Monitors ArgoCD Applications.
  • Compares desired state with live state.
  • Detects drift.
  • Determines Synced or OutOfSync status.
  • Performs reconciliation.
  • Monitors application health.
  • Triggers synchronization according to policy.
Interview Answer:
The Application Controller continuously compares the desired state from Git with the live Kubernetes state and reconciles differences according to the configured policy.

⭐⭐⭐⭐⭐ 5. Repository Server

The Repo Server is responsible for retrieving application configuration from source repositories and generating Kubernetes manifests.

Git Repository
↓
Repo Server
↓
Manifest Generation
↓
Kubernetes Manifests
↓
Application Controller

Common Configuration Sources

  • Plain Kubernetes YAML
  • Helm charts
  • Kustomize
  • Other supported configuration tools
Important Interview Difference:
Repo Server → Gets configuration and generates manifests.

Application Controller → Compares states and reconciles the application.

⭐⭐⭐ 6. Redis

ArgoCD uses Redis mainly for caching.

Interview Answer:
Redis is a cache used by ArgoCD to improve performance. It is not the source of truth. Git remains the source of truth for the desired application configuration.

⭐⭐⭐ 7. Dex Server

Dex can be used as an identity broker between ArgoCD and external identity providers.

It is mainly related to authentication and identity integration. Authorization and permissions are handled through ArgoCD's access control mechanisms.

⭐⭐⭐ 8. ApplicationSet Controller

ApplicationSet helps create multiple ArgoCD Applications from a common template.

ApplicationSet
↓
Generator
↓
Application Template
↓
Application 1    Application 2    Application 3

This becomes useful when the same application needs to be deployed to multiple clusters or environments.

⭐⭐⭐⭐⭐ 10. How Does ArgoCD Communicate With Kubernetes?

ArgoCD communicates with Kubernetes through the Kubernetes API Server.

ArgoCD Application Controller
↓
Kubernetes API Server
↓
Deployments
↓
ReplicaSets
↓
Pods
↓
Services / Ingress / ConfigMaps / Secrets
Interview Answer:
ArgoCD uses the Kubernetes API to inspect the live state of resources and apply the desired configuration to the target cluster.

⭐⭐⭐⭐⭐ 11. Desired State vs Live State

State Meaning
Desired State Configuration stored in Git.
Live State Resources currently running in Kubernetes.
Drift Difference between desired and live state.
Reconciliation Process of bringing live state toward desired state.

⭐⭐⭐⭐⭐ 12. What Happens When Git Changes?

  1. Developer modifies Kubernetes configuration.
  2. The change is committed and pushed to Git.
  3. ArgoCD detects the updated desired state.
  4. Repo Server retrieves the configuration.
  5. Required manifests are generated.
  6. Application Controller compares desired and live state.
  7. The application becomes OutOfSync if there is a difference.
  8. ArgoCD synchronizes the resources according to the configured policy.
  9. Kubernetes API applies the changes.
  10. ArgoCD monitors the resulting health.

⭐⭐⭐⭐⭐ 13. What Happens If Someone Uses kubectl?

Suppose Git says the Deployment should have three replicas, but an engineer manually changes it to one replica using kubectl.

Git
replicas = 3
↓
Manual kubectl Change
replicas = 1
↓
ArgoCD Detects Difference
↓
OutOfSync
↓
Self-Heal if configured
↓
Cluster moves toward Git state
Interview Term: This difference between Git and Kubernetes is called configuration drift.

⭐⭐⭐⭐ 14. What If Git Repository Is Unavailable?

If ArgoCD cannot access the Git repository, it cannot obtain fresh desired-state information from that repository.

Existing workloads already running in Kubernetes do not simply disappear because Git is temporarily unavailable. However, ArgoCD cannot fetch new desired configuration from that repository until connectivity is restored.

⭐⭐⭐⭐ 15. What If Kubernetes API Is Unavailable?

ArgoCD may still be able to access repository information, but it cannot inspect or modify the target Kubernetes cluster while the Kubernetes API is unavailable.

Once Kubernetes API connectivity is restored, ArgoCD can resume monitoring and reconciliation.
