ArgoCD Troubleshooting & Real-Time Scenarios

Practical troubleshooting for OutOfSync, SyncFailed, Degraded, repository errors, Kubernetes failures and common production issues.

⭐⭐⭐⭐⭐ 1. How Do You Troubleshoot ArgoCD?

The first step is to identify whether the problem is related to the Git repository, manifest generation, ArgoCD synchronization, Kubernetes resources or application health.

Git Repository
↓
Repo Server
↓
Manifest Generation
↓
Application Controller
↓
Sync
↓
Kubernetes
↓
Application Health
Interview Answer:
I first check the Application status and events, then determine whether the failure is in Git access, manifest generation, synchronization, Kubernetes resources or application health. I troubleshoot from the ArgoCD Application down to the underlying Kubernetes resources.

⭐⭐⭐⭐⭐ 2. Application is OutOfSync

Possible Causes

  • Git configuration changed.
  • Someone manually changed the Kubernetes resource.
  • Generated manifests differ from live resources.
  • Different Git revision is being tracked.
  • Expected resource is missing.

What I Check

argocd app get my-app

argocd app diff my-app
Approach:
I compare the desired state with the live state using the Application details or CLI diff. Then I identify which resource differs before performing a sync.

⭐⭐⭐⭐⭐ 3. Application is SyncFailed

SyncFailed means ArgoCD attempted synchronization but one or more operations failed.

Common Causes

  • Invalid Kubernetes manifest.
  • Insufficient Kubernetes permissions.
  • Resource already exists with conflicting ownership.
  • Invalid namespace.
  • Admission webhook rejection.
  • Immutable field modification.

Useful Commands

argocd app get my-app

kubectl get events -n my-namespace

kubectl describe deployment my-app -n my-namespace

⭐⭐⭐⭐⭐ 4. Application is Degraded

A Degraded status generally means that the resources may match the desired configuration but one or more resources are not healthy.

Git = Desired State
↓
ArgoCD Sync
↓
Kubernetes Resource Created
↓
Pod Fails
↓
❌ Application Degraded

Check

kubectl get pods -n my-namespace

kubectl describe pod <pod-name> -n my-namespace

kubectl logs <pod-name> -n my-namespace
Important:
If ArgoCD says the application is Degraded, do not immediately assume ArgoCD itself is broken. The underlying Kubernetes workload may be unhealthy.

⭐⭐⭐⭐⭐ 5. Git Repository Connection Failed

Possible Causes

  • Incorrect repository URL.
  • Invalid credentials.
  • Expired access token.
  • Private repository without valid credentials.
  • Network or certificate problem.

Check

argocd repo list

argocd repo get https://github.com/example/repo.git
Approach:
I verify the repository URL, authentication configuration and whether ArgoCD can successfully access the repository.

⭐⭐⭐⭐⭐ 6. Manifest Generation Failed

ArgoCD may fail before synchronization if it cannot generate valid Kubernetes manifests.

Common Causes

  • Invalid YAML.
  • Broken Helm template.
  • Invalid Kustomize configuration.
  • Missing Helm values.
  • Unsupported plugin or configuration.
Interview Answer:
If manifest generation fails, I inspect the Application error message and determine whether the source is plain YAML, Helm or Kustomize. Then I validate the configuration independently before retrying.

⭐⭐⭐⭐ 7. Namespace Not Found

A deployment may fail when the target namespace does not exist or the application is configured with an incorrect destination.

Check

kubectl get namespaces

kubectl get applications -n argocd

argocd app get my-app
Fix:
Verify the destination namespace and configure namespace creation where appropriate for the deployment model being used.

⭐⭐⭐⭐⭐ 8. Pod is CrashLoopBackOff

This is usually a Kubernetes workload problem rather than an ArgoCD problem. 

kubectl get pods -n my-namespace

kubectl describe pod <pod-name> -n my-namespace

kubectl logs <pod-name> -n my-namespace

kubectl logs <pod-name> --previous -n my-namespace

Common Causes

  • Application startup failure.
  • Incorrect environment variables.
  • Missing Secret or ConfigMap.
  • Incorrect command or arguments.
  • Health probe failure.
  • Dependency unavailable.

⭐⭐⭐⭐⭐ 9. ImagePullBackOff

The Kubernetes node cannot successfully pull the required container image.

Check

kubectl describe pod <pod-name> -n my-namespace

Possible Causes

  • Incorrect image name.
  • Incorrect image tag.
  • Private registry authentication issue.
  • Registry unavailable.
  • Image does not exist.
Important:
ArgoCD may have successfully synchronized the Deployment while the application still remains unhealthy because Kubernetes cannot pull the image.

⭐⭐⭐⭐ 10. Sync is Hanging

A sync can appear stuck when a resource is waiting for readiness, dependencies are unavailable or Kubernetes operations are blocked.

Check

argocd app get my-app

kubectl get pods -A

kubectl get events -A --sort-by=.lastTimestamp
Approach:
I check the specific resource where the sync is waiting, inspect Kubernetes events and verify whether the workload is becoming ready.

⭐⭐⭐⭐⭐ 11. ArgoCD Cannot Connect to Kubernetes

Possible Causes

  • Cluster credentials problem.
  • Network connectivity issue.
  • Expired or invalid authentication.
  • API server unavailable.
  • Certificate problem.

Check

argocd cluster list
Interview Answer:
I verify the cluster registration, connectivity to the Kubernetes API server and the credentials used by ArgoCD for that cluster.

⭐⭐⭐⭐ 12. Useful ArgoCD CLI Commands

Command Purpose
argocd app list List applications.
argocd app get APP Show application details.
argocd app diff APP Compare desired and live state.
argocd app sync APP Trigger synchronization.
argocd app history APP View deployment history.
argocd repo list List configured repositories.
argocd cluster list List registered clusters.

⭐⭐⭐⭐⭐ 13. Useful Kubernetes Commands

kubectl get pods -A

kubectl get deployments -A

kubectl get services -A

kubectl get events -A

kubectl describe pod <pod-name> -n <namespace>

kubectl logs <pod-name> -n <namespace>

kubectl get nodes
Golden Rule:
ArgoCD manages the desired state, but the actual workload still runs inside Kubernetes. Always inspect Kubernetes when application health is failing.

⭐⭐⭐⭐⭐ 14. Scenario: Git Change but ArgoCD Does Not Update

Possible Reasons

  1. Wrong branch configured.
  2. Wrong repository path.
  3. ArgoCD cannot access the repository.
  4. Manifest generation failed.
  5. Application is not configured for automated sync.
Interview Answer:
I first check the Application source configuration, tracked revision and path. Then I verify repository connectivity and manifest generation. Finally I check whether the application requires manual sync or has automated synchronization enabled.

⭐⭐⭐⭐⭐ 15. Scenario: Manual kubectl Change Gets Reverted

Git
replicas = 3
↓
kubectl change
replicas = 1
↓
ArgoCD detects drift
↓
Self-Heal
↓
replicas = 3
Explanation:
This is expected behavior when the application is configured for automated synchronization with self-healing. Git remains the desired source of truth.

⭐⭐⭐⭐⭐ 16. Scenario: Sync Succeeds but Application is Degraded

Git Configuration
↓
ArgoCD Sync
↓
✅ Sync Successful
↓
Kubernetes Pod
↓
❌ Application Failure
↓
⚠️ Degraded
Interview Answer:
A successful sync only means ArgoCD applied the desired resources. The application can still be unhealthy. I would inspect Pods, Deployments, events, logs and health probes.

🧠 One-Minute Revision

OutOfSync → Desired state differs from live state.

SyncFailed → Synchronization operation failed.

Degraded → Application resources are unhealthy.

CrashLoopBackOff → Container repeatedly fails/restarts.

ImagePullBackOff → Kubernetes cannot successfully pull the image.

Git Error → Check repository URL, credentials and connectivity.

Manifest Error → Check YAML, Helm or Kustomize generation.

Golden Rule → Troubleshoot from ArgoCD status down to the underlying Kubernetes resource.
