ArgoCD Applications & Sync

Applications, synchronization, OutOfSync, automated deployment, self-healing, pruning, health status and real-time GitOps flow.

⭐⭐⭐⭐⭐ 1. What is an ArgoCD Application?

An ArgoCD Application is a Kubernetes custom resource that defines which configuration should be deployed from a source repository to a target Kubernetes cluster and namespace.

Interview Answer:
An ArgoCD Application connects the desired state stored in Git with a destination Kubernetes cluster and continuously manages the application according to the configured synchronization policy.

⭐⭐⭐⭐⭐ 2. Three Important Parts of an Application

Part Meaning
Source Where the desired configuration comes from.
Destination Where the application will be deployed.
Sync Policy Controls how synchronization should happen.
📦 Git Repository
Source
↓
🔄 ArgoCD Application
↓
☸️ Kubernetes Cluster
Destination

⭐⭐⭐⭐⭐ 3. Example ArgoCD Application

apiVersion: argoproj.io/v1alpha1
kind: Application

metadata:
  name: nginx-app
  namespace: argocd

spec:
  project: default

  source:
    repoURL: https://github.com/example/gitops-repo.git
    targetRevision: main
    path: manifests

  destination:
    server: https://kubernetes.default.svc
    namespace: nginx

  syncPolicy:
    automated:
      prune: true
      selfHeal: true
Remember:
source → What should be deployed?
destination → Where should it be deployed?
syncPolicy → How should synchronization happen?

⭐⭐⭐⭐⭐ 4. What is Sync?

Sync is the process of applying the desired state from Git to the target Kubernetes cluster.

Git Desired State
↓
ArgoCD
↓
Compare With Live State
↓
Differences Found
↓
SYNC
↓
Kubernetes Updated

⭐⭐⭐⭐⭐ 5. What is OutOfSync?

An application becomes OutOfSync when the desired state in Git differs from the live state in Kubernetes.

Git
replicas = 3
↓
Kubernetes
replicas = 1
↓
⚠️ OUT OF SYNC
Interview Answer:
OutOfSync means there is a difference between the desired state stored in Git and the live state running in the Kubernetes cluster.

⭐⭐⭐⭐⭐ 6. What is Synced?

An application is Synced when the live Kubernetes state matches the desired configuration.

Git
replicas = 3
↕
Kubernetes
replicas = 3
↓
✅ SYNCED

⭐⭐⭐⭐⭐ 7. Manual Sync

In manual synchronization, ArgoCD detects a difference but waits for the user to trigger synchronization.

Git Change
↓
ArgoCD Detects Difference
↓
⚠️ OutOfSync
↓
👨‍💻 Engineer Clicks Sync
↓
Kubernetes Updated
Use Case:
Manual sync is useful when deployments, especially production deployments, require an explicit human action.

⭐⭐⭐⭐⭐ 8. Automated Sync

With automated synchronization enabled, ArgoCD can automatically apply eligible changes detected in the desired Git state.

Developer
↓
Git Commit
↓
ArgoCD Detects Change
↓
Automatic Sync
↓
Kubernetes Updated
Interview Point:
Automated sync removes the need for an engineer to manually click the Sync button for every eligible Git change.

⭐⭐⭐⭐⭐ 9. What is Self-Heal?

Self-healing allows ArgoCD to react to certain changes made directly to Kubernetes that cause drift from the desired Git state.

Git
replicas = 3
↓
Manual kubectl Change
replicas = 1
↓
ArgoCD Detects Drift
↓
Self-Heal
↓
Cluster moves toward Git state
Interview Answer:
Self-heal helps ArgoCD automatically reconcile certain out-of-band changes so that the live state moves back toward the desired Git state.

⭐⭐⭐⭐ 10. What is Pruning?

Pruning removes resources that are no longer defined in the desired application state when pruning is enabled.

Git
Deployment + Service
↓
Developer removes Service from Git
↓
ArgoCD Detects Difference
↓
Pruning Enabled
↓
Service Removed From Cluster
Important:
Pruning can delete Kubernetes resources. It should be enabled carefully, especially for production environments.

⭐⭐⭐⭐⭐ 11. Sync Policy

The sync policy defines how ArgoCD should synchronize the application.

Option Purpose
Automated Automatically synchronize eligible changes.
Prune Remove resources no longer desired.
Self-Heal React to supported live-state drift.

⭐⭐⭐⭐ 12. Application Health

ArgoCD also monitors the health of application resources.

Status Meaning
Healthy Resources are operating as expected.
Progressing Resources are still moving toward the expected state.
Degraded One or more resources are unhealthy.
Missing An expected resource is not present.
Unknown ArgoCD cannot determine the resource health.

⭐⭐⭐⭐⭐ 13. Synced vs Healthy

Status Question It Answers
Synced Does the live configuration match Git?
Healthy Are the deployed resources operating correctly?
Example:
An application can be Synced but Degraded if Kubernetes matches Git but the deployed application is unhealthy.

⭐⭐⭐⭐ 14. Sync Waves

Sync waves allow resources to be applied in a controlled order.

Wave 0
Namespace
↓
Wave 1
ConfigMap / Secret
↓
Wave 2
Deployment
↓
Wave 3
Ingress

This is useful when certain resources need to exist before dependent resources are deployed.

⭐⭐⭐⭐⭐ 16. Real-Time Interview Scenario

Scenario

Your Git repository says the application should have three replicas, but someone manually changes the Deployment to one replica using kubectl.

What happens?

  1. ArgoCD compares desired and live state.
  2. It detects a difference.
  3. The Application becomes OutOfSync.
  4. If automated sync with self-heal is enabled, ArgoCD can reconcile the drift.
  5. The Kubernetes Deployment moves toward the Git-defined state.
  6. ArgoCD checks the resulting application health.
Interview Answer:
"This is configuration drift. ArgoCD detects that the live state differs from the desired state in Git. If self-healing is enabled, ArgoCD automatically reconciles the supported drift and brings the cluster back toward the Git state."
