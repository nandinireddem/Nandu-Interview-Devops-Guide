GitOps & ArgoCD Basics

Core GitOps concepts and ArgoCD fundamentals explained in interview-ready language with practical Kubernetes examples.

⭐⭐⭐⭐⭐ 1. What is GitOps?

GitOps is a way of managing application and infrastructure deployments where Git acts as the source of truth. The desired state of the system is stored in Git, and an automated controller continuously works to make the actual environment match that desired state.

Interview Answer:
GitOps is a declarative deployment approach where the desired state of applications and infrastructure is maintained in Git. A GitOps controller such as ArgoCD continuously compares the Git state with the Kubernetes cluster and reconciles differences.

⭐⭐⭐⭐⭐ 2. Why Do We Use GitOps?

  • Git provides version history.
  • Every configuration change can be reviewed.
  • Changes can go through Pull Requests.
  • Rollback becomes easier.
  • Deployment becomes consistent and repeatable.
  • Cluster configuration becomes auditable.
  • Manual kubectl changes can be reduced.
Key Idea:
Instead of manually telling Kubernetes what to do every time, we declare what we want in Git and let automation maintain that state.

⭐⭐⭐⭐⭐ 3. What is ArgoCD?

ArgoCD is a Kubernetes-native continuous delivery and GitOps tool. It monitors Git repositories containing Kubernetes manifests or Helm/Kustomize configurations and synchronizes them with the target Kubernetes cluster.

Interview Answer:
ArgoCD is a declarative GitOps continuous delivery tool for Kubernetes. It continuously monitors the desired state stored in Git and synchronizes that state with the Kubernetes cluster.

⭐⭐⭐⭐⭐ 4. Traditional Deployment vs GitOps

Traditional Approach GitOps Approach
Developer or operator may manually run deployment commands. Git contains the desired state.
Cluster state may not be fully tracked. Configuration is version-controlled.
Rollback can require manual commands. Previous Git versions can be restored.
Configuration changes may be difficult to audit. Git history provides an audit trail.
Manual drift correction. Controller can continuously reconcile drift.

⭐⭐⭐⭐⭐ 5. Declarative vs Imperative

Imperative

You tell the system how to perform an action.

kubectl create deployment nginx --image=nginx

Declarative

You define what the final state should be. Kubernetes determines how to reach that state.

Git
↓
deployment.yaml
↓
ArgoCD
↓
Kubernetes
Interview Point:
GitOps strongly favors a declarative model because the desired state is explicitly stored and versioned.

⭐⭐⭐⭐⭐ 6. Push-Based vs Pull-Based Deployment

Push-Based Pull-Based
CI/CD system pushes changes into the cluster. Agent/controller pulls desired state from Git.
Pipeline usually needs cluster credentials. Cluster-side controller can access Git.
Example: CI pipeline running kubectl apply. Example: ArgoCD.
Important:
ArgoCD follows the pull-based GitOps model. ArgoCD continuously monitors the Git repository and reconciles the desired state with Kubernetes.

⭐⭐⭐⭐⭐ 8. Desired State vs Actual State

Term Meaning
Desired State The configuration defined in Git.
Actual State The resources currently running in Kubernetes.
Drift A difference between desired and actual state.
Reconciliation The process of bringing actual state toward desired state.

⭐⭐⭐⭐⭐ 9. What is Drift?

Drift occurs when the Kubernetes cluster no longer matches the configuration stored in Git.

Git says replicas = 3
↓
Someone manually changes replicas to 1
↓
Git State ≠ Cluster State
↓
Drift Detected
If automated self-healing is enabled, ArgoCD can restore the cluster toward the Git-defined state.

⭐⭐⭐⭐⭐ 10. What is Sync?

Sync means applying the desired configuration from Git to the Kubernetes cluster so that the cluster moves toward the desired state.

ArgoCD can perform synchronization manually or automatically depending on the application's configuration.

⭐⭐⭐⭐⭐ 11. What is Reconciliation?

Reconciliation is the continuous process of comparing the desired state with the actual state and identifying differences.

Interview Wording:
ArgoCD continuously observes the application state and compares it with the desired state in Git. If there is a difference, ArgoCD can take action to reconcile the cluster according to the configured sync policy.

⭐⭐⭐⭐ 12. Sync vs Reconciliation

Sync Reconciliation
Action that applies desired configuration. Continuous comparison process.
Can be manually or automatically triggered. Continuously evaluates state.
Moves cluster toward desired state. Detects whether the cluster has drifted.

⭐⭐⭐⭐ 13. What is Self-Healing?

Self-healing is the ability of ArgoCD to automatically correct certain out-of-band changes so that the cluster returns toward the desired state defined in Git.

Git
replicas: 3
↓
Manual Change
replicas: 1
↓
ArgoCD Detects Drift
↓
Self-Healing
↓
replicas: 3

⭐⭐⭐⭐ 14. What is Pruning?

Pruning removes Kubernetes resources that were previously managed by ArgoCD but are no longer defined in the desired Git configuration, when pruning is enabled.

Interview Caution:
Pruning can delete resources. It should be enabled carefully, especially in production environments.

⭐⭐⭐⭐⭐ 15. Why is Git the Source of Truth?

  • Git provides version control.
  • Changes are traceable.
  • Pull Requests can provide review and approval.
  • Previous versions are available.
  • Deployment configuration is centralized.
  • Teams can reproduce the desired environment.
