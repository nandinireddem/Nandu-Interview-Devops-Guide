QUESTION 01

What is Cloud Security?

⭐⭐⭐⭐⭐ MUST KNOW

Cloud security is the set of technologies, processes, policies and controls used to protect cloud resources, applications, identities and data from unauthorized access, misconfiguration, attacks and other security threats.

💡 Simple Example

An application is running on AWS. Cloud security may involve:

→ IAM controls who can access resources
→ Security Groups control network access
→ Encryption protects data
→ Logging helps detect suspicious activity
→ Least privilege limits unnecessary permissions

🎤 Interview Answer

"Cloud security is the practice of protecting cloud infrastructure, applications, identities and data using appropriate security controls, policies and processes."

QUESTION 02

What is the Shared Responsibility Model?

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

The Shared Responsibility Model defines which security responsibilities are handled by the cloud provider and which responsibilities are handled by the customer. The exact division depends on the cloud service being used.

CLOUD PROVIDER ↓ Security OF the Cloud ↓ Physical Infrastructure Data Centers Hardware Networking Infrastructure

CUSTOMER ↓ Security IN the Cloud ↓ Data Identity & Access Configurations Operating System where applicable Applications
🔥 AWS Example

AWS is responsible for protecting the physical infrastructure and underlying cloud infrastructure. The customer is responsible for correctly configuring resources, controlling access and protecting their data. For an EC2 instance, the customer also has responsibility for the guest operating system and software they install.

🎤 Strong Interview Answer

"The Shared Responsibility Model divides security responsibilities between the cloud provider and the customer. The provider is responsible for security of the underlying cloud infrastructure, while the customer is responsible for security controls within their environment, such as data, identity, configuration and, depending on the service, the operating system and applications."

QUESTION 03

What is the difference between Authentication and Authorization?

⭐⭐⭐⭐⭐ MUST KNOW

Authentication verifies who you are.

Authorization determines what you are allowed to do after you are authenticated.

💡 Simple Example

You log in to AWS.
Authentication: → "Are you really Nandu?"

Authorization: → "What AWS resources is Nandu allowed to access?"

Authentication Authorization
Who are you? What can you do?
Verifies identity Checks permissions
Login / identity verification Policies / permissions
🎤 Interview Answer

"Authentication verifies the identity of a user or system, while authorization determines what actions that authenticated identity is permitted to perform."

QUESTION 04

What is the Principle of Least Privilege?

⭐⭐⭐⭐⭐ VERY COMMON

The Principle of Least Privilege means giving a user, service or application only the permissions required to perform its intended task and no unnecessary permissions.

🔥 Real-Time Example

Suppose a CI/CD pipeline only needs permission to push an image to Amazon ECR. Instead of giving the pipeline administrator-level access to the entire AWS account, provide only the required permissions.

🎤 Interview Answer

"Least privilege means granting only the minimum permissions required for a user or application to perform its task. It reduces the potential impact if credentials are compromised."

QUESTION 05

What is IAM?

⭐⭐⭐⭐⭐ MUST KNOW

IAM stands for Identity and Access Management. It is used to control who can access cloud resources and what actions they are allowed to perform.

🧠 Remember

Identity → Who is accessing?
Authentication → Are they really who they claim to be?
Authorization → What can they do?
IAM → Manage identities and permissions.
💡 AWS Example

A developer may need permission to read objects from a specific S3 bucket but should not automatically receive permission to delete the entire AWS infrastructure.

AWS IAM is covered separately in this guide in much greater depth. Here the focus is the fundamental security concept.

QUESTION 06

What is Encryption?

⭐⭐⭐⭐⭐ MUST KNOW

Encryption converts readable data, called plaintext, into an encoded form, called ciphertext, so that unauthorized parties cannot easily understand it. A cryptographic key is used as part of the encryption and decryption process.

💡 Example

Sensitive customer data is stored in a database. If the data is encrypted at rest, someone who gains access to the underlying encrypted data cannot simply read it as normal plaintext.

🎤 Interview Answer

"Encryption protects data by transforming plaintext into ciphertext using cryptographic mechanisms. Authorized systems can decrypt the data using the appropriate key."

QUESTION 07

What is the difference between Encryption at Rest and Encryption in Transit?

⭐⭐⭐⭐⭐ VERY COMMON
Encryption at Rest Encryption in Transit
Protects stored data Protects data while moving
Disk / database / object storage Network communication
Example: encrypted storage Example: HTTPS / TLS
Data Stored → 🔐 Encryption at Rest

Application → 🔐 TLS / HTTPS → Server
🔐 Encryption in Transit
🎤 Interview Answer

"Encryption at rest protects data while it is stored, while encryption in transit protects data while it is moving between systems, such as between a client and server using TLS."

QUESTION 08

What is Multi-Factor Authentication?

⭐⭐⭐⭐⭐

Multi-Factor Authentication, or MFA, requires more than one authentication factor to verify a user's identity. Common factor categories include:

→ Something you know
→ Something you have
→ Something you are

💡 Example

Password + authentication code from an authenticator device. Even if the password is compromised, the second factor adds another security layer.

🎤 Interview Answer

"MFA strengthens authentication by requiring multiple independent authentication factors, reducing the risk of account compromise from a stolen password."

QUESTION 09

What is a Security Group?

⭐⭐⭐⭐⭐ DEVOPS FAVORITE

In AWS, a Security Group acts as a virtual firewall for associated resources such as EC2 instances. It controls allowed inbound and outbound network traffic based on configured rules. Security Groups are stateful.

🔥 Example

Web server:
HTTP/HTTPS → Allow from appropriate sources
SSH → Allow only from a trusted administrative source

You should avoid exposing administrative ports broadly to the internet unless there is a justified requirement.

🎤 Interview Answer

"An AWS Security Group acts as a virtual firewall for supported resources such as EC2. It controls inbound and outbound traffic using rules and is stateful."

QUESTION 10

What is a Network ACL?

⭐⭐⭐⭐⭐

A Network ACL, or NACL, is a network-level access control mechanism associated with a VPC subnet. AWS Network ACLs are stateless, so return traffic must be explicitly allowed by the appropriate rule.

🎤 Interview Answer

"A Network ACL is a stateless network access control layer associated with a subnet. It can allow or deny traffic based on rules."

QUESTION 11

Security Group vs Network ACL — What is the difference?

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

Security Group → Stateful → Resource

QUESTION 12

Why should you avoid using the root user for daily AWS tasks?

⭐⭐⭐⭐⭐

The AWS account root user has extensive privileges. Using it for everyday operations increases security risk. Instead, organizations should use appropriate IAM identities and permissions for normal tasks.

🎤 Interview Answer

"I would avoid using the AWS root user for daily operations because it has highly privileged access. I would use appropriate IAM identities with least-privilege permissions and protect the root account with strong security controls such as MFA."

QUESTION 13

Why should AWS credentials not be hard-coded in source code?

⭐⭐⭐⭐⭐ DEVOPS FAVORITE

Hard-coding credentials in source code can expose secrets through Git repositories, logs, build artifacts or accidental sharing. Credentials should be managed using appropriate secret and identity mechanisms.

❌ Bad Practice

Password or access key directly inside application source code.

✅ Better Approach Use appropriate IAM roles, secret-management mechanisms and temporary credentials where possible.

🎤 Interview Answer

"I would never hard-code cloud credentials in source code. Depending on the workload, I would prefer IAM roles or an appropriate secrets-management mechanism and use least privilege."

QUESTION 14

What is a secret?

⭐⭐⭐⭐

A secret is sensitive information that should be protected from unauthorized access. Examples include:

→ API keys
→ Database passwords
→ Tokens
→ Private credentials

🔥 DevOps Example

A CI/CD pipeline needs a database password. Instead of placing the password inside the Git repository, store it in an appropriate secrets-management system and provide access only to the required workload.

QUESTION 15

What is the Principle of Defense in Depth?

⭐⭐⭐⭐

Defense in Depth means using multiple independent security controls so that if one security layer fails, additional layers can still provide protection.

Identity Controls ↓ Network Controls ↓ Encryption ↓ Application Security ↓ Logging & Monitoring ↓ Incident Response
🎤 Interview Answer

"Defense in Depth means implementing multiple security layers instead of relying on a single control. If one layer fails, other controls can reduce the impact."

QUESTION 16

Why is logging important for cloud security?

⭐⭐⭐⭐

Security logs help organizations detect suspicious activity, investigate incidents, understand what happened and support auditing.

💡 Example

If an unexpected administrative action occurs, logs can help identify:

→ Who performed the action
→ What action occurred
→ When it occurred
→ Which resource was affected

⭐⭐⭐ Medium Priority

QUESTION 17

What is a Zero Trust security approach?

⭐⭐⭐

Zero Trust is a security approach based on the principle that access should not be automatically trusted simply because a user or system is inside a particular network. Access should be continuously evaluated based on identity, context, permissions and other security controls.

🧠 Easy Memory

"Never automatically trust. Verify access."
QUESTION 18

What is data masking?

⭐⭐⭐

Data masking hides or transforms sensitive information so that unauthorized users cannot see the original sensitive values.

Example

Production customer data may contain sensitive information. A testing environment can use masked or anonymized values instead of exposing the original production data.

QUESTION 19

Why should security patches be applied regularly?

⭐⭐⭐

Security patches fix known vulnerabilities and reduce the opportunity for attackers to exploit outdated software.

🎤 Interview Answer

"I would maintain a patching process for operating systems, applications and dependencies based on risk and organizational requirements. Critical vulnerabilities should be prioritized."

⭐⭐ Less Frequently Asked

QUESTION 20

What is a vulnerability?

⭐⭐

A vulnerability is a weakness in software, configuration, process or infrastructure that could potentially be exploited by an attacker.

QUESTION 21

What is a security incident?

⭐⭐

A security incident is an event that may compromise the confidentiality, integrity or availability of systems or data, or indicates a potential security violation.

🎯 Real-Time Interview Scenarios

SCENARIO 01

A developer asks for AdministratorAccess because their application is failing. What will you do?

⭐⭐⭐⭐⭐ DEVOPS FAVORITE

I would not immediately grant administrator access. First I would identify what operation is failing and determine the exact permission required. Then I would provide the minimum required permission.

Application Error ↓ Identify Failed Action ↓ Identify Required Permission ↓ Grant Minimum Permission ↓ Test ↓ Monitor
🎤 Strong Answer

"I would follow least privilege. Instead of granting AdministratorAccess, I would identify the exact API action or resource causing the failure and provide only the required permission. If the permission is temporary, I would also consider temporary access and review it afterward."

SCENARIO 02

An EC2 server is exposed to SSH from 0.0.0.0/0. Is this a good practice?

⭐⭐⭐⭐⭐

Generally, allowing SSH from the entire internet unnecessarily increases exposure. I would restrict administrative access to trusted sources or use a more appropriate secure access mechanism based on the architecture.

🎤 Answer

"No, I would avoid exposing SSH to 0.0.0.0/0 unless there is a specific justified requirement. I would restrict the source range or use a secure administrative access solution and follow least privilege."

SCENARIO 03

A GitHub repository contains an AWS access key. What will you do?

⭐⭐⭐⭐⭐ CRITICAL

I would treat the credential as compromised. I would immediately revoke or rotate the exposed credential, investigate its usage, identify the affected resources and replace the authentication mechanism with a safer approach.

Secret Exposed ↓ Revoke / Rotate ↓ Check Usage / Logs ↓ Assess Impact ↓ Replace Hard-coded Credential ↓ Use Secure Identity / Secret Management
🎤 Strong Answer

"I would treat the credential as compromised. I would immediately revoke or rotate it, investigate logs for suspicious usage, assess the impact and then remove the secret from the repository history where appropriate. For the future, I would use IAM roles or an appropriate secrets-management solution instead of hard-coded credentials."

SCENARIO 04

An application needs to access an S3 bucket. Would you give the application full AWS access?

⭐⭐⭐⭐⭐

No. The application should receive only the permissions required for its S3 operations.

💡 Example

If the application only needs to read objects from one bucket, the identity should not automatically receive permissions to delete objects from every S3 bucket.

SCENARIO 05

How would you secure a three-tier application in AWS?

⭐⭐⭐⭐⭐ DEVOPS FAVORITE

A common approach is to separate the web, application and database tiers and restrict communication between them.

Internet ↓ Load Balancer ↓ Web / Application Tier ↓ Application Tier ↓ Database Tier

IAM + Least Privilege * Security Groups * Encryption * Logging & Monitoring
🎤 Strong Answer

"I would separate the tiers and avoid exposing the database directly to the internet. I would use appropriate network controls between tiers, least-privilege IAM, encryption for sensitive data, secure secrets management and logging and monitoring for detection and auditing."
