⭐⭐⭐⭐⭐ Load Balancing

QUESTION 01

What is Load Balancing?

⭐⭐⭐⭐⭐ MUST KNOW

Load balancing distributes incoming application traffic across multiple healthy servers or resources.

Users ↓ Load Balancer ↓ Server 1    Server 2    Server 3
💡 Simple Example

Suppose an application receives thousands of requests. Instead of sending every request to one server, the load balancer distributes traffic across multiple application instances.

🎤 Interview Answer

"Load balancing distributes incoming traffic across multiple healthy resources. It improves availability, scalability and fault tolerance by preventing a single server from handling all the traffic."

QUESTION 02

Why do we need a Load Balancer?

⭐⭐⭐⭐⭐ VERY COMMON

A load balancer can help:

→ Distribute traffic
→ Improve availability
→ Support horizontal scaling
→ Detect unhealthy targets
→ Reduce dependency on a single server

🔥 Real-Time Example

If Server-1 becomes unhealthy, the load balancer can stop sending new requests to that unhealthy target and route traffic to healthy targets.

QUESTION 03

What is a Health Check?

⭐⭐⭐⭐⭐

A health check verifies whether a target is healthy enough to receive traffic.

Load Balancer ↓ Health Check ↓ Healthy → Receive Traffic Unhealthy → Do Not Receive New Traffic

⭐⭐⭐⭐⭐ Auto Scaling

QUESTION 04

What is Auto Scaling?

⭐⭐⭐⭐⭐ MUST KNOW

Auto Scaling automatically adjusts the number or capacity of resources according to workload requirements and configured policies.

Low Traffic
↓ Fewer Instances
↓ Traffic Increases
↓ More Instances
↓ Traffic Decreases
↓ Scale Down
🎤 Interview Answer

"Auto Scaling automatically adds or removes resources according to workload demand. It helps maintain application performance during traffic changes while avoiding unnecessary resource usage."

QUESTION 05

Scalability vs Auto Scaling?

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE
Scalability Auto Scaling
Ability to handle increased workload Mechanism that automatically adjusts resources
General architecture capability Automated resource adjustment
Can be manual or automatic Uses configured policies/rules
🎤 Interview Answer

"Scalability is the ability of a system to handle increased workload, while Auto Scaling is an automated mechanism that adds or removes resources according to defined conditions."

⭐⭐⭐⭐⭐ Multi-AZ & High Availability

QUESTION 06

What is Multi-AZ architecture?

⭐⭐⭐⭐⭐ MUST KNOW

Multi-AZ architecture deploys application resources across multiple Availability Zones within an AWS Region.

AWS Region ↓ AZ-A      AZ-B ↓ Application Instances
🔥 Why?

If one Availability Zone experiences a failure, healthy resources in another Availability Zone can continue serving traffic.

🎤 Interview Answer

"Multi-AZ architecture distributes workloads across multiple Availability Zones within a region. It improves availability and resilience because the application does not depend on a single Availability Zone."

QUESTION 07

How would you design a highly available application?

⭐⭐⭐⭐⭐ DEVOPS FAVORITE
Users ↓ Load Balancer ↓ AZ-A      AZ-B ↓ Application Instances ↓ Database

I would distribute application instances across multiple Availability Zones and use a load balancer to route traffic to healthy instances.

🎤 Strong Interview Answer

"I would design the application across multiple Availability Zones and place a load balancer in front of the application instances. I would use health checks and Auto Scaling where appropriate so that unhealthy or insufficient capacity can be handled automatically."

⭐⭐⭐⭐ Multi-Region

QUESTION 08

What is Multi-Region architecture?

⭐⭐⭐⭐

Multi-Region architecture deploys workloads across multiple geographic cloud regions.

Region A ↓ Application       Region B ↓ Application

It can be used for regional disaster recovery, geographic distribution, latency requirements or business continuity.

🎤 Interview Answer

"Multi-Region architecture deploys workloads across multiple geographic regions. It can provide additional resilience against regional failures and can also support geographic distribution and latency requirements."

QUESTION 09

Multi-AZ vs Multi-Region?

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE
Multi-AZ Multi-Region
Multiple AZs in one region Multiple geographic regions
High availability within region Protection against regional failure
Common architecture More complex architecture
Lower complexity Higher operational complexity
🎤 Interview Answer

"Multi-AZ is commonly used for high availability within a region, while Multi-Region can provide additional protection against regional failures and support geographic distribution. The choice depends on business and recovery requirements."

⭐⭐⭐⭐ DNS Fundamentals

QUESTION 10

What is DNS?

⭐⭐⭐⭐⭐ MUST KNOW

DNS stands for Domain Name System. It translates human-readable domain names into IP addresses or other DNS records that allow clients to locate services.

example.com ↓ DNS ↓ IP Address / Service Endpoint ↓ Application
💡 Example

Instead of remembering an IP address, users access an application using a domain name such as:

[www.example.com](http://www.example.com)

🎤 Interview Answer

"DNS is the Domain Name System. It translates domain names into IP addresses or service endpoints and helps clients locate applications and services."

QUESTION 11

What is a DNS record?

⭐⭐⭐⭐

A DNS record defines information used to resolve or route a domain name.

Record Purpose
A Maps a domain name to an IPv4 address
AAAA Maps a domain name to an IPv6 address
CNAME Maps a name to another domain name
MX Defines mail servers
TXT Stores text-based information

⭐⭐⭐⭐ CDN Fundamentals

QUESTION 12

What is a CDN?

⭐⭐⭐⭐⭐ VERY COMMON

CDN stands for Content Delivery Network. A CDN uses geographically distributed edge locations to deliver cached or optimized content closer to users.

Origin Server ↓ CDN Edge Locations ↓ Users
🔥 Real-Time Example

If users are located in different countries, a CDN can cache static content closer to those users, reducing latency and improving delivery performance.

🎤 Interview Answer

"A CDN is a distributed network of edge locations that delivers content closer to end users. It reduces latency and can improve application performance by caching and serving content from locations closer to users."

QUESTION 13

Why use a CDN?

⭐⭐⭐⭐

→ Reduce latency
→ Improve content delivery performance
→ Reduce load on origin servers
→ Improve global user experience
→ Handle high volumes of static content requests

⭐⭐⭐⭐⭐ Backup & Disaster Recovery

QUESTION 14

What is Backup?

⭐⭐⭐⭐⭐ MUST KNOW

A backup is a copy of data maintained so that the data can be restored after accidental deletion, corruption or other failures.

💡 Example

Database backup is created daily. If important data is accidentally deleted, the organization can restore it from an available backup.

QUESTION 15

What is Disaster Recovery?

⭐⭐⭐⭐⭐ MUST KNOW

Disaster Recovery, or DR, is the process and architecture used to restore applications and data after a major disruption.

Primary Environment ↓ Failure / Disaster ↓ DR Environment / Backup ↓ Restore ↓ Application Available
🎤 Interview Answer

"Disaster Recovery is the strategy and process for restoring applications and data after a major failure or disaster. It typically includes backups, recovery procedures and potentially a secondary environment."

QUESTION 16

RPO vs RTO?

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE
RPO RTO
Recovery Point Objective Recovery Time Objective
How much data loss is acceptable? How much downtime is acceptable?
Measured in time/data point Measured in recovery time
🔥 Example

RPO = 15 minutes
→ Business can tolerate losing up to around 15 minutes of data.

RTO = 1 hour
→ Application should be restored within approximately 1 hour.

🎤 Interview Answer

"RPO defines the maximum acceptable amount of data loss measured in time, while RTO defines the target time within which a system should be restored after a disruption."

⭐⭐⭐⭐ Cloud Architecture / Well-Architected

QUESTION 17

What is the AWS Well-Architected Framework?

⭐⭐⭐⭐

The AWS Well-Architected Framework provides principles and best practices for designing and evaluating cloud workloads.

The major pillars are:

→ Operational Excellence
→ Security
→ Reliability
→ Performance Efficiency
→ Cost Optimization
→ Sustainability

🎤 Interview Answer

"The AWS Well-Architected Framework provides best practices for designing secure, reliable, efficient and cost-effective cloud workloads. It is organized around six pillars: operational excellence, security, reliability, performance efficiency, cost optimization and sustainability."

QUESTION 18

Why is architecture important in Cloud?

⭐⭐⭐⭐

Cloud architecture determines how resources are organized to achieve availability, security, scalability, performance and cost objectives.

🎤 Interview Answer

"Good cloud architecture balances availability, scalability, security, performance and cost according to the application's business requirements."

⭐⭐⭐⭐⭐ Production Architecture

How would you design a highly available web application?

⭐⭐⭐⭐⭐ DEVOPS FAVORITE
Users ↓ DNS ↓ CDN / Edge ↓ Load Balancer ↓ ┌─────────────────┐
AZ-A       AZ-B
Application    Application
Instances     Instances
└─────────────────┘ ↓ Database ↓ Backup / DR

For a production application, I would avoid depending on a single server or Availability Zone.

I would use DNS for name resolution, a CDN when global content delivery is required, a load balancer for traffic distribution, multiple Availability Zones for resilience and Auto Scaling for variable workload.

🎤 Strong Interview Answer

"I would design the application using a multi-tier and multi-AZ architecture. DNS would route users to the application, a CDN could serve cacheable content, and a load balancer would distribute traffic across healthy application instances in multiple Availability Zones. Auto Scaling would adjust capacity based on demand. I would use an appropriate highly available database configuration and implement backups and disaster recovery according to the application's RPO and RTO requirements."

🎯 Real-Time Interview Scenarios

SCENARIO 01

Traffic suddenly increases 10 times. What would you do?

⭐⭐⭐⭐⭐

I would use horizontal scaling with a load balancer and Auto Scaling.

Traffic Increase ↓ Load Balancer ↓ Auto Scaling ↓ More Instances ↓ Traffic Distributed
🎤 Answer

"I would use a load-balanced architecture with Auto Scaling. When demand increases, additional instances can be launched and traffic can be distributed across healthy instances. When demand falls, capacity can scale down."

SCENARIO 02

One Availability Zone goes down. How can the application remain available?

⭐⭐⭐⭐⭐

Deploy the application across multiple Availability Zones and use a load balancer to route traffic to healthy resources.

🎤 Answer

"I would deploy application instances across multiple Availability Zones and use health checks with a load balancer. If one AZ becomes unavailable, traffic can continue through healthy resources in another AZ."

SCENARIO 03

Users from different countries complain about slow static content.

⭐⭐⭐⭐

I would evaluate using a CDN so that cacheable content can be served from edge locations closer to users.

🎤 Answer

"I would use a CDN for cacheable static content. The CDN can serve content from geographically distributed edge locations, reducing latency for users who are far from the origin."

SCENARIO 04

The business says the application must recover within 30 minutes and can tolerate only 5 minutes of data loss.

⭐⭐⭐⭐⭐ RTO/RPO

RTO = 30 minutes
RPO = 5 minutes

🎤 Answer

"The recovery requirements are an RTO of 30 minutes and an RPO of 5 minutes. I would design the backup and disaster recovery strategy to meet those objectives."

SCENARIO 05

Should every application use Multi-Region architecture?

⭐⭐⭐⭐⭐ TRICK QUESTION

No. Multi-Region architecture adds operational complexity and cost. It should be selected when business requirements justify it.

🎤 Strong Answer

"No. I would choose Multi-Region based on requirements such as regional disaster recovery, geographic distribution, latency or business continuity. For many applications, Multi-AZ provides sufficient high availability within a region."
