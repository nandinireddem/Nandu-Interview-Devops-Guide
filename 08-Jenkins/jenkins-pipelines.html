Jenkins Pipelines

Complete interview-focused guide covering Jenkins Pipeline, Jenkinsfile, Declarative and Scripted Pipelines, stages, steps, parameters, environment variables, conditions, post actions, parallel execution and real-time CI/CD examples.

⭐⭐⭐⭐⭐ Core Concept

A Jenkins Pipeline defines the complete CI/CD workflow as code. Instead of manually configuring every build step in the Jenkins UI, we define the workflow in a Jenkinsfile.

Git Push
↓
Jenkins
↓
Pipeline
↓
Checkout → Build → Test → Scan → Package
↓
Docker Build → Push
↓
Deploy
Real-time example: A Java application is pushed to GitHub. Jenkins starts the pipeline, checks out the code, runs Maven build and tests, performs a quality scan, builds a Docker image, pushes it to ECR and deploys the application to Kubernetes.

⭐⭐⭐⭐⭐ 1. What is a Jenkins Pipeline?

A Jenkins Pipeline is a collection of automated steps that define how software moves through stages such as build, test, security scan, packaging and deployment.
Interview answer: "Jenkins Pipeline is a way of defining the complete CI/CD workflow as code. It allows us to automate multiple stages such as checkout, build, test, Docker image creation and deployment."

⭐⭐⭐⭐⭐ 2. What is a Jenkinsfile?

A Jenkinsfile is a text file containing the Jenkins Pipeline definition. It is commonly stored in the application's Git repository.

Basic structure

pipeline {

    agent any

    stages {

        stage('Build') {
            steps {
                echo 'Building'
            }
        }

        stage('Test') {
            steps {
                echo 'Testing'
            }
        }

        stage('Deploy') {
            steps {
                echo 'Deploying'
            }
        }
    }
}
Why keep it in Git? It provides version control, code review, history and the ability to reproduce previous pipeline versions.

⭐⭐⭐⭐⭐ 3. Declarative vs Scripted Pipeline

Declarative Scripted
Structured and easier to read. More flexible and programmatic.
Uses pipeline {}. Uses Groovy scripting.
Preferred for most standard CI/CD pipelines. Useful for complex custom logic.
Has built-in pipeline structure. Provides greater programming flexibility.

Declarative example

pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                echo 'Build'
            }
        }
    }
}
Interview answer: "I generally prefer Declarative Pipeline because it provides a clear structure and is easier to maintain. Scripted Pipeline is useful when more advanced Groovy-based logic is required."

⭐⭐⭐⭐⭐ 4. What is an Agent?

The agent tells Jenkins where the pipeline or a stage should execute.

Any available agent

pipeline {
    agent any

    stages {
        stage('Build') {
            steps {
                echo 'Running build'
            }
        }
    }
}

Stage-specific agent

pipeline {

    agent none

    stages {

        stage('Build') {

            agent {
                label 'linux'
            }

            steps {
                sh 'mvn clean package'
            }
        }
    }
}

⭐⭐⭐⭐⭐ 5. Pipeline Stages

A stage represents a logical section of the CI/CD workflow. Typical stages include:
Checkout
↓
Build
↓
Test
↓
Security Scan
↓
Docker Build
↓
Push
↓
Deploy

Example

stages {

    stage('Build') {
        steps {
            sh 'mvn clean package'
        }
    }

    stage('Test') {
        steps {
            sh 'mvn test'
        }
    }

    stage('Deploy') {
        steps {
            sh './deploy.sh'
        }
    }
}

⭐⭐⭐⭐⭐ 6. What is a Step?

A step is an individual action executed inside a stage. 
stage('Build') {
    steps {
        echo 'Starting build'
        sh 'mvn clean package'
    }
}

Here echo and sh are steps.

⭐⭐⭐⭐⭐ 7. Common Jenkins Pipeline Steps

Step Purpose
echo Print a message.
sh Execute Linux shell commands.
bat Execute Windows batch commands.
checkout Checkout source code.
input Wait for manual approval/input.
archiveArtifacts Archive build artifacts.

⭐⭐⭐⭐⭐ 8. Environment Variables

Environment variables allow configuration values to be provided to the pipeline without hard-coding them repeatedly. 
pipeline {

    agent any

    environment {
        APP_NAME = 'payment-app'
        ENVIRONMENT = 'production'
    }

    stages {

        stage('Build') {
            steps {
                echo "Building ${APP_NAME}"
                echo "Environment: ${ENVIRONMENT}"
            }
        }
    }
}
Do not put passwords or API keys directly inside the environment block. Use Jenkins Credentials instead.

⭐⭐⭐⭐⭐ 9. Pipeline Parameters

Parameters allow users or automation to provide values when starting a pipeline. 
pipeline {

    agent any

    parameters {
        choice(
            name: 'ENV',
            choices: ['dev', 'qa', 'prod'],
            description: 'Select environment'
        )
    }

    stages {

        stage('Deploy') {
            steps {
                echo "Deploying to ${params.ENV}"
            }
        }
    }
}
Real-time use: The same deployment pipeline can be used for Dev, QA and Production by selecting the required environment.

⭐⭐⭐⭐⭐ 10. What is the when condition?

The when directive controls whether a stage should execute based on a condition. 
stage('Production Deploy') {

    when {
        branch 'main'
    }

    steps {
        echo 'Deploying production'
    }
}
For example, production deployment can be restricted to the main branch.

⭐⭐⭐⭐⭐ 11. What is post?

The post section defines actions that should happen after the pipeline or a stage completes. 
pipeline {

    agent any

    stages {

        stage('Build') {
            steps {
                echo 'Building'
            }
        }
    }

    post {

        success {
            echo 'Pipeline succeeded'
        }

        failure {
            echo 'Pipeline failed'
        }

        always {
            echo 'Pipeline completed'
        }
    }
}
Common uses include notifications, cleanup and publishing test reports.

⭐⭐⭐⭐ 12. Manual Approval using input

The input step pauses a pipeline and waits for human approval before continuing. 
stage('Production Approval') {

    steps {

        input message: 'Deploy to production?'

        echo 'Approved'
    }
}
Continuous Delivery example: Build → Test → Scan → Staging → Manual Approval → Production.

⭐⭐⭐⭐⭐ 13. Parallel Stages

Independent tasks can run in parallel to reduce total pipeline execution time. 
stage('Tests') {

    parallel {

        stage('Unit Tests') {
            steps {
                sh 'mvn test'
            }
        }

        stage('Security Scan') {
            steps {
                sh './security-scan.sh'
            }
        }
    }
}
If unit tests and security scans do not depend on each other, running them in parallel can reduce pipeline duration.

⭐⭐⭐⭐⭐ 14. Complete Real-Time Jenkins Pipeline

pipeline {

    agent any

    environment {
        APP_NAME = 'payment-app'
        IMAGE = 'payment-app:v1'
    }

    stages {

        stage('Checkout') {
            steps {
                checkout scm
            }
        }

        stage('Build') {
            steps {
                sh 'mvn clean package'
            }
        }

        stage('Test') {
            steps {
                sh 'mvn test'
            }
        }

        stage('Security Scan') {
            steps {
                sh 'trivy fs .'
            }
        }

        stage('Docker Build') {
            steps {
                sh 'docker build -t $IMAGE .'
            }
        }

        stage('Push Image') {
            steps {
                sh 'docker push $IMAGE'
            }
        }

        stage('Deploy') {
            steps {
                sh 'kubectl apply -f k8s/'
            }
        }
    }

    post {

        success {
            echo 'Deployment successful'
        }

        failure {
            echo 'Pipeline failed'
        }

        always {
            echo 'Pipeline completed'
        }
    }
}
This is an interview-oriented example. In production, registry authentication, cloud credentials and Kubernetes access should be handled securely through Jenkins Credentials or appropriate identity mechanisms rather than hard-coded secrets.

⭐⭐⭐⭐⭐ 15. How does Jenkins Pipeline handle failure?

Normally, when a step fails, the current stage fails and the pipeline can stop unless the pipeline explicitly handles the failure. The post section can still run cleanup or notification logic. 
post {

    success {
        echo 'Success'
    }

    failure {
        echo 'Failure notification'
    }

    always {
        echo 'Cleanup'
    }
}

⭐⭐⭐⭐ 16. How do you skip a stage for certain branches?

stage('Deploy') {

    when {
        branch 'main'
    }

    steps {
        sh './deploy.sh'
    }
}

This prevents the deployment stage from executing for branches that do not satisfy the condition.

⭐⭐⭐⭐⭐ 17. How do you pass artifacts between stages?

Files created during one stage can remain in the workspace for subsequent stages when those stages run in the same suitable workspace. For more explicit artifact management, Jenkins provides artifact archiving and other mechanisms depending on the pipeline design. 
stage('Build') {
    steps {
        sh 'mvn package'
        archiveArtifacts artifacts: 'target/*.jar'
    }
}

⭐⭐⭐⭐⭐ 18. Jenkins Pipeline Troubleshooting

Pipeline failed: Do not immediately rerun it repeatedly.

1. Open Console Output.
2. Identify failed stage.
3. Find the exact command that failed.
4. Check agent availability.
5. Verify workspace files.
6. Check credentials.
7. Check external services.
8. Reproduce the command manually where appropriate.
9. Fix the root cause.
10. Run the pipeline again.

⭐⭐⭐⭐⭐ 20. Pipeline Best Practices

  • Keep Jenkinsfiles in Git.
  • Use meaningful stage names.
  • Keep pipelines modular and readable.
  • Do not hard-code credentials.
  • Use environment variables for non-sensitive configuration.
  • Use Jenkins Credentials for secrets.
  • Fail fast when critical stages fail.
  • Use parallel stages when tasks are independent.
  • Use manual approval for controlled production releases where required.
  • Keep deployment logic reproducible.
  • Use dedicated agents for specialized workloads.

🎯 If Interviewer Says: "Explain Jenkins Pipeline"

"A Jenkins Pipeline is an automated CI/CD workflow defined as code, usually inside a Jenkinsfile. I normally structure it into stages such as checkout, build, test, security scanning, Docker image creation, image push and deployment. The pipeline runs on Jenkins agents. I use environment variables for normal configuration and Jenkins Credentials for sensitive information. Using Declarative Pipeline, I can define conditions with when, post-build actions with post, manual production approval with input and parallel execution for independent tasks. Keeping the Jenkinsfile in Git gives us version control, reviewability and reproducibility."
