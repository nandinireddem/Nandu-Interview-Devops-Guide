Jenkins Basics

Interview-focused guide covering Jenkins architecture, Controller and Agents, Jobs, Builds, Plugins, Workspace, CI/CD workflow and real-time DevOps usage.

⭐⭐⭐⭐⭐ Core Concept

Jenkins is an open-source automation server mainly used to implement Continuous Integration and Continuous Delivery / Deployment pipelines.

Developer
↓
Git Repository
↓
Webhook
↓
Jenkins
↓
Build → Test → Scan → Package
↓
Docker Image / Artifact
↓
Deployment
Real-time example: A developer pushes code to GitHub. A webhook triggers Jenkins. Jenkins checks out the code, builds the application, runs tests, creates a Docker image and pushes it to a container registry. The pipeline can then deploy the application to Kubernetes or AWS.

⭐⭐⭐⭐⭐ 1. What is Jenkins?

Jenkins is an open-source automation server used to automate software build, test, integration and deployment activities. It is widely used in DevOps to create CI/CD pipelines.

Interview Answer

"Jenkins is an open-source automation server that helps automate CI/CD processes. We can integrate Jenkins with Git, Docker, cloud platforms, Kubernetes and many testing or security tools to automate the software delivery lifecycle."

⭐⭐⭐⭐⭐ 2. Why do we use Jenkins?

  • Automate application builds.
  • Run automated tests.
  • Integrate with Git repositories.
  • Build CI/CD pipelines.
  • Create Docker images.
  • Push artifacts to repositories.
  • Deploy applications automatically.
  • Integrate security and code-quality tools.
Without Jenkins: Developer manually builds, tests and deploys the application.

With Jenkins: A Git push can automatically trigger the complete workflow.

⭐⭐⭐⭐⭐ 3. Jenkins Architecture

Modern Jenkins commonly follows a controller-agent architecture. Controller: manages Jenkins configuration, jobs/pipelines and coordinates execution. Agent: provides the environment where build or pipeline steps execute.
Jenkins Controller
↓
Pipeline / Job Scheduling
↓
Agent 1 → Build
Agent 2 → Test
Agent 3 → Docker
↓
Artifacts / Deployment

⭐⭐⭐⭐⭐ 4. Controller vs Agent

Controller Agent
Manages Jenkins configuration. Executes assigned build or pipeline work.
Schedules jobs. Runs commands and tools.
Stores Jenkins configuration. Provides execution environment.
Can manage multiple agents. Can be labeled for specific workloads.
Interview tip: Do not say the controller must execute every build. A production Jenkins setup can use dedicated agents so workloads are distributed and the controller is not overloaded.

⭐⭐⭐⭐⭐ 5. What is a Jenkins Job?

A Jenkins Job is a configured task that Jenkins can execute. Depending on the setup, it can represent a build, test, pipeline or another automated process.

Common examples

  • Freestyle project
  • Pipeline
  • Multibranch Pipeline
  • Organization Folder
Example: Payment-Service-CI can be configured to checkout code, run tests, build a Docker image and publish the image.

⭐⭐⭐⭐⭐ 6. What is a Build?

A build is an execution of a Jenkins job or pipeline. Every execution can produce a build result such as SUCCESS, FAILURE, ABORTED or UNSTABLE, depending on the job and configuration.

Example

Build #101 → SUCCESS
Build #102 → SUCCESS
Build #103 → FAILURE
Build #104 → SUCCESS
When a build fails, I first inspect the console logs and identify which stage or command failed before changing the pipeline.

⭐⭐⭐⭐⭐ 7. What is a Jenkins Plugin?

A Jenkins plugin extends Jenkins functionality and allows Jenkins to integrate with external tools and platforms.

Examples

  • Git integration
  • Pipeline functionality
  • Credentials management
  • Docker integration
  • Kubernetes integration
  • Notifications
Do not install unnecessary plugins. A production Jenkins installation should keep plugins controlled, compatible and regularly maintained.

⭐⭐⭐⭐⭐ 8. What is Jenkins Workspace?

A workspace is the directory where Jenkins performs operations such as source-code checkout, compilation, testing and artifact generation for a build.

Useful troubleshooting command

Inside a Jenkins pipeline, shell commands execute in the workspace unless another directory is specified.

⭐⭐⭐⭐⭐ 10. Freestyle Job vs Pipeline

Freestyle Pipeline
Configured mainly through Jenkins UI. Pipeline can be defined as code.
Suitable for simple jobs. Better for complex CI/CD workflows.
Harder to version configuration. Jenkinsfile can be stored in Git.
Less suitable for complex stages. Supports stages, conditions and reusable logic.
Interview answer: "For modern CI/CD, I prefer Pipeline as Code using a Jenkinsfile because the pipeline definition can be version-controlled along with the application source code."

⭐⭐⭐⭐⭐ 11. What is Pipeline as Code?

Pipeline as Code means defining the CI/CD workflow in a file, commonly called a Jenkinsfile, instead of relying only on Jenkins UI configuration.

Basic example

pipeline {

    agent any

    stages {

        stage('Build') {
            steps {
                echo 'Building application'
            }
        }

        stage('Test') {
            steps {
                echo 'Running tests'
            }
        }

        stage('Deploy') {
            steps {
                echo 'Deploying application'
            }
        }
    }
}

⭐⭐⭐⭐ 12. What is Continuous Integration?

Continuous Integration means developers frequently integrate code changes into a shared repository and automated processes build and test those changes.
Developer pushes code.
↓ Jenkins starts automatically.
↓ Code is compiled and tested.
↓ Failure is reported quickly.

The main goal is to detect integration problems early.

⭐⭐⭐⭐ 13. Continuous Delivery vs Continuous Deployment

Continuous Delivery Continuous Deployment
Software is kept ready for release. Successful changes are automatically released.
May require manual production approval. Production deployment can happen automatically.
Example: Delivery: Jenkins builds and tests the application, then waits for production approval.

Deployment: Jenkins automatically deploys the successful build to production.

⭐⭐⭐⭐⭐ 14. How does Jenkins trigger a pipeline?

A Jenkins job can be triggered through several mechanisms, depending on configuration.
  • GitHub/GitLab webhook
  • Manual trigger
  • Scheduled trigger
  • SCM polling
  • Another Jenkins job
  • API or automation
Preferred modern approach: Git push → Webhook → Jenkins pipeline. This avoids Jenkins repeatedly polling the repository just to discover changes.

⭐⭐⭐⭐⭐ 15. How do you troubleshoot a failed Jenkins build?

I follow a systematic approach rather than randomly changing the pipeline.
Build Failed
↓
Open Console Output
↓
Identify Failed Stage
↓
Check Exact Error
↓
Verify Agent / Workspace
↓
Check Credentials / Permissions
↓
Check Tool / Dependency
↓
Fix → Re-run

Useful areas to inspect

  • Console output
  • Pipeline stage logs
  • Agent availability
  • Workspace files
  • Credentials
  • Docker / Kubernetes connectivity
  • Disk space
  • Network access

⭐⭐⭐⭐⭐ 16. Real-Time Scenario: Agent Offline

Problem: Jenkins pipeline is waiting because the required agent is offline.

Approach: 1. Check the agent status.
2. Check connectivity.
3. Verify agent process/service.
4. Check resource availability.
5. Verify labels match the pipeline requirement.
6. Reconnect or replace the agent if required.
I would not immediately restart the entire Jenkins controller. First I identify whether the issue is isolated to the agent.

⭐⭐⭐⭐⭐ 17. Real-Time Scenario: Build is very slow

Possible causes:
  • Insufficient CPU or memory.
  • Slow dependency downloads.
  • Large Docker builds.
  • Too many builds on one agent.
  • Disk or workspace problems.
  • Unnecessary stages.
  • Network latency.
Solution: Use appropriate agents, parallelize independent stages, cache dependencies where suitable and optimize Docker/build processes.

⭐⭐⭐⭐⭐ 18. Jenkins Production Best Practices

  • Use Pipeline as Code.
  • Store Jenkinsfiles in Git.
  • Use dedicated agents for workloads.
  • Use credentials management instead of hard-coded secrets.
  • Apply least-privilege access.
  • Keep plugins maintained and controlled.
  • Monitor Jenkins disk, CPU and memory.
  • Back up important Jenkins configuration and data.
  • Use webhooks for event-driven CI where appropriate.
  • Keep production pipelines reproducible.

🎯 If Interviewer Says: "Explain Jenkins"

"Jenkins is an open-source automation server widely used for CI/CD. In a typical DevOps workflow, a developer pushes code to GitHub and a webhook triggers Jenkins. Jenkins checks out the source code and executes a pipeline on an appropriate agent. The pipeline can build the application, run tests and security scans, create a Docker image and push it to a container registry. The image can then be deployed to platforms such as Kubernetes or AWS. For production, I prefer Pipeline as Code using Jenkinsfiles, dedicated agents, secure credential management, controlled plugins and proper monitoring and backups."
