⭐⭐⭐⭐⭐ 2. Prometheus — Must Know

  • Prometheus is an open-source monitoring and alerting system.
  • It primarily collects time-series metrics.
  • Prometheus usually uses a pull-based scraping model.
  • Targets expose metrics through an HTTP endpoint.
  • Prometheus stores metrics in its time-series database.
  • PromQL is used to query metrics.
  • Alert rules can be evaluated by Prometheus.
  • Alertmanager handles alert routing and notifications.

Important Components

Component Purpose
Prometheus Server Scrapes and stores metrics.
Service Discovery Finds monitoring targets.
Exporters Expose metrics for systems that do not natively expose Prometheus metrics.
PromQL Queries and analyzes metrics.
Alert Rules Define conditions for alerts.
Alertmanager Routes and manages alerts.

⭐⭐⭐⭐⭐ 4. PromQL Quick Revision

Basic Metric Query

up

Returns the status of monitored targets.

CPU Example

rate(node_cpu_seconds_total[5m])

Memory Example

node_memory_MemAvailable_bytes

HTTP Error Example

rate(http_requests_total{status=~"5.."}[5m])
Interview Point: PromQL allows filtering, aggregation and calculation over time-series metrics.

⭐⭐⭐⭐⭐ 5. Grafana — Must Know

  • Grafana is a visualization and observability platform.
  • It connects to data sources such as Prometheus.
  • Queries retrieve data from the configured data source.
  • Panels visualize the query results.
  • Multiple panels can be organized into dashboards.
  • Grafana can also participate in alerting.

⭐⭐⭐⭐⭐ 6. Common Grafana Questions

What is a Dashboard?

A dashboard is a collection of visualization panels that present monitoring information in one place.

What is a Data Source?

A data source is the backend from which Grafana retrieves data. Prometheus is a common monitoring data source.

Why use Grafana with Prometheus?

Prometheus is excellent at collecting and querying metrics, while Grafana provides a powerful visual interface for analyzing those metrics through dashboards.

⭐⭐⭐⭐⭐ 8. Four Golden Signals

Signal Meaning
Latency How long requests take.
Traffic How much demand the system receives.
Errors How many requests are failing.
Saturation How close the system is to its resource limits.

⭐⭐⭐⭐⭐ 9. Metrics vs Logs vs Traces

Observability Signal Main Purpose
Metrics Numerical measurements and trends.
Logs Detailed events and messages.
Traces Track a request across distributed services.
Metrics → What is wrong?

Logs → What happened?

Traces → Where did the request go / slow / fail?

⭐⭐⭐⭐⭐ 10. Top Troubleshooting Scenarios

CPU is 95%

Check the affected instance, process usage, traffic, deployments, memory and scaling requirements.

Pod keeps restarting

Check kubectl describe pod, logs, events, probes, configuration and OOMKilled status.

Prometheus target is DOWN

Check target connectivity, exporter, metrics endpoint, port, service discovery and Prometheus configuration.

Grafana shows No Data

Check data source, Prometheus availability, PromQL query, time range, dashboard variables and target status.

5xx errors increase

Check application logs, recent deployments, dependencies, infrastructure metrics and database health.

Disk reaches 90%

df -h
du -sh /var/log/*

🎯 14. Interview-Ready Answer: Monitoring in DevOps

"In a DevOps environment, monitoring helps us understand the health and performance of applications and infrastructure. We can use Prometheus to collect and query metrics and Grafana to visualize those metrics through dashboards. Alerting can notify engineers when defined thresholds or conditions are reached. During incidents, I correlate metrics with logs and other available observability data, identify the root cause, mitigate the impact and then implement a permanent fix."
