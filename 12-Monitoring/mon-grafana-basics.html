Grafana Basics

Interview-focused guide to Grafana, dashboards, data sources, panels, Prometheus integration, variables and monitoring scenarios.

⭐⭐⭐⭐⭐ 1. What is Grafana?

Interview Answer:
Grafana is an open-source observability and visualization platform used to query, visualize and monitor data from different data sources through dashboards.

Grafana itself is commonly used as the visualization layer while Prometheus provides the metrics.

⭐⭐⭐⭐⭐ 2. Why do we use Grafana?

  • Create monitoring dashboards.
  • Visualize metrics and trends.
  • Connect to multiple data sources.
  • Create panels for CPU, memory and application metrics.
  • Use variables for dynamic dashboards.
  • Support alerting workflows depending on configuration.
  • Help DevOps teams troubleshoot production systems.

⭐⭐⭐⭐⭐ 4. What is a Data Source?

A data source is a backend system from which Grafana retrieves data for queries and visualizations.

⭐⭐⭐⭐⭐ 6. What is a Dashboard?

A Grafana dashboard is a collection of visualizations that presents monitoring information in one place.

A production dashboard can contain CPU usage, memory usage, request rate, error rate, latency and infrastructure health.

⭐⭐⭐⭐⭐ 7. What is a Panel?

A panel is an individual visualization inside a Grafana dashboard.

Panel Example
Time Series CPU usage over time.
Stat Current memory usage.
Gauge CPU utilization percentage.
Table Application status by service.
Bar Chart Requests by service.

⭐⭐⭐⭐⭐ 8. What is a Time Series Panel?

A Time Series panel displays metric values across time.

Time
→
Metric Values
→

For example, CPU utilization can be plotted over the last hour.

⭐⭐⭐⭐⭐ 9. What is PromQL in Grafana?

When Prometheus is configured as the data source, Grafana panels can use PromQL queries to retrieve metrics. 

up

rate(http_requests_total[5m])

⭐⭐⭐⭐⭐ 11. What are Variables?

Grafana variables allow users to dynamically change dashboard filters without creating separate dashboards for every environment, service or instance.

Examples:

  • Environment → dev / staging / production
  • Service → frontend / backend / payment
  • Instance → server-01 / server-02
  • Namespace → dev / production

⭐⭐⭐⭐⭐ 12. Why are Variables useful?

Instead of creating multiple dashboards, one dashboard can be reused with different variable values.

↓

⭐⭐⭐⭐⭐ 13. What is a Query?

A query retrieves data from the configured data source.

For Prometheus, Grafana sends a PromQL query to Prometheus. 

rate(http_requests_total[5m])
The result of the query is then displayed using a Grafana panel.

⭐⭐⭐⭐⭐ 17. Real-Time Scenario: Production CPU Spike

Scenario

The production CPU usage suddenly reaches 95%.

Step 1: Open the Grafana dashboard.

Step 2: Identify which node, Pod or service is consuming CPU.

Step 3: Use PromQL to inspect the metric.

Step 4: Check memory, traffic, errors and latency.

Step 5: Check recent deployments and application logs.

Step 6: Determine whether scaling or rollback is required.

⭐⭐⭐⭐ 20. Common Grafana Problems

Problem Possible Cause
No data Wrong data source or query.
Prometheus unreachable Network or URL configuration issue.
Panel error Invalid query or unsupported data.
Missing metrics Prometheus scrape or exporter problem.
Wrong dashboard values Incorrect filters, labels or query.

⭐⭐⭐⭐⭐ 21. Troubleshooting "No Data"

  1. Check Grafana data source.
  2. Click the data source connection test.
  3. Verify the Prometheus URL.
  4. Open Prometheus directly.
  5. Run the same PromQL query in Prometheus.
  6. Check whether the target is up.
  7. Check the selected time range.
  8. Verify dashboard variables and filters.

⭐⭐⭐⭐⭐ 23. Interview Answer: Explain Grafana

"Grafana is an open-source visualization and observability platform. In a typical DevOps environment, I can configure Prometheus as a Grafana data source, use PromQL queries to retrieve metrics and display those metrics using dashboards and panels. For Kubernetes monitoring, Grafana can provide dashboards for CPU, memory, Pod restarts, request rate, latency and other application metrics."
