⭐⭐⭐⭐⭐ 2. Main Components

Component Purpose
Prometheus Server Scrapes targets, evaluates rules and stores metrics.
TSDB Stores time-series metric data.
Service Discovery Discovers monitoring targets dynamically.
Exporters Expose metrics from systems that do not natively expose Prometheus metrics.
PromQL Queries and analyzes stored metrics.
Alerting Rules Evaluate conditions and generate alerts.
Alertmanager Groups, routes and manages alerts.
Grafana Provides dashboards and visualizations.
Pushgateway Provides a way for certain short-lived jobs to expose metrics to Prometheus.

⭐⭐⭐⭐⭐ 3. Prometheus Server

The Prometheus Server is the central component responsible for discovering targets, scraping metrics, storing time-series data, evaluating recording/alerting rules and serving PromQL queries.

↓

↓

⭐⭐⭐⭐⭐ 4. What is TSDB?

TSDB stands for Time Series Database. Prometheus stores collected metric samples as time-series data.

A time series is identified by a metric name and its set of labels, with values recorded over time. 

node_cpu_seconds_total{
    mode="idle",
    instance="server-01"
}
Interview Point:
Prometheus's local storage is optimized for time-series metrics.

⭐⭐⭐⭐⭐ 7. What is Service Discovery?

Service discovery allows Prometheus to dynamically discover targets that should be monitored.

This is particularly important in cloud-native environments because instances, containers and Pods can be created and removed dynamically.

↓

⭐⭐⭐⭐⭐ 8. Static vs Dynamic Target Discovery

Static Configuration Service Discovery
Targets are manually specified. Targets are discovered automatically.
Simple environments. Dynamic environments.
Less flexible. Better for Kubernetes and cloud environments.

⭐⭐⭐⭐⭐ 11. Prometheus Configuration

Prometheus commonly uses prometheus.yml to define global settings and scrape configurations. 

global:
  scrape_interval: 15s

scrape_configs:

  - job_name: "node-exporter"

    static_configs:
      - targets:
          - "localhost:9100"

⭐⭐⭐⭐⭐ 12. What is a Job?

A Prometheus scrape configuration uses a job_name to logically group targets that perform the same monitoring role. 

scrape_configs:

  - job_name: "web-servers"

    static_configs:
      - targets:
          - "server1:9100"
          - "server2:9100"

⭐⭐⭐⭐⭐ 13. Labels in Architecture

Labels identify and differentiate time series. 

http_requests_total{
    job="frontend",
    instance="10.0.1.10:8080",
    status="200"
}
Why labels matter:
They allow engineers to filter, group and aggregate metrics using PromQL.

⭐⭐⭐⭐⭐ 14. PromQL

PromQL is the query language used to retrieve and analyze metrics stored by Prometheus. 

up

up{job="node-exporter"}

rate(http_requests_total[5m])

sum(rate(http_requests_total[5m]))

⭐⭐⭐⭐⭐ 16. Prometheus vs Alertmanager

Prometheus Alertmanager
Evaluates alerting rules. Receives alerts.
Determines when an alert condition is true. Groups and routes alerts.
Generates alert events. Handles notifications, silences and inhibition.

⭐⭐⭐⭐⭐ 17. What is Alertmanager?

Alertmanager handles alerts sent by Prometheus. It can group related alerts, route them to receivers, silence alerts and apply inhibition rules to reduce unnecessary notifications.

⭐⭐⭐⭐ 18. What is Pushgateway?

Pushgateway is useful when certain short-lived or batch jobs cannot be reliably scraped directly.

↓

Important:
Pushgateway should not be treated as a general replacement for Prometheus's normal pull model.

⭐⭐⭐⭐⭐ 21. What if Prometheus cannot scrape a target?

  1. Check target status in Prometheus.
  2. Check whether the target endpoint is reachable.
  3. Verify the metrics port.
  4. Verify the /metrics endpoint.
  5. Check firewall and network rules.
  6. Check exporter status.
  7. Check Prometheus configuration.
  8. Check service discovery labels.

⭐⭐⭐⭐⭐ 23. Production Monitoring Example

Scenario:

A production Kubernetes application is experiencing increased latency.

Approach:
  1. Check Grafana latency dashboard.
  2. Use PromQL to identify affected Pods.
  3. Check request rate and error rate.
  4. Check CPU and memory usage.
  5. Check recent deployments.
  6. Check application logs.
  7. Check Kubernetes events.
  8. Identify and resolve the root cause.

⭐⭐⭐⭐⭐ 24. Prometheus Data Flow — Interview Answer

"Prometheus discovers monitoring targets through static configuration or service discovery. It periodically scrapes metrics from those targets, parses the metric data and stores the samples in its time-series database. Engineers query the data using PromQL. Alerting rules can generate alerts, which are handled by Alertmanager. Grafana can use Prometheus as a data source to visualize the metrics."
