Prometheus Basics

Interview-focused guide to Prometheus, metrics, targets, scraping, labels, exporters, PromQL and monitoring fundamentals.

⭐⭐⭐⭐⭐ 1. What is Prometheus?

Interview Answer:
Prometheus is an open-source monitoring and alerting system designed primarily for collecting and storing time-series metrics. It uses a pull-based model where Prometheus periodically scrapes metrics from configured targets.
Application / Server
↓
Metrics Endpoint
↓
Prometheus
↓
Time-Series Database
↓
PromQL
↓
Dashboard / Alert

⭐⭐⭐⭐⭐ 2. Why is Prometheus used?

  • Infrastructure monitoring.
  • Application monitoring.
  • Kubernetes monitoring.
  • CPU and memory monitoring.
  • Request and error monitoring.
  • Alerting based on metrics.
  • Performance troubleshooting.
Example:
If a Kubernetes application's CPU usage continuously increases, Prometheus can collect the CPU metrics and an alert rule can notify the DevOps team.

⭐⭐⭐⭐⭐ 3. What is a Metric?

A metric is a numerical measurement representing the state or behavior of a system at a particular point in time.

Metric Example Meaning
CPU usage Processor utilization.
Memory usage Memory consumed by a process or system.
HTTP requests Number of requests received.
HTTP errors Number of failed requests.
Network traffic Amount of network data transferred.

⭐⭐⭐⭐⭐ 4. What is Time-Series Data?

Prometheus stores metrics as time-series data. A time series consists of a metric name, labels and timestamped values. 

http_requests_total{
    method="GET",
    status="200"
}
The same metric can contain different time series based on its labels.

⭐⭐⭐⭐⭐ 5. What is Scraping?

Scraping means Prometheus periodically sends an HTTP request to a target's metrics endpoint and collects the exposed metrics.
Prometheus
↓
HTTP GET
↓
Target: /metrics
↓
Metrics Returned
↓
Prometheus Stores Metrics

⭐⭐⭐⭐⭐ 6. Pull Model vs Push Model

Pull Model Push Model
Monitoring system pulls metrics. Applications push metrics.
Prometheus primarily uses pull. Pushgateway can be used for certain short-lived jobs.
Prometheus controls scraping. Application controls sending.
Interview Tip:
Prometheus primarily follows a pull-based architecture.

⭐⭐⭐⭐⭐ 7. What is a Target?

A target is an endpoint that Prometheus monitors and scrapes for metrics.

Examples:

  • Linux server.
  • Application server.
  • Kubernetes node.
  • Database exporter.
  • Web server exporter.

⭐⭐⭐⭐⭐ 8. What is an Exporter?

An exporter is a component that exposes metrics from a system or application in a format that Prometheus can scrape.
Exporter Purpose
Node Exporter Linux/Unix system metrics.
Blackbox Exporter Probe endpoints and network services.
MySQL Exporter MySQL database metrics.
Redis Exporter Redis metrics.
Linux Server
↓
Node Exporter
↓
/metrics
↓
Prometheus

⭐⭐⭐⭐⭐ 9. What is Node Exporter?

Node Exporter exposes hardware and operating-system metrics from Unix-like systems so Prometheus can collect them.

Examples include:

  • CPU statistics.
  • Memory statistics.
  • Disk usage.
  • Filesystem statistics.
  • Network statistics.

⭐⭐⭐⭐⭐ 10. What are Labels?

Labels are key-value pairs attached to metrics that provide additional dimensions for filtering and grouping. 

http_requests_total{
    method="GET",
    status="200",
    service="frontend"
}

Here method, status and service are labels.

⭐⭐⭐⭐⭐ 11. Prometheus Metric Types

Type Purpose
Counter Monotonically increasing value, such as total requests.
Gauge Value that can increase or decrease, such as memory usage.
Histogram Measures observations and groups them into buckets.
Summary Calculates quantiles over observations.

⭐⭐⭐⭐⭐ 12. Counter vs Gauge

Counter Gauge
Normally only increases. Can increase or decrease.
Example: total HTTP requests. Example: current memory usage.
Can reset when application restarts. Represents current state.

⭐⭐⭐⭐⭐ 13. What is PromQL?

PromQL, or Prometheus Query Language, is used to select, filter, aggregate and analyze time-series data stored in Prometheus.

Example

up

Returns the health status of monitored targets.

Example with label filtering

up{job="node-exporter"}

⭐⭐⭐⭐⭐ 14. Common PromQL Examples

up

rate(http_requests_total[5m])

sum(rate(http_requests_total[5m]))

node_memory_MemAvailable_bytes

node_cpu_seconds_total
Interview Tip:
Know the concepts behind rate(), label filtering, aggregation and time ranges.

⭐⭐⭐⭐ 15. What is the up Metric?

The up metric indicates whether Prometheus was able to successfully scrape a target.

Value Meaning
1 Target scrape succeeded.
0 Target scrape failed.

⭐⭐⭐⭐⭐ 16. Prometheus Configuration

Prometheus configuration is commonly stored in prometheus.yml. 

global:
  scrape_interval: 15s

scrape_configs:

  - job_name: "node-exporter"

    static_configs:
      - targets:
          - "localhost:9100"

The configuration defines how frequently Prometheus scrapes targets and which targets should be monitored.

⭐⭐⭐⭐⭐ 17. What is scrape_interval?

scrape_interval specifies how frequently Prometheus collects metrics from targets. 

scrape_interval: 15s

This means Prometheus attempts to scrape configured targets every 15 seconds unless overridden by a more specific configuration.

⭐⭐⭐⭐ 18. What is Service Discovery?

Service discovery allows Prometheus to automatically discover monitoring targets instead of manually configuring every target.

This is especially useful in dynamic environments such as Kubernetes, where Pods and Services can change frequently.

⭐⭐⭐⭐⭐ 20. Prometheus vs Grafana

Prometheus Grafana
Collects and stores metrics. Visualizes metrics.
Provides PromQL. Provides dashboards and panels.
Can evaluate alert rules. Can visualize and alert depending on configuration.
Simple Interview Answer:
Prometheus is primarily the metrics collection and time-series monitoring system, while Grafana is primarily the visualization and dashboarding platform.

⭐⭐⭐⭐⭐ 22. Troubleshooting: Metric Not Available

  1. Check whether Prometheus is running.
  2. Check the target status.
  3. Verify the metrics endpoint.
  4. Check up.
  5. Check Prometheus configuration.
  6. Check network connectivity.
  7. Check exporter logs.
  8. Verify the metric name and labels.
up

⭐⭐⭐⭐⭐ 23. Interview Scenario

Scenario:

Your application CPU usage suddenly reaches 95%. What would you do?

Answer:

First, I would use Prometheus metrics to confirm the CPU spike and identify the affected instance or Pod using labels. Then I would check application traffic, recent deployments, resource limits and application logs. If the issue is caused by increased traffic, I would verify whether scaling is working correctly. If it is caused by a faulty deployment, I would investigate the recent change and roll back if required.
