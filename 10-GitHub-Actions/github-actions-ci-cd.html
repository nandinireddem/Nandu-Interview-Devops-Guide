⭐⭐⭐⭐⭐ 2. Basic CI Pipeline

name: CI

on:
  push:
    branches:
      - main

  pull_request:
    branches:
      - main

jobs:

  build-test:

    runs-on: ubuntu-latest

    steps:

      - name: Checkout Code
        uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install Dependencies
        run: npm ci

      - name: Run Tests
        run: npm test

      - name: Build
        run: npm run build
This pipeline validates code whenever changes are pushed or a pull request is created.

⭐⭐⭐⭐⭐ 3. CI Pipeline with Docker

name: Docker CI

on:
  push:
    branches:
      - main

jobs:

  docker-build:

    runs-on: ubuntu-latest

    steps:

      - name: Checkout
        uses: actions/checkout@v4

      - name: Build Docker Image
        run: |
          docker build \
            -t myapp:${{ github.sha }} .

      - name: List Docker Images
        run: docker images
Using github.sha gives the image a unique identifier associated with the commit that produced it.

⭐⭐⭐⭐⭐ 5. Push Docker Image to Docker Hub

- name: Login to Docker Hub
  uses: docker/login-action@v3
  with:
    username: ${{ secrets.DOCKER_USERNAME }}
    password: ${{ secrets.DOCKER_PASSWORD }}

- name: Build Image
  run: docker build -t myuser/myapp:${{ github.sha }} .

- name: Push Image
  run: docker push myuser/myapp:${{ github.sha }}
Docker Hub credentials should be stored in GitHub Secrets and never hard-coded in the workflow.

⭐⭐⭐⭐⭐ 7. ECR Login Example

- name: Configure AWS Credentials
  uses: aws-actions/configure-aws-credentials@v4
  with:
    role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
    aws-region: ap-south-1

- name: Login to Amazon ECR
  id: login-ecr
  uses: aws-actions/amazon-ecr-login@v2
For production, prefer short-lived credentials through GitHub OIDC and an AWS IAM role rather than storing long-lived AWS access keys.

⭐⭐⭐⭐⭐ 8. Complete Docker + ECR Pipeline

name: Build and Push

on:
  push:
    branches:
      - main

env:
  AWS_REGION: ap-south-1
  ECR_REPOSITORY: myapp

jobs:

  build-push:

    runs-on: ubuntu-latest

    permissions:
      id-token: write
      contents: read

    steps:

      - name: Checkout
        uses: actions/checkout@v4

      - name: Configure AWS
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: ${{ env.AWS_REGION }}

      - name: Login to ECR
        id: login-ecr
        uses: aws-actions/amazon-ecr-login@v2

      - name: Build Image
        run: |
          docker build \
            -t ${{ steps.login-ecr.outputs.registry }}/${{ env.ECR_REPOSITORY }}:${{ github.sha }} .

      - name: Push Image
        run: |
          docker push \
            ${{ steps.login-ecr.outputs.registry }}/${{ env.ECR_REPOSITORY }}:${{ github.sha }}

⭐⭐⭐⭐⭐ 9. Why Use GitHub OIDC with AWS?

GitHub Actions can use OpenID Connect to obtain temporary AWS credentials by assuming an IAM role. This avoids storing long-lived AWS access keys inside GitHub.

⭐⭐⭐⭐⭐ 13. GitHub Actions Updating a GitOps Repository

- name: Update Image Tag
  run: |
    sed -i "s|image: .*|image: ${{ steps.login-ecr.outputs.registry }}/myapp:${{ github.sha }}|" \
      k8s/deployment.yaml

- name: Commit Changes
  run: |
    git config user.name "github-actions"
    git config user.email "github-actions@github.com"
    git add k8s/deployment.yaml
    git commit -m "Update image to ${{ github.sha }}" || exit 0
    git push
The exact implementation depends on repository structure. The key idea is that CI updates the desired state, and ArgoCD detects and reconciles that change.

⭐⭐⭐⭐⭐ 14. Multi-Stage CI/CD Pipeline

      - uses: actions/checkout@v4

⭐⭐⭐⭐⭐ 21. Rollback

A rollback restores a previously working version when a deployment causes unacceptable problems. 
kubectl rollout status deployment/myapp

kubectl rollout history deployment/myapp

kubectl rollout undo deployment/myapp
Production scenario:
If error rates suddenly increase after deployment, first stabilize the service. Stop or roll back the release when appropriate, then investigate the root cause.

⭐⭐⭐⭐⭐ 22. Real-Time Scenario: Docker Push Failed

Situation: Docker image builds successfully but push to ECR fails.

Check: 1. AWS authentication.
2. IAM permissions.
3. ECR repository name.
4. AWS region.
5. Registry URL.
6. Image tag.
7. ECR login step.
8. OIDC trust relationship if OIDC is being used.

⭐⭐⭐⭐⭐ 23. Real-Time Scenario: Kubernetes Deployment Failed

Situation: Pipeline succeeds until deployment, but Kubernetes deployment fails.

Check: 
kubectl get pods

kubectl describe deployment myapp

kubectl get events

kubectl logs <pod>
Then check:
• Image name/tag
• Registry authentication
• Deployment YAML
• Environment variables
• Secrets
• ConfigMaps
• Resource limits
• Probes

⭐⭐⭐⭐⭐ 24. Real-Time Scenario: ImagePullBackOff

ImagePullBackOff usually indicates Kubernetes is having trouble pulling the container image. Check:

1. Image repository.
2. Image tag.
3. Registry availability.
4. ImagePullSecrets if required.
5. Node/network access.
6. Registry permissions.

⭐⭐⭐⭐⭐ 25. Real-Time Scenario: CrashLoopBackOff

CrashLoopBackOff means the container starts and repeatedly exits, causing Kubernetes to restart it. Check: 
kubectl logs <pod>

kubectl logs <pod> --previous

kubectl describe pod <pod>
Possible causes include:
• Application error
• Incorrect command
• Missing environment variable
• Missing secret/config
• Port/configuration problem
• Dependency failure

⭐⭐⭐⭐⭐ 27. Best Practices

  • Keep workflows small and readable.
  • Use reusable workflows where appropriate.
  • Use least-privilege permissions.
  • Prefer OIDC for AWS authentication.
  • Never hard-code credentials.
  • Use immutable image tags.
  • Run automated tests before deployment.
  • Scan dependencies and images.
  • Protect production environments.
  • Keep deployment configuration version-controlled.
  • Monitor deployments.
  • Have a rollback strategy.

🎯 Interview-Ready Answer

"In a GitHub Actions CI/CD pipeline, I would trigger the workflow through a push or pull request. The pipeline first checks out the source code, installs dependencies, runs tests and performs code-quality and security checks. Then I build a Docker image and tag it with an immutable identifier such as the commit SHA. The image is pushed to Amazon ECR. For AWS authentication, I prefer GitHub OIDC with an IAM role so the workflow can obtain temporary credentials instead of storing long-lived AWS access keys. For deployment, I can deploy the image to Kubernetes directly, but for a GitOps architecture I would update the desired state in Git and let ArgoCD reconcile it into the EKS cluster. Finally, Prometheus and Grafana can be used to monitor the application and infrastructure."
