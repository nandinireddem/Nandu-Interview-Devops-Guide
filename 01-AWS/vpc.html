QUESTION 01

What is Amazon VPC?

⭐⭐⭐⭐⭐ MOST FREQUENTLY ASKED

VPC stands for Virtual Private Cloud. Amazon VPC allows us to create a logically isolated virtual network inside AWS. Within a VPC, we can control:

→ IP address ranges
→ Subnets
→ Route tables
→ Internet connectivity
→ Network security
→ Private connectivity

🌐 VPC → 🧩 Subnets → 🛣️ Route Tables → 🔐 Security → 🖥️ Resources
💡 Real-Time Example

Suppose we are deploying an application on EC2. Instead of placing servers randomly on the AWS network, we create a VPC and decide which servers should be public and which should remain private.

🎤 Interview Answer

"Amazon VPC is a logically isolated virtual network in AWS where we can define IP ranges, subnets, routing and network security for our resources."

🔎 Possible Follow-ups
  • What is a subnet?
  • What is a route table?
  • What is an Internet Gateway?
  • What is a NAT Gateway?
  • What is the difference between public and private subnet?
QUESTION 02

What is a CIDR block?

⭐⭐⭐⭐⭐ VERY COMMON

CIDR stands for Classless Inter-Domain Routing. CIDR notation represents an IP address range using an address followed by a prefix length. Example: 

```

10.0.0.0/16
```

The /16 indicates the network prefix length. A larger prefix number means a smaller address range. For example: 

```

10.0.0.0/16
10.0.1.0/24
10.0.2.0/24
```
💡 DevOps Example

A common VPC design might use:

VPC → 10.0.0.0/16
Public subnet → 10.0.1.0/24
Private subnet → 10.0.2.0/24

🎤 Interview Answer

"CIDR is a notation used to define an IP address range. In a VPC, we use CIDR blocks to define the VPC and subnet address ranges."

QUESTION 03

What is a subnet?

⭐⭐⭐⭐⭐ MUST KNOW

A subnet is a smaller IP address range inside a VPC. Subnets allow us to divide a VPC into separate network segments. Each subnet belongs to one Availability Zone.

VPC: 10.0.0.0/16

├── Public Subnet → 10.0.1.0/24
├── Public Subnet → 10.0.2.0/24
├── Private Subnet → 10.0.11.0/24
└── Private Subnet → 10.0.12.0/24
💡 Why use subnets?

We can put internet-facing load balancers in public subnets and application servers in private subnets. This creates network separation.

🎤 Interview Answer

"A subnet is a logical subdivision of a VPC's IP address range. Each subnet is associated with one Availability Zone and can be used to separate workloads based on network requirements."

QUESTION 04

What is the difference between a public subnet and a private subnet?

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE

The key difference is the subnet's routing configuration. A subnet is considered public when its route table has a route to an Internet Gateway. A subnet is considered private when it does not have a direct route to an Internet Gateway. A private subnet can still have outbound internet access through a NAT Gateway when appropriately configured.

PUBLIC
EC2 → Route Table → Internet Gateway → 🌐 Internet

PRIVATE
EC2 → Route Table → NAT Gateway → Internet Gateway → 🌐 Internet
💡 Production Example

Public subnet:
→ Application Load Balancer

Private subnet:
→ Application servers
→ Databases
→ Internal services

🎤 Interview Answer

"A public subnet has a route to an Internet Gateway, allowing supported resources to communicate with the internet when their other network configuration also permits it. A private subnet does not have a direct route to an Internet Gateway. It can use a NAT Gateway for outbound internet access."

QUESTION 05

What is an Internet Gateway?

⭐⭐⭐⭐⭐ VERY FREQUENT

An Internet Gateway, or IGW, is a VPC component that provides a path between a VPC and the internet. For an IPv4 public subnet, the route table normally contains a default route: 

```

0.0.0.0/0 → Internet Gateway
```

The subnet alone is not enough. The instance also needs appropriate addressing and security configuration.

💡 Simple Example

EC2 in public subnet
→ route table has 0.0.0.0/0 to IGW
→ EC2 has a public IPv4 address
→ security rules allow required traffic
→ internet communication can work.

🎤 Interview Answer

"An Internet Gateway is a VPC component that enables communication between a VPC and the internet. A public subnet typically has a default route pointing to the Internet Gateway."

QUESTION 06

What is a NAT Gateway?

⭐⭐⭐⭐⭐ MUST KNOW

NAT stands for Network Address Translation. A NAT Gateway allows resources in private subnets to initiate outbound connections to the internet without requiring those resources to have public IP addresses. It does not provide unsolicited inbound internet access to the private resources.

🖥️ Private EC2 → 🛣️ Private Route Table → NAT Gateway → Internet Gateway → 🌐 Internet
💡 DevOps Example

A private EC2 instance needs to download security updates or install packages. Instead of giving the EC2 instance a public IP, we can route outbound traffic through a NAT Gateway.

🎤 Interview Answer

"A NAT Gateway allows resources in private subnets to initiate outbound internet connections while keeping those resources without public IP addresses. It is deployed in a public subnet and uses an Elastic IP for IPv4 internet connectivity."

QUESTION 07

What is a Route Table?

⭐⭐⭐⭐⭐ VERY COMMON

A route table contains rules that determine where network traffic should be sent. Each route has:

→ Destination
→ Target 

```

Destination       Target

10.0.0.0/16       local
0.0.0.0/0         igw-xxxxxxxx
```

The local route allows communication within the VPC's CIDR.

💡 Example

If a public subnet needs internet connectivity, its route table can contain: 

```

0.0.0.0/0 → Internet Gateway
```
🎤 Interview Answer

"A route table contains routing rules that determine where traffic from a subnet should be sent. For example, a public subnet can have a default route to an Internet Gateway."

QUESTION 08

What is the difference between Security Group and NACL?

⭐⭐⭐⭐⭐ EXTREMELY IMPORTANT
SECURITY GROUP → 🖥️ ENI / Resource

NACL → 🧩 Subnet

Security Group:
→ Works at the resource/network-interface level
→ Stateful
→ Supports allow rules
→ Commonly used for instance-level access control

Network ACL:
→ Works at subnet boundary
→ Stateless
→ Supports allow and deny rules
→ Rules are evaluated in order

🎤 Interview Answer

"Security Groups are stateful virtual firewalls associated with network interfaces and support allow rules. Network ACLs operate at the subnet level, are stateless, support both allow and deny rules, and are evaluated in rule order."

🔎 Very Common Follow-ups
  • Which one is stateful?
  • Which one supports deny rules?
  • Where does NACL work?
  • Where does Security Group work?
  • Which is evaluated first?
QUESTION 09

What is the difference between a default VPC and a custom VPC?

⭐⭐⭐⭐ IMPORTANT

AWS accounts can have a default VPC in supported Regions. AWS creates common networking components for the default VPC, making it convenient for initial workloads. A custom VPC is designed by us according to application requirements.

💡 Production Example

For a production environment, we normally design our own CIDR ranges, public and private subnets, routing, NAT, security and connectivity rather than depending on the default VPC design.

🎤 Interview Answer

"A default VPC is an AWS-provided VPC with common networking configuration for convenience. A custom VPC is designed and configured according to the application's networking and security requirements."

QUESTION 10

Can a subnet span multiple Availability Zones?

⭐⭐⭐⭐⭐ TRICK QUESTION

No. An AWS subnet is associated with exactly one Availability Zone. A VPC can span multiple Availability Zones, but each individual subnet belongs to one AZ.

VPC
├── AZ-A → Subnet-A
└── AZ-B → Subnet-B
🎤 Interview Answer

"No. A subnet is associated with one Availability Zone. To build a multi-AZ architecture, we create separate subnets in multiple Availability Zones."

QUESTION 11

What are the main components of a VPC?

⭐⭐⭐⭐ COMMON

Important VPC-related components include:

→ VPC
→ Subnets
→ Route Tables
→ Internet Gateway
→ NAT Gateway
→ Security Groups
→ Network ACLs
→ Network Interfaces
→ VPC Endpoints
→ VPC Peering
→ Transit Gateway for larger network designs

🎤 Interview Answer

"A VPC consists of networking constructs such as CIDR ranges, subnets, route tables, gateways, security controls and network interfaces. Additional connectivity components such as VPC endpoints, peering and Transit Gateway can be used depending on the architecture."

QUESTION 12

What is a VPC Peering connection?

⭐⭐⭐⭐ IMPORTANT

VPC Peering is a networking connection between two VPCs that allows resources in those VPCs to communicate using private IP addresses, subject to routing and security configuration. The VPCs can be in the same or different AWS accounts, and supported peering can also span Regions.

VPC-A ⇄ VPC Peering ⇄ VPC-B
⚠️ The VPC CIDR ranges must not overlap for normal VPC peering routing to work.
🎤 Interview Answer

"VPC Peering creates private network connectivity between two VPCs. After establishing the peering connection, we must configure appropriate routes and security rules. The VPC CIDRs should not overlap."

QUESTION 13

What is a VPC Endpoint?

⭐⭐⭐⭐ VERY USEFUL

VPC Endpoints provide private connectivity from a VPC to supported AWS services without requiring traffic to traverse the public internet. Two important endpoint categories are:

Gateway Endpoints
Commonly used for Amazon S3 and DynamoDB.

Interface Endpoints
Powered by AWS PrivateLink and implemented using elastic network interfaces.

💡 DevOps Example

A private EC2 instance needs access to S3. Instead of sending that traffic through a NAT Gateway, an S3 Gateway Endpoint can provide private access.

🎤 Interview Answer

"VPC endpoints provide private connectivity between resources in a VPC and supported AWS services. Gateway endpoints are commonly used for S3 and DynamoDB, while interface endpoints use AWS PrivateLink."

QUESTION 14

What is an Elastic Network Interface (ENI)?

⭐⭐⭐⭐ IMPORTANT

An ENI is a virtual network interface in a VPC. It can have attributes such as:

→ Private IPv4 addresses
→ Secondary private IP addresses
→ Security groups
→ MAC address
→ Optional public/Elastic IP associations

💡 Simple Understanding

Think of an ENI as a virtual network card attached to a resource.

🎤 Interview Answer

"An Elastic Network Interface is a virtual network interface in a VPC that provides network connectivity and can have private IP addresses, security groups and other network attributes."

QUESTION 15

What is the difference between a NAT Gateway and an Internet Gateway?

⭐⭐⭐⭐⭐ VERY COMMON
Internet Gateway → VPC ↔ Internet

NAT Gateway → Private Subnet → Internet
🚫 No direct unsolicited inbound access

An Internet Gateway is attached to a VPC and provides a path for internet communication. A NAT Gateway is deployed in a subnet, typically a public subnet, and allows private subnet resources to make outbound internet connections.

🎤 Interview Answer

"An Internet Gateway provides internet connectivity for a VPC. A NAT Gateway is used by private subnet resources to initiate outbound internet connections without exposing those resources with public IPs."

QUESTION 16

Why is a NAT Gateway placed in a public subnet?

⭐⭐⭐⭐ TRICKY

A NAT Gateway needs a path to the internet for the outbound traffic it translates. Therefore, for IPv4 internet access, the NAT Gateway is typically deployed in a public subnet with a route to an Internet Gateway and an Elastic IP. Private subnet route tables then point their default route to the NAT Gateway.

Private Subnet → NAT Gateway → Public Subnet → IGW → Internet
🎤 Interview Answer

"A NAT Gateway is placed in a public subnet because it needs a route through the Internet Gateway to provide outbound internet connectivity for resources in private subnets."

QUESTION 17

What is VPC Flow Logs?

⭐⭐⭐⭐ MONITORING + TROUBLESHOOTING

VPC Flow Logs capture information about IP traffic going to and from network interfaces, subnets or VPCs depending on the configured scope. They are useful for troubleshooting connectivity and security analysis.

💡 Example

An application cannot connect to a database. Flow Logs can help determine whether traffic is being accepted or rejected at the network-flow level.

🎤 Interview Answer

"VPC Flow Logs capture metadata about network traffic flows and are useful for troubleshooting connectivity, analyzing rejected traffic and supporting security investigations."

QUESTION 18

What is a default route?

⭐⭐⭐⭐ COMMON

A default route is used when no more specific route matches the destination. For IPv4: 

```

0.0.0.0/0
```

For IPv6: 

```

::/0
```
💡 Example

A public subnet route table might contain: 

```

0.0.0.0/0 → Internet Gateway
```
🎤 Interview Answer

"A default route matches destinations for which no more specific route exists. In IPv4 it is represented as 0.0.0.0/0."

⭐⭐⭐ Medium Priority

QUESTION 19

What is a Transit Gateway?

⭐⭐⭐ NETWORK ARCHITECTURE

AWS Transit Gateway acts as a central network hub that can connect multiple VPCs and on-premises networks. It is useful when a company has many networks and point-to-point VPC peering would become difficult to manage.

VPC-A ↘
VPC-B → 🏢 Transit Gateway ← VPC-C
↗ On-Premises
🎤 Interview Answer

"Transit Gateway is a centralized network hub used to connect multiple VPCs and on-premises networks. It simplifies large-scale network connectivity compared with maintaining many individual peering connections."

QUESTION 20

What is DNS resolution in a VPC?

⭐⭐⭐ COMMON

AWS provides DNS functionality within VPCs. Important VPC DNS settings include:

enableDnsSupport → controls whether DNS resolution is supported.

enableDnsHostnames → controls whether instances in the VPC receive DNS hostnames when applicable.

🎤 Interview Answer

"VPC DNS settings control DNS resolution and DNS hostnames for resources inside the VPC. AWS provides DNS resolution through the VPC resolver."

QUESTION 21

What is an Elastic IP?

⭐⭐⭐ COMMON

An Elastic IP is a static public IPv4 address allocated to your AWS account. It can be associated with supported AWS resources. It is useful when a stable public IPv4 address is required.

⚠️ In production, avoid using Elastic IPs unnecessarily. DNS and load balancers are often better architectural choices for application endpoints.
🎤 Interview Answer

"An Elastic IP is a static public IPv4 address allocated to an AWS account that can be associated with supported resources when a stable public address is required."

QUESTION 22

Can two VPCs have overlapping CIDR ranges?

⭐⭐⭐ TRICKY

Two completely independent VPCs can technically have the same CIDR range. However, overlapping CIDRs create problems for direct private routing between those networks and are generally avoided when designing connected networks.

💡 Example

VPC-A → 10.0.0.0/16
VPC-B → 10.0.0.0/16

If we later need normal VPC peering between them, the overlapping ranges prevent the required routing.

🎤 Interview Answer

"Independent VPCs can have overlapping CIDRs, but overlapping address ranges prevent normal private routing between them and create major connectivity problems. Therefore non-overlapping CIDRs are preferred for connected network designs."

QUESTION 23

What is the difference between public IP and private IP in a VPC?

⭐⭐⭐ IMPORTANT

A private IP is used for communication inside the VPC and connected private networks. A public IPv4 address is used for internet-facing communication when the network configuration allows it. Private IP addresses remain associated with the ENI while the instance exists, subject to the specific network configuration.

Private IP → 🏠 Internal Communication

Public IP → 🌐 Internet Communication
🎤 Interview Answer

"Private IP addresses are used for communication within the VPC and connected private networks. Public IPv4 addresses provide internet-facing addressing when the resource's routing and security configuration permits it."

⭐⭐ Less Frequently Asked

QUESTION 24

What is a network interface's secondary private IP?

⭐⭐

A network interface can have additional private IPv4 addresses beyond its primary private IP, subject to service and instance limits. Secondary IPs can be useful for applications that need multiple addresses on the same network interface.

🎤 Interview Answer

"A secondary private IP is an additional private IPv4 address assigned to a network interface. It can support applications that require multiple private addresses."

QUESTION 25

What are VPC DHCP options?

⭐⭐

DHCP option sets allow you to configure certain network settings provided to instances through DHCP, such as domain name and DNS server information. AWS provides a default DHCP option set for VPCs.

🎤 Interview Answer

"VPC DHCP option sets define network configuration information such as domain name and DNS servers that can be provided to instances through DHCP."

QUESTION 26

What is IPv6 in VPC?

⭐⭐

AWS VPCs can use IPv6 addressing in addition to IPv4. IPv6 provides a very large address space and can be useful for modern architectures that need globally unique IPv6 addresses.

🎤 Interview Answer

"AWS VPC supports IPv6 addressing alongside IPv4. IPv6 provides a very large address space and can support applications that require IPv6 connectivity."

⭐ Bonus Questions

QUESTION 27

What is the difference between VPC Peering and Transit Gateway?

⭐ ARCHITECTURE

VPC Peering provides a direct connection between two VPCs. Transit Gateway provides a centralized hub for connecting many VPCs and networks.

Peering:
VPC-A ⇄ VPC-B

Transit Gateway:
VPC-A ↘ TGW ← VPC-B ↗ VPC-C
🎤 Interview Answer

"VPC Peering is suitable for direct connectivity between VPCs, while Transit Gateway is better for centralized connectivity across many VPCs and on-premises networks."

🎯 Real-Time VPC Scenarios

SCENARIO 01

An EC2 instance in a private subnet cannot access the internet. How do you troubleshoot it?

⭐⭐⭐⭐⭐ VERY COMMON

I would check the path step by step.

1. Check the private subnet route table.
It should have a default route: 

```

0.0.0.0/0 → NAT Gateway
```

2. Check the NAT Gateway.
Confirm it is available and deployed in a public subnet.

3. Check the NAT subnet route.
NAT Gateway's subnet should have: 

```

0.0.0.0/0 → Internet Gateway
```

4. Check Network ACLs.
Because NACLs are stateless, return traffic must also be allowed.

5. Check security group rules.
Verify required outbound traffic is allowed.

Private EC2 → Private Route Table → NAT Gateway → Public Route Table → IGW → Internet
🎤 Interview Answer

"I would first check the private subnet route table for a default route to the NAT Gateway. Then I would verify the NAT Gateway is healthy and is in a public subnet whose route table has a route to the Internet Gateway. Finally I would check NACL and security group rules."

SCENARIO 02

EC2 has a public IP but still cannot access the internet. What will you check?

⭐⭐⭐⭐⭐ TROUBLESHOOTING

A public IP alone does not guarantee internet connectivity. I would check:

1. Is the subnet actually public?
2. Does its route table contain: 

```

0.0.0.0/0 → Internet Gateway
```

3. Is the Internet Gateway attached to the VPC?
4. Are security group rules correct?
5. Are NACL rules correct?
6. Is the OS firewall blocking the traffic?
7. Is the application listening on the expected port?

🎤 Interview Answer

"I would not assume that a public IP is sufficient. I would verify the subnet route table, Internet Gateway attachment, security groups, NACLs, operating-system firewall and application listener."

SCENARIO 03

Two EC2 instances in the same VPC cannot communicate. What would you check?

⭐⭐⭐⭐⭐ COMMON

I would check:

→ Are both instances in the expected VPC?
→ Are their subnets correctly routed?
→ Is the local VPC route present?
→ Does the destination security group allow the source?
→ Are NACLs allowing both directions?
→ Is the application actually listening?
→ Is the OS firewall blocking the connection?

💡 Example

Web Server:
10.0.1.10

Application Server:
10.0.2.10

If the application server's security group does not allow the required application port from the web server's security group, the connection can fail.

🎤 Interview Answer

"I would verify the VPC and routing first, then check the destination security group, NACLs, operating-system firewall and application listener."

SCENARIO 04

Design a production 3-tier architecture using VPC.

⭐⭐⭐⭐⭐ DEVOPS ARCHITECTURE
🌐 Internet ↓ ⚖️ Application Load Balancer ↓ ┌──────────────────────────────┐ │ Public Subnets │ │ ALB │ └──────────────────────────────┘ ↓ ┌──────────────────────────────┐ │ Private App Subnets │ │ EC2 / ECS / Applications │ └──────────────────────────────┘ ↓ ┌──────────────────────────────┐ │ Private DB Subnets │ │ Database │ └──────────────────────────────┘

A common production design separates workloads into different subnet tiers.

Public subnet:
Load Balancer

Private application subnet:
Application servers

Private database subnet:
Database services

NAT Gateway can provide outbound internet access for private application resources when required. Multiple Availability Zones should be used for resilience.

🎤 Interview Answer

"I would design a multi-AZ VPC with public subnets for the load balancer, private application subnets for application workloads and isolated private database subnets. NAT Gateways can provide outbound internet access for private application resources, while security groups control tier-to-tier access."

SCENARIO 05

Security Group allows traffic, but the connection is still failing. What could be wrong?

⭐⭐⭐⭐ TROUBLESHOOTING

A Security Group is only one part of the network path. I would also check:

→ Route tables
→ NACLs
→ Internet Gateway / NAT Gateway
→ DNS
→ OS firewall
→ Application listener
→ Correct IP and port
→ VPC Flow Logs

🎤 Interview Answer

"A security group being correct does not guarantee connectivity. I would verify routing, NACLs, gateways, DNS, the operating-system firewall and whether the application is listening on the expected address and port."
