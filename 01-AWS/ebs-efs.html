QUESTION 01

What is Amazon EBS?

⭐⭐⭐⭐⭐ MOST FREQUENTLY ASKED

Amazon EBS stands for Elastic Block Store. It provides persistent block-level storage volumes that can be attached to EC2 instances. Think of EBS like a virtual hard disk for an EC2 instance.

EC2 Instance → EBS Volume → Persistent Data
💡 Easy Example

Suppose an EC2 instance contains an application and its data. If the instance is stopped and started again, the EBS volume can retain the data. Therefore EBS provides persistent storage separately from the compute instance.

🎤 Interview Answer

"Amazon EBS is a persistent block storage service designed for EC2. An EBS volume can be attached to an EC2 instance and is commonly used for operating system disks, application data and databases."

QUESTION 02

What is the difference between EBS and instance store?

⭐⭐⭐⭐⭐ INTERVIEW FAVORITE
Feature EBS Instance Store
Storage Type Persistent block storage Temporary local storage
Data Persistence Designed to persist independently of instance lifecycle Data can be lost when the instance is stopped/terminated depending on lifecycle
Network Attached Yes Physically attached to host
Typical Use OS, application data, databases Temporary/cache/scratch workloads
🧠 Easy Memory Trick

EBS = Persistent Disk
Instance Store = Temporary Local Disk

🎤 Interview Answer

"EBS provides persistent block storage that is independent from the lifecycle of the EC2 compute resource. Instance store is temporary local storage physically attached to the host and is suitable for temporary data."

QUESTION 03

What are the main EBS volume types?

⭐⭐⭐⭐⭐ MUST KNOW

The major EBS volume families you should know are:

gp3
General-purpose SSD. A common choice for general workloads.

gp2
Previous-generation general-purpose SSD.

io2
Provisioned IOPS SSD for I/O-intensive workloads.

st1
Throughput-oriented HDD, suitable for large sequential workloads.

sc1
Lower-cost HDD designed for infrequently accessed throughput-oriented workloads.

💡 In most modern general-purpose application architectures, gp3 is an important volume type to understand.
🎤 Interview Answer

"EBS provides different volume types based on workload requirements. gp3 is commonly used for general-purpose SSD workloads, io2 is used for high-performance IOPS-intensive workloads, while st1 and sc1 are throughput-oriented HDD options."

QUESTION 04

What is the difference between gp3 and io2?

⭐⭐⭐⭐⭐ VERY COMMON
Feature gp3 io2
Type General-purpose SSD Provisioned IOPS SSD
Use Case General applications High I/O intensive workloads
Performance Good general-purpose performance High and predictable IOPS
Typical Workload Web servers, applications, DevOps workloads High-performance databases and critical I/O workloads
🎤 Interview Answer

"gp3 is a general-purpose SSD suitable for most application workloads, while io2 is designed for workloads that require high and predictable IOPS, such as demanding database workloads."

QUESTION 05

What is an EBS snapshot?

⭐⭐⭐⭐⭐ VERY FREQUENT

An EBS snapshot is a point-in-time backup of an EBS volume. Snapshots are stored in Amazon S3-managed infrastructure and can be used to create new EBS volumes or restore data.

EBS Volume → 📸 Snapshot → Backup → New EBS Volume
💡 Real-Time Example

Before performing a risky production change, you can create a snapshot of the relevant EBS volume. If recovery is required, the snapshot can be used to create a new volume.

🎤 Interview Answer

"An EBS snapshot is a point-in-time backup of an EBS volume. It can be used for backup, recovery, migration and creating new EBS volumes."

QUESTION 06

What is Amazon EFS?

⭐⭐⭐⭐⭐ MUST KNOW

Amazon EFS stands for Elastic File System. It provides managed, elastic file storage that can be accessed concurrently by multiple compute resources. EFS uses the NFS protocol.

EC2-A ↘
EC2-B → 📁 EFS ← EC2-C
💡 Real-Time Example

Suppose three EC2 instances are running a web application and all need access to the same uploaded files. Instead of storing those files separately on each EC2 instance, an EFS file system can provide shared file storage.

🎤 Interview Answer

"Amazon EFS is a managed elastic file storage service that provides shared file storage using NFS. Multiple supported compute resources can mount and access the same file system."

QUESTION 07

What is the difference between EBS and EFS?

⭐⭐⭐⭐⭐ TOP INTERVIEW QUESTION
Feature EBS EFS
Storage Model Block storage File storage
Access Attached to EC2 according to supported configuration Shared file system
Protocol Block device NFS
Multi-Instance Access Limited by volume and attachment capabilities Designed for concurrent access
Typical Use OS disks, databases, application disks Shared files, content, common application storage
🧠 Easy Memory Trick

EBS = One virtual hard disk

EFS = Shared network file system

🎤 Interview Answer

"EBS is block storage primarily attached to EC2, while EFS is a managed shared file system accessed using NFS. EBS is commonly used for operating system and application disks, while EFS is useful when multiple instances need shared files."

QUESTION 08

Can multiple EC2 instances access the same EFS?

⭐⭐⭐⭐⭐ COMMON

Yes. EFS is designed to provide shared file storage that multiple supported compute resources can access concurrently.

EC2-1 ─┐
EC2-2 ─┼──→ EFS
EC2-3 ─┘
🎤 Interview Answer

"Yes. Amazon EFS is a shared file system, so multiple EC2 instances can mount and access the same EFS file system concurrently."

QUESTION 09

Can EBS be attached to multiple EC2 instances?

⭐⭐⭐⭐⭐ TRICK QUESTION

The normal EBS usage model is one volume attached to one EC2 instance at a time. However, certain EBS volume types and supported EC2 configurations provide multi-attach capabilities. Therefore, don't simply say "EBS can never be attached to multiple instances."

🎯 Interview Tip: Say:

"Normally an EBS volume is attached to a single EC2 instance, but specific supported configurations such as EBS Multi-Attach allow certain io2 volumes to be attached to multiple supported instances in the same Availability Zone."
QUESTION 10

What is EBS encryption?

⭐⭐⭐⭐⭐ MUST KNOW

EBS encryption protects data at rest on EBS volumes. AWS Key Management Service (KMS) can be used to manage the encryption keys. Encryption can cover:

→ Data at rest
→ Snapshots
→ Volumes created from encrypted snapshots
→ Data moving between the instance and the EBS volume depending on supported implementation

🎤 Interview Answer

"EBS encryption protects EBS data at rest and uses AWS KMS for key management. Encrypted snapshots and volumes can also be created from encrypted EBS resources."

QUESTION 11

What is EFS mount target?

⭐⭐⭐⭐⭐ VERY IMPORTANT

An EFS mount target provides network access to an EFS file system from a specific Availability Zone. It is associated with a subnet and security group. EC2 instances use the mount target to connect to the EFS file system.

EC2 in AZ-A → Mount Target AZ-A → EFS

EC2 in AZ-B → Mount Target AZ-B → EFS
🎤 Interview Answer

"An EFS mount target provides a network endpoint through which resources in an Availability Zone can access the EFS file system. It is created in a subnet and associated with security groups."

QUESTION 12

How do you mount EFS on an EC2 instance?

⭐⭐⭐⭐⭐ DEVOPS PRACTICAL

A common approach is to install the EFS mount helper, create a mount directory and mount the file system. 

```

sudo mkdir -p /mnt/efs

sudo mount -t efs fs-XXXXXXXX:/ /mnt/efs
```

The exact commands depend on the operating system and whether encryption-in-transit is enabled.

💡 Verify Mount 
```

df -h
```
🎤 Interview Answer

"I would install the required EFS mount helper, create a mount point and mount the EFS file system. Then I would verify the mount using commands such as df -h and confirm that security groups allow NFS traffic."

⭐⭐⭐⭐ High Priority

QUESTION 13

What is EBS volume resizing?

⭐⭐⭐⭐

EBS volumes can generally be modified to increase storage capacity and, for supported volume types, adjust performance characteristics. After increasing the volume size, the operating system filesystem may also need to be expanded.

AWS EBS Volume → Increase Size → OS Detects Larger Disk → Expand Partition / Filesystem
💡 Linux Example 
```

lsblk

df -h
```

After resizing the EBS volume in AWS, verify the device and expand the partition/filesystem as required by the operating system and filesystem type.

🎤 Interview Answer

"After increasing an EBS volume size, I verify that the operating system sees the larger block device. Then I expand the partition and filesystem if required so the application can use the additional capacity."

QUESTION 14

What is the difference between EBS snapshot and AMI?

⭐⭐⭐⭐
Snapshot AMI
Backup of EBS volume Machine image used to launch EC2 instances
Primarily storage-level backup Instance template / image
Can create EBS volumes Can launch EC2 instances
🎤 Interview Answer

"An EBS snapshot is a point-in-time backup of an EBS volume. An AMI is a machine image that can be used to launch EC2 instances and can reference one or more snapshots."

QUESTION 15

What is EFS performance mode?

⭐⭐⭐⭐

EFS provides performance modes that determine how the file system behaves for different workloads. The key concept to remember is that performance mode selection is related to workload characteristics and throughput/latency requirements.

💡 Interview focus: Don't memorize random values. Understand that EFS performance configuration should match the application's file access pattern and performance requirements.
🎤 Interview Answer

"EFS performance configuration is selected based on application access patterns and performance requirements. I would evaluate the workload's latency and throughput characteristics before selecting the appropriate configuration."

QUESTION 16

What is EFS throughput mode?

⭐⭐⭐⭐

EFS throughput mode controls how throughput is provided to the file system. Modern EFS supports modes such as:

→ Elastic
→ Provisioned
→ Bursting

The correct mode depends on workload characteristics and traffic patterns.

🎤 Interview Answer

"EFS throughput mode determines how file-system throughput is provided. Elastic can adapt to workload demand, while Provisioned allows a configured throughput level. Bursting uses a model based on file system size and workload behavior."

QUESTION 17

What is EFS storage class?

⭐⭐⭐⭐

EFS supports storage classes designed for different access patterns and cost requirements. Common concepts include:

→ EFS Standard
→ EFS Infrequent Access
→ EFS Archive

Lifecycle management can move files between appropriate storage classes based on access patterns.

🎤 Interview Answer

"EFS provides storage classes for frequently and infrequently accessed data, including Archive for long-term infrequently accessed data. Lifecycle policies can help optimize storage cost."

QUESTION 18

What security group rules are required for EFS?

⭐⭐⭐⭐⭐ PRACTICAL

EFS uses NFS. Therefore, the EC2 instances that mount EFS need network connectivity to the EFS mount target on the NFS port. 

```

NFS
TCP
Port 2049
```
EC2 Security Group → TCP 2049 → EFS Mount Target Security Group
🔐 Best Practice: Allow TCP 2049 from the application's EC2 security group rather than allowing it broadly from the entire internet.
🎤 Interview Answer

"EFS uses NFS, so the EC2 instances need network access to the EFS mount target on TCP port 2049. I would allow that traffic using security groups with least privilege."

⭐⭐⭐ Medium Priority

QUESTION 19

What is EFS Access Point?

⭐⭐⭐

An EFS Access Point provides an application-specific entry point into an EFS file system. It can enforce a configured root directory and POSIX identity for access. This is especially useful when multiple applications share one EFS file system but should have isolated access paths.

💡 Example

Application A:
`/app-a`

Application B:
`/app-b`

Each application can use a different access point.

🎤 Interview Answer

"An EFS Access Point provides an application-specific access path into an EFS file system and can enforce a POSIX identity and root directory."

QUESTION 20

What is EFS encryption in transit?

⭐⭐⭐

EFS supports encryption at rest and encryption in transit. Encryption in transit protects data while it is moving between the client and EFS. TLS can be used through the EFS mount helper. 

```

sudo mount -t efs -o tls fs-XXXXXXXX:/ /mnt/efs
```
🎤 Interview Answer

"EFS supports encryption at rest and encryption in transit. For encryption in transit, the EFS mount helper can establish a TLS-protected connection."

QUESTION 21

What happens if an EC2 instance is terminated?

⭐⭐⭐

The behavior depends on the EBS volume's DeleteOnTermination setting. For a root volume, it is commonly configured to delete when the instance terminates. Additional EBS volumes can be configured to persist after instance termination.

🎯 Interview Tip: Always say:

"It depends on the DeleteOnTermination setting."
🎤 Interview Answer

"Whether an EBS volume is deleted when an EC2 instance terminates depends on its DeleteOnTermination configuration. I verify this setting before terminating production instances."

⭐⭐ Less Frequently Asked

QUESTION 22

What is EBS Multi-Attach?

⭐⭐

EBS Multi-Attach allows a supported EBS volume to be attached to multiple supported EC2 instances in the same Availability Zone. It is designed for specific clustered application architectures and requires application-level coordination to safely manage shared block storage.

🎤 Interview Answer

"EBS Multi-Attach allows certain supported io2 volumes to be attached to multiple supported EC2 instances in the same Availability Zone. The application must be designed to safely coordinate concurrent access."

QUESTION 23

Can EBS volumes be moved across Availability Zones?

⭐⭐

An EBS volume is associated with a specific Availability Zone. To use its data in another Availability Zone, a common approach is to create a snapshot and then create a new volume from that snapshot in the target Availability Zone.

EBS Volume → Snapshot → Target AZ → New EBS Volume
🎤 Interview Answer

"An EBS volume is AZ-specific. To move its data to another Availability Zone, I can create a snapshot and create a new EBS volume from that snapshot in the target AZ."

QUESTION 24

What is EFS One Zone?

⭐⭐

EFS provides Regional file systems designed for multi-AZ availability and One Zone file systems that store data within a single Availability Zone. One Zone can be useful for workloads where lower storage cost is more important and the availability trade-off is acceptable.

🎤 Interview Answer

"EFS One Zone stores data in a single Availability Zone and can provide a lower-cost option for appropriate workloads. Regional EFS provides multi-AZ storage for higher availability."

🎯 Real-Time EBS & EFS Scenarios

SCENARIO 01

EC2 says the EBS volume is full. What will you do?

⭐⭐⭐⭐⭐ VERY COMMON

First I check disk usage: 

```

df -h
```

Then identify which directories are consuming space: 

```

sudo du -sh /* 2>/dev/null
```

Then:

1. Clean unnecessary data/logs if safe.
2. Increase EBS volume size if required.
3. Expand the partition/filesystem.
4. Verify using `df -h`.

🎤 Interview Answer

"I would first identify what is consuming the disk using df and du. If cleanup is not enough, I would increase the EBS volume size and then expand the filesystem. Finally, I would verify the available space."

SCENARIO 02

EC2 cannot mount EFS. What will you check?

⭐⭐⭐⭐⭐ DEVOPS FAVORITE

Follow the network path.

1. DNS
Confirm the instance can resolve the EFS endpoint.

2. Mount Target
Confirm the EFS mount target exists for the relevant Availability Zone/network.

3. Security Group
Check TCP 2049.

4. Network ACL / Routing
Verify network connectivity.

5. EFS Mount Helper
Confirm required packages are installed.

6. File System Policy / IAM
If using IAM authorization, verify permissions.

🎤 Interview Answer

"I would first check the EFS mount target and network connectivity, especially TCP 2049. Then I would verify DNS, security groups, NACLs, routing and the EFS mount helper. If IAM authorization is enabled, I would also verify the relevant permissions."

SCENARIO 03

Three EC2 instances need access to the same uploaded files. EBS or EFS?

⭐⭐⭐⭐⭐ SCENARIO

EFS is generally the better fit because the requirement is shared file access across multiple instances.

EC2-1 ↘
EC2-2 → EFS ← EC2-3
🎤 Interview Answer

"I would choose EFS because multiple EC2 instances need concurrent access to the same shared file system. EFS is designed for this shared file storage requirement."

SCENARIO 04

Your database requires consistently high IOPS. Which EBS type would you consider?

⭐⭐⭐⭐

I would consider an appropriate provisioned-IOPS SSD such as io2, after evaluating the database workload, required IOPS, throughput, latency and cost.

🎤 Interview Answer

"For a database requiring consistently high and predictable IOPS, I would evaluate io2 because it is designed for provisioned IOPS workloads. I would still size it based on measured application requirements."

SCENARIO 05

You terminated an EC2 instance and lost its root disk data. Why?

⭐⭐⭐⭐

The root EBS volume may have had DeleteOnTermination enabled. Before terminating an instance, production data should be stored and protected according to the application's backup and persistence requirements.

🎤 Interview Answer

"The root EBS volume may have been configured with DeleteOnTermination enabled. I would check the volume's lifecycle configuration and ensure production data has appropriate backups before terminating instances."
