QUESTION 01

What is Amazon S3?

CLEAR CONCEPT

Amazon S3 stands for Simple Storage Service. It is an AWS object storage service used to store and retrieve data from anywhere over the internet or through AWS services. S3 is designed to provide highly durable and scalable storage. Instead of storing files on a server's local disk, we can store them as objects inside S3.

👤 Application → 🪣 S3 Bucket → 📦 Object → 💾 Stored Data
💡 Real-Time Example

Suppose our application allows users to upload profile pictures. Instead of storing thousands of images directly on an EC2 server, we can upload those images to S3 and store the S3 object reference in our application/database.

🎤 Interview Answer

"Amazon S3 is an object storage service provided by AWS. It is used to store and retrieve objects such as files, images, videos, backups and logs. S3 provides scalable storage with high durability and supports features such as versioning, lifecycle management, encryption and access control."

QUESTION 02

What is a bucket in S3?

CLEAR CONCEPT

A bucket is a container used to store objects in S3. Think of a bucket as the top-level storage location where we keep files and other objects. Each object belongs to a bucket. Bucket-level configuration can include things such as access controls, versioning, lifecycle rules, encryption settings and other policies.

💡 Real-Time Example

If we build an e-commerce application, we might have a bucket for product images and another bucket for application backups. Inside the bucket we can organize objects using key prefixes such as: 

```

product-images/
phones/
laptops/

backups/
database/
application/
```
🎤 Interview Answer

"An S3 bucket is a logical container in which objects are stored. We can configure bucket-level settings such as access policies, versioning, lifecycle rules and encryption."

  • What makes an S3 bucket name unique?

  • Can we change a bucket's region?
QUESTION 03

What is an object in S3?

CLEAR CONCEPT

An object is the actual piece of data stored in S3. An object consists mainly of:

Data — the actual file content.
Key — the unique name/path used to identify the object within a bucket.
Metadata — information associated with the object.

💡 Real-Time Example

Suppose we upload: 

```

profile.jpg
```

to: 

```

nandu-app-bucket/users/1001/profile.jpg
```

Here the file is the object and the complete object key identifies where it is logically located in the bucket.

🎤 Interview Answer

"An S3 object is the actual data stored in a bucket. An object has data, a key that identifies it, and metadata associated with it."

QUESTION 04

Is S3 file storage, block storage or object storage?

VERY COMMON CONCEPT

S3 is an object storage service. This is an important distinction.

S3 → Object Storage
EBS → Block Storage
EFS → File Storage

Object storage manages data as objects rather than presenting a traditional block device or shared filesystem.

💡 Easy Way to Remember

S3 → Files as objects
EBS → Disk-like block storage for EC2
EFS → Shared filesystem

🎤 Interview Answer

"Amazon S3 is object storage. EBS provides block storage and EFS provides managed file storage. The correct choice depends on the application's storage requirement."

QUESTION 05

What are S3 storage classes?

MUST KNOW

S3 storage classes are different storage options designed for different access patterns. Common classes include:

S3 Standard — frequently accessed data.
S3 Intelligent-Tiering — useful when access patterns are unpredictable.
S3 Standard-IA — infrequently accessed data that still needs quick access.
S3 One Zone-IA — infrequently accessed data stored in a single Availability Zone.
S3 Glacier Instant Retrieval — archive data that still needs very fast retrieval.
S3 Glacier Flexible Retrieval — archive data where retrieval can take longer.
S3 Glacier Deep Archive — very long-term archival data with infrequent access.

💡 Real-Time Example

A company may keep active application assets in S3 Standard, move older data to an appropriate infrequent-access or archive class through lifecycle rules, and use Deep Archive for long-term retention.

🎤 Interview Answer

"S3 provides multiple storage classes based on access frequency and retrieval requirements. For example, Standard is suitable for frequently accessed data, while Glacier classes are designed for archival workloads."

QUESTION 06

What is S3 Versioning?

MUST KNOW

S3 Versioning allows S3 to maintain multiple versions of an object in the same bucket. If an object is overwritten or deleted, previous versions can remain available depending on the bucket's versioning state and lifecycle configuration. This helps protect against accidental deletion or accidental overwrites.

💡 Real-Time Example

Suppose we have: 

```

config.json → Version 1
config.json → Version 2
config.json → Version 3
```

If Version 3 contains a mistake, we may be able to recover an earlier version instead of losing the previous data.

🎤 Interview Answer

"S3 Versioning keeps multiple versions of objects in a bucket. It helps protect data from accidental deletion and overwrites and can support recovery of previous object versions."

QUESTION 07

What is an S3 Lifecycle Rule?

MUST KNOW

An S3 Lifecycle Rule automatically performs actions on objects based on conditions such as object age. We can use lifecycle rules to transition objects between storage classes or expire objects when they are no longer required.

💡 Real-Time Example

Imagine application logs are stored in S3. We may configure a lifecycle policy such as: 

```

Day 0      → S3 Standard
Day 30     → Infrequent Access
Day 90     → Archive
Day 365    → Delete
```

The exact policy should be chosen based on the application's retention and compliance needs.

🎤 Interview Answer

"S3 Lifecycle Rules automate object management. They can transition objects to different storage classes or expire objects based on defined conditions such as age."

QUESTION 08

How do you secure an S3 bucket?

SECURITY

S3 security should be designed using multiple controls rather than depending on only one setting. Important controls include:

• IAM policies
• Bucket policies
• Block Public Access
• Encryption
• Versioning where appropriate
• Least-privilege permissions
• Logging and monitoring

💡 Real-Time Example

If an application needs to upload files to S3, instead of making the bucket public, we can give the application's IAM role only the required S3 permissions.

🎤 Interview Answer

"I secure S3 using least-privilege IAM or resource policies, Block Public Access, encryption, appropriate bucket configuration, and monitoring. I avoid making buckets public unless there is a specific justified requirement."

QUESTION 09

What is the difference between IAM Policy and S3 Bucket Policy?

HIGH PRIORITY

Both are authorization mechanisms, but they are attached differently.

IAM Policy is attached to IAM identities such as users, groups or roles.

Bucket Policy is a resource-based policy attached directly to an S3 bucket. Bucket policies are especially useful for defining access to the bucket as a resource, including cross-account scenarios.

💡 Simple Example

An EC2 instance can use an IAM role with permissions to access an S3 bucket. Alternatively, an S3 bucket policy can explicitly allow a particular principal to perform specific actions on the bucket.

🎤 Interview Answer

"An IAM policy is an identity-based policy attached to an IAM principal, while an S3 bucket policy is a resource-based policy attached to the bucket. Both can participate in determining whether an S3 request is authorized."

QUESTION 10

What is S3 encryption?

SECURITY

S3 encryption protects object data at rest. Common server-side encryption approaches include:

SSE-S3 — encryption using S3-managed keys.
SSE-KMS — encryption using AWS Key Management Service keys, providing additional key-management and auditing capabilities.
SSE-C — the customer provides the encryption key with the request. S3 also supports client-side encryption where the data is encrypted before being uploaded.

💡 Real-Time Example

For sensitive application backups, a company may choose SSE-KMS so encryption is integrated with KMS key management and access controls.

🎤 Interview Answer

"S3 supports server-side encryption such as SSE-S3 and SSE-KMS. SSE-KMS is useful when we need AWS KMS-based key management and additional control over key usage."

QUESTION 11

What is S3 Replication?

HIGH PRIORITY

S3 Replication automatically copies objects from one S3 bucket to another bucket according to configured replication rules. Common use cases include:

• Disaster recovery
• Compliance
• Cross-region data copies
• Centralized data management

💡 Real-Time Example

A company has production data in one AWS Region and wants a copy in another Region for disaster recovery. S3 replication can be configured to copy eligible objects to the destination bucket.

🎤 Interview Answer

"S3 Replication automatically copies objects from a source bucket to a destination bucket according to replication rules. It can be used for disaster recovery, compliance and cross-region data requirements."

⭐⭐⭐ Medium Priority

QUESTION 12

What is S3 Static Website Hosting?

CONCEPT

S3 can host static website content such as HTML, CSS, JavaScript and images. Static website hosting is suitable for websites where the content does not require a server-side application running on the hosting service. For production architectures, S3 is often combined with other AWS services such as CloudFront depending on requirements.

💡 Real-Time Example

A simple portfolio website containing only HTML, CSS, JavaScript and images can be stored in S3 and served as static content.

🎤 Interview Answer

"S3 can be used to host static website content such as HTML, CSS and JavaScript files. For a production setup, we can integrate it with services such as CloudFront based on the architecture requirements."

QUESTION 13

What is S3 Transfer Acceleration?

CONCEPT

S3 Transfer Acceleration helps speed up uploads and downloads to S3 by using AWS edge locations and the AWS global network. It can be useful when users are geographically far from the S3 bucket's Region and large amounts of data need to be transferred.

💡 Real-Time Example

If users around the world need to upload large files to an S3 bucket located in one Region, Transfer Acceleration may improve transfer performance depending on network conditions.

🎤 Interview Answer

"S3 Transfer Acceleration uses AWS edge locations and the AWS global network to accelerate data transfers to and from S3, especially for geographically distributed users."

⭐⭐ Low Priority

QUESTION 14

What is an S3 presigned URL?

PRACTICAL CONCEPT

A presigned URL provides temporary access to a specific S3 object without requiring the recipient to have direct AWS credentials. The URL is generated with a defined expiration time and permissions based on the credentials and request used to generate it.

💡 Real-Time Example

A private S3 bucket contains a user's resume. Instead of making the bucket public, the application can generate a temporary presigned URL so the user can download the file.

🎤 Interview Answer

"A presigned URL provides temporary access to a specific S3 object. It allows us to share private objects without making the entire bucket public."

QUESTION 15

Does S3 have folders like a traditional filesystem?

CONCEPT

S3 is an object storage service rather than a traditional hierarchical filesystem. What appears as folders in the S3 console is based on object key prefixes. For example: 

```

app/logs/2026/08/application.log
```

Here:
app/logs/2026/08/ is a key prefix.
application.log is the object name portion.

🎤 Interview Answer

"S3 does not use traditional filesystem folders. The folder-like structure shown in the console is based on object key prefixes."

Common AWS CLI commands for S3

aws s3 ls s3://my-bucket

aws s3 cp file.txt s3://my-bucket/

aws s3 cp s3://source-bucket/file.txt s3://destination-bucket/

🎯 Real-Time S3 Scenarios

SCENARIO 01

Your application gets AccessDenied when trying to upload an object to S3. What will you check?

TROUBLESHOOTING

I would check authorization systematically.

🛠️ Troubleshooting Flow

Application → IAM Principal / Role → IAM Policy → Bucket Policy → Block Public Access / Resource Restrictions → S3 Object


I would also verify that the request is using the correct bucket, Region and credentials, and check whether encryption with KMS introduces additional permissions requirements.
🎤 Interview Answer

"For an S3 AccessDenied error, I first identify which IAM principal is making the request. Then I check its IAM permissions, the bucket policy, public-access settings and any applicable resource restrictions. If KMS encryption is involved, I also verify the required KMS permissions."

SCENARIO 02

A developer accidentally deleted an important S3 object. How can you recover it?

PRODUCTION SCENARIO

If S3 Versioning was enabled before the deletion, previous versions of the object may still be available. In a versioned bucket, a normal deletion can create a delete marker rather than immediately removing all previous versions. The exact recovery approach depends on the bucket's versioning state and lifecycle configuration.

💡 Real-Time Example

Production bucket has versioning enabled. Developer deletes: 

```

production-config.json
```

We inspect the object's versions, identify the required previous version and restore/recover it according to the application's recovery procedure.

🎤 Interview Answer

"If S3 Versioning was enabled, I would check the object's previous versions and delete markers. We can use the previous version to recover the required data."

SCENARIO 03

Your S3 bucket contains sensitive company data. The team asks you to make the bucket public for easier access. What would you do?

SECURITY SCENARIO

I would not make a sensitive bucket public simply for convenience. First I would understand the actual access requirement. If users need temporary access, a presigned URL may be appropriate. If an application needs access, an IAM role with least-privilege permissions is usually preferable. If a public website is genuinely required, I would separate public assets from sensitive data and design the access model accordingly.

🎤 Interview Answer

"I would avoid making sensitive S3 data publicly accessible. I would first identify who needs access and provide the minimum required permissions using IAM roles, bucket policies or temporary presigned URLs. I would follow the principle of least privilege."
