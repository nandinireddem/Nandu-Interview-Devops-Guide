QUESTION 01

What is AWS CLI?

⭐⭐⭐⭐⭐ MUST KNOW

AWS CLI stands for AWS Command Line Interface. It is a command-line tool that allows us to interact with AWS services using commands instead of manually using the AWS Management Console.

💡 Example

Instead of opening the S3 console and checking buckets manually, we can run: 

aws s3 ls

This lists the S3 buckets accessible using the configured AWS credentials.

🎤 Interview Answer

"AWS CLI is a command-line interface provided by AWS that allows us to manage and automate AWS resources using commands. It is useful for administration, scripting and DevOps automation."

QUESTION 02

Why do we use AWS CLI in DevOps?

⭐⭐⭐⭐⭐ VERY COMMON

AWS CLI is useful because DevOps work involves automation. Instead of performing repetitive tasks manually through the console, commands can be executed through scripts, CI/CD pipelines and automation tools.

Developer → GitHub / Jenkins → AWS CLI Commands → AWS Resources
🔥 Real-Time DevOps Example

A CI/CD pipeline can use AWS CLI to upload build artifacts to S3 or interact with ECR, ECS, EC2 and other AWS services.

🎤 Interview Answer

"In DevOps, AWS CLI helps automate AWS operations. We can use it inside shell scripts and CI/CD pipelines instead of performing repetitive tasks manually through the AWS Console."

QUESTION 03

How do you configure AWS CLI?

⭐⭐⭐⭐⭐ MUST KNOW

The commonly used command is: 

aws configure

It asks for:

→ AWS Access Key ID
→ AWS Secret Access Key
→ Default AWS Region
→ Default output format

💡 Example 
aws configure

Then configure the required values.

⚠️ Never hard-code or expose AWS access keys in GitHub repositories, source code or public files.
🎤 Interview Answer

"I can configure AWS CLI using the aws configure command, which stores the CLI configuration for the selected profile. In production automation, I prefer temporary credentials or IAM roles rather than hard-coded long-lived access keys."

QUESTION 04

How do you check whether AWS CLI is installed?

⭐⭐⭐⭐⭐ 
aws --version

This displays the installed AWS CLI version.

💡 Example 
aws --version
QUESTION 05

How do you check which AWS identity is being used?

⭐⭐⭐⭐⭐ VERY IMPORTANT

Use: 

aws sts get-caller-identity

This is one of the most useful troubleshooting commands. It tells us the AWS account and identity associated with the credentials currently being used.

🔥 Real-Time Example

Suppose Terraform or AWS CLI gives an AccessDenied error. Before changing permissions, I can verify which identity is actually being used. 

aws sts get-caller-identity
🎤 Interview Answer

"I use aws sts get-caller-identity to verify which AWS identity and account my CLI session is using. It is very useful when troubleshooting credentials or permissions."

QUESTION 06

What is an AWS CLI profile?

⭐⭐⭐⭐⭐

A profile is a named set of AWS CLI configuration and credential settings. Profiles are useful when working with multiple AWS accounts or environments.

💡 Example 
aws configure --profile dev
aws configure --profile prod

Then select a profile while running a command: 

aws s3 ls --profile dev
🎤 Interview Answer

"AWS CLI profiles allow me to maintain separate configurations for different AWS accounts or environments. I can select a specific profile using the --profile option."

QUESTION 07

What is the difference between AWS CLI and AWS Management Console?

⭐⭐⭐⭐⭐ COMMON

Both can manage AWS resources, but the method is different.

AWS Console → GUI / Browser

AWS CLI → Commands / Scripts / Automation
🎤 Interview Answer

"The AWS Management Console is a graphical interface, while AWS CLI provides command-line access. CLI is particularly useful for automation, scripting and CI/CD pipelines."

QUESTION 08

How do you specify an AWS region using CLI?

⭐⭐⭐⭐

A region can be specified directly using: 

aws ec2 describe-instances --region ap-south-1

Or a default region can be configured using: 

aws configure
💡 Example

If your resources are in Mumbai: 

aws ec2 describe-instances --region ap-south-1
QUESTION 09

What are common AWS CLI output formats?

⭐⭐⭐⭐

Common output formats include:

→ json
→ text
→ table
→ yaml / yaml-stream in supported AWS CLI versions

💡 Example 
aws ec2 describe-instances --output table
aws ec2 describe-instances --output json

QUESTION 10

How do you list EC2 instances using AWS CLI?

⭐⭐⭐⭐ 
aws ec2 describe-instances

This returns information about EC2 instances accessible to the configured identity.

QUESTION 11

How do you list S3 buckets?

⭐⭐⭐⭐⭐ 
aws s3 ls
🎤 Interview Tip

Remember the difference:

aws s3 ls → high-level S3 command

aws s3api ... → lower-level S3 API operations

QUESTION 12

What is the difference between aws s3 and aws s3api?

⭐⭐⭐⭐

aws s3 provides high-level, easier-to-use commands for common S3 operations.

aws s3api provides direct access to individual S3 API operations.

Examples 
aws s3 ls
aws s3 cp file.txt s3://my-bucket/
aws s3api list-buckets
🎤 Interview Answer

"aws s3 provides high-level S3 commands for common tasks, while aws s3api exposes individual S3 API operations and gives more direct control."

QUESTION 13

How do you upload a file to S3 using AWS CLI?

⭐⭐⭐⭐⭐ 
aws s3 cp file.txt s3://my-bucket/
💡 Example 
aws s3 cp app.zip s3://my-bucket/releases/
QUESTION 14

How do you download a file from S3?

⭐⭐⭐⭐ 
aws s3 cp s3://my-bucket/app.zip .

The dot means the current directory.

QUESTION 15

What is AWS STS?

⭐⭐⭐⭐⭐ IMPORTANT

AWS STS stands for Security Token Service. It provides temporary security credentials for AWS access.

💡 Common DevOps Use

IAM roles and temporary credentials can be used by workloads or automation systems without storing long-lived access keys directly in code.

🎤 Interview Answer

"AWS STS provides temporary security credentials. It is commonly used with IAM roles and temporary access instead of relying on long-lived credentials."

QUESTION 16

How do you get help for an AWS CLI command?

⭐⭐⭐⭐ 
aws help
aws ec2 help
aws ec2 describe-instances help

The CLI documentation built into the command can help identify syntax, options and parameters.

QUESTION 17

How can AWS CLI output be filtered?

⭐⭐⭐⭐

AWS CLI supports options such as --query for JMESPath expressions.

💡 Example 
aws ec2 describe-instances \
```

--query "Reservations[].Instances[].InstanceId"
```

This extracts instance IDs instead of displaying the entire response.

🎤 Interview Answer

"I use the --query option with JMESPath expressions to extract only the required fields from AWS CLI output."

QUESTION 18

What is the difference between --query and --filter?

⭐⭐⭐⭐

They work at different levels.

--filters are service-specific request filters that can limit resources returned by the AWS API.

--query processes the returned response using JMESPath and extracts the information you need.

Easy memory:

Filter → Ask AWS for fewer resources.
Query → Select fields from the response.

⭐⭐⭐ Medium Priority

QUESTION 19

Where does AWS CLI store configuration?

⭐⭐⭐

AWS CLI commonly uses configuration files under the user's AWS directory. On Linux/macOS: 

~/.aws/

Common files include: 

~/.aws/config
```

~/.aws/credentials
```

On Windows, the AWS directory is typically under the user's profile directory.

QUESTION 20

What is the AWS_DEFAULT_REGION environment variable?

⭐⭐⭐

It can be used to provide a default AWS region to AWS SDKs and CLI behavior where applicable.

Linux/macOS 
export AWS_DEFAULT_REGION=ap-south-1
PowerShell 
$env:AWS_DEFAULT_REGION="ap-south-1"
QUESTION 21

What is the difference between AWS CLI and SDK?

⭐⭐⭐

AWS CLI is a command-line tool used by users and scripts. AWS SDKs are software libraries that developers use inside applications written in supported programming languages.

🎤 Interview Answer

"AWS CLI is mainly used from the command line and automation scripts, while AWS SDKs allow application code to interact programmatically with AWS services."

QUESTION 22

How do you delete an S3 object using CLI?

⭐⭐⭐ 
aws s3 rm s3://my-bucket/file.txt

To remove objects recursively from a prefix: 

aws s3 rm s3://my-bucket/folder/ --recursive
⚠️ Always verify the bucket and path before using recursive delete commands.

⭐⭐ Less Frequently Asked

QUESTION 23

What is the AWS CLI --dry-run option?

⭐⭐

Some AWS CLI operations support --dry-run to test whether the command would succeed without actually performing the requested operation. 

aws ec2 run-instances --dry-run ...

The exact behavior depends on the API operation.

QUESTION 24

What is pagination in AWS CLI?

⭐⭐

Some AWS APIs return large result sets in multiple pages. AWS CLI generally handles pagination automatically, but pagination behavior can be controlled with CLI options such as: 

--no-paginate
💡 Why useful?

When troubleshooting or scripting, controlling pagination can make output easier to process.

🎯 Real-Time Interview Scenarios

SCENARIO 01

AWS CLI says AccessDenied. How will you troubleshoot?

⭐⭐⭐⭐⭐ VERY IMPORTANT

I would troubleshoot systematically.

Step 1: Check the current identity. 

aws sts get-caller-identity

Step 2: Check which profile/credentials are being used.

Step 3: Verify the IAM policy permissions.

Step 4: Check resource policies such as S3 bucket policies where applicable.

Step 5: Check region and resource ARN.

🎤 Strong Interview Answer

"First I would run aws sts get-caller-identity to confirm which identity is being used. Then I would check the IAM permissions, resource policy, resource ARN and region. I would also verify that the CLI is using the expected profile or role."

SCENARIO 02

You have Dev and Production AWS accounts. How would you manage them using CLI?

⭐⭐⭐⭐⭐

I would use separate AWS CLI profiles or, preferably in production environments, role-based access with appropriate identity management. 

aws configure --profile dev
aws configure --profile prod

Then: 

aws ec2 describe-instances --profile dev
aws ec2 describe-instances --profile prod
🎤 Strong Interview Answer

"For separate environments I can use named CLI profiles, but for production I prefer role-based access and temporary credentials rather than storing long-lived access keys."

SCENARIO 03

Your command is working in one region but not another. What will you check?

⭐⭐⭐⭐

I would check:

→ Current/default region
→ Explicit --region
→ Whether the resource exists in that region
→ IAM permissions
→ Resource-specific regional behavior 

aws ec2 describe-instances --region ap-south-1
SCENARIO 04

Your Jenkins pipeline needs to upload a build artifact to S3. How would you do it securely?

⭐⭐⭐⭐⭐ DEVOPS SCENARIO
Git Push → Jenkins → Build → AWS Authentication → AWS CLI → S3

I would avoid storing AWS access keys directly inside the Jenkinsfile. Instead, I would use an appropriate IAM role or secure credential mechanism with least-privilege permissions. 

aws s3 cp build.zip s3://my-bucket/releases/
🎤 Strong Interview Answer

"I would integrate Jenkins with AWS using a secure IAM-based authentication mechanism and least privilege. The pipeline can then use AWS CLI to upload the artifact to the required S3 bucket without hard-coding credentials in the Jenkinsfile."
