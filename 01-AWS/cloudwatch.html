QUESTION 01

What is Amazon CloudWatch?

⭐⭐⭐⭐⭐ MUST KNOW

Amazon CloudWatch is an AWS monitoring and observability service. It helps us monitor AWS resources, applications and infrastructure by collecting and analyzing metrics, logs and other operational data.

💡 Simple Example

Suppose we have an EC2 server running our application. We can use CloudWatch to monitor things such as:

→ CPU utilization
→ Network activity
→ Status-related metrics
→ Application logs

🎤 Interview Answer

"Amazon CloudWatch is an AWS monitoring and observability service used to collect metrics and logs, create alarms and dashboards, and monitor the health and performance of AWS resources and applications."

QUESTION 02

What are the main components of CloudWatch?

⭐⭐⭐⭐⭐ VERY COMMON

Important CloudWatch concepts include:

📊 Metrics
📝 Logs
🚨 Alarms
📈 Dashboards
⚡ Events / EventBridge integration
📋 Logs Insights

AWS Resources / Applications → CloudWatch → Metrics + Logs → Alarms / Dashboards / Actions
🎤 Interview Answer

"The major CloudWatch capabilities I use are metrics, logs, alarms, dashboards and log analysis. These help monitor infrastructure and applications and trigger actions when defined conditions occur."

QUESTION 03

What is a CloudWatch Metric?

⭐⭐⭐⭐⭐ MUST KNOW

A metric is a time-ordered set of data points used to measure the performance or behavior of a resource or application.

💡 EC2 Example

EC2 can publish metrics such as:

→ CPUUtilization
→ NetworkIn
→ NetworkOut

Easy memory:

Metric = numerical measurement.

Example: CPU utilization = 82%
🎤 Interview Answer

"A CloudWatch metric is a time-series measurement used to monitor the performance or health of a resource. For example, EC2 CPUUtilization is a CloudWatch metric."

QUESTION 04

What is a CloudWatch Alarm?

⭐⭐⭐⭐⭐ VERY IMPORTANT

A CloudWatch Alarm watches a metric and performs an action when the metric crosses a defined threshold for a specified evaluation period.

Metric → Threshold → Alarm → Action
🔥 Real-Time Example

Suppose an EC2 instance has CPU utilization above 80%. We can create an alarm that changes state when the configured condition remains true.

🎤 Interview Answer

"A CloudWatch alarm monitors a metric against a configured threshold and changes state when the condition is met. It can then be used to trigger an action such as an SNS notification or an Auto Scaling-related action."

QUESTION 05

What are the states of a CloudWatch Alarm?

⭐⭐⭐⭐⭐ COMMON

A CloudWatch alarm has three main states:

🟢 OK
The metric is within the configured condition.

🔴 ALARM
The configured alarm condition has been met.

⚪ INSUFFICIENT_DATA
There is not enough data to determine the state.

🎤 Interview Answer

"The three CloudWatch alarm states are OK, ALARM and INSUFFICIENT_DATA."

QUESTION 06

What is CloudWatch Logs?

⭐⭐⭐⭐⭐ MUST KNOW

CloudWatch Logs provides centralized collection and monitoring of log data from applications, services and AWS resources.

💡 Example

Application logs from an EC2-hosted application can be sent to CloudWatch Logs and then searched and analyzed.

🎤 Interview Answer

"CloudWatch Logs allows us to collect, store and analyze log data from applications and AWS resources. It is useful for troubleshooting application and infrastructure issues."

QUESTION 07

What is a Log Group and Log Stream?

⭐⭐⭐⭐⭐ IMPORTANT

A Log Group is a collection of log streams that share the same retention, monitoring and access-control settings.

A Log Stream is a sequence of log events from the same source or related source.

Log Group → Log Stream 1
→ Log Stream 2
→ Log Stream 3
Easy memory:

Log Group = container/category
Log Stream = individual sequence of logs
QUESTION 08

What is a CloudWatch Dashboard?

⭐⭐⭐⭐

A CloudWatch Dashboard provides a visual representation of metrics and monitoring information in one place.

🔥 DevOps Example

A dashboard can display:

EC2 CPU
Application metrics
ALB metrics
Database metrics
Error-related metrics

QUESTION 09

What is the difference between CloudWatch Metrics and Logs?

⭐⭐⭐⭐⭐ VERY COMMON
Metrics → numbers used for monitoring.

Logs → detailed event records.
Example

Metric:
CPU = 90%

Log:
"Application failed to connect to database."

🎤 Interview Answer

"Metrics provide numerical time-series data for monitoring performance, while logs contain detailed records of application or system events. Metrics are useful for thresholds and alarms, while logs are useful for troubleshooting."

⭐⭐⭐⭐ Frequently Asked

QUESTION 10

How do you monitor an EC2 instance using CloudWatch?

⭐⭐⭐⭐⭐ DEVOPS QUESTION

EC2 publishes standard monitoring metrics to CloudWatch. We can view these metrics, create alarms and build dashboards.

EC2 → CloudWatch Metrics → Alarm → SNS / Auto Scaling / Action
🔥 Example

Create an alarm when average CPU utilization remains above a defined threshold.

🎤 Interview Answer

"I monitor EC2 through CloudWatch metrics such as CPU utilization and network metrics. I can create alarms on those metrics and use dashboards for visualization."

QUESTION 11

What is the difference between Basic and Detailed Monitoring for EC2?

⭐⭐⭐⭐

EC2 basic monitoring provides metrics at a lower frequency, while detailed monitoring provides more frequent monitoring data.

Interview memory:

Basic → 5-minute monitoring
Detailed → 1-minute monitoring

Availability and pricing should be considered when choosing monitoring options.
QUESTION 12

What is CloudWatch Agent?

⭐⭐⭐⭐⭐ IMPORTANT

The CloudWatch Agent is software that can collect additional system-level metrics and logs from servers.

💡 Why do we need it?

Standard EC2 monitoring does not provide every operating-system-level metric. For example, you may want to monitor memory utilization or collect application/system logs. The CloudWatch Agent can be configured for this.

🎤 Interview Answer

"The CloudWatch Agent is installed on supported servers when we need additional system metrics or log collection beyond the default metrics provided by the service."

QUESTION 13

What is CloudWatch Logs Insights?

⭐⭐⭐⭐

CloudWatch Logs Insights is used to interactively query and analyze log data stored in CloudWatch Logs.

🔥 Real-Time Example

If an application is returning many errors, Logs Insights can help search the logs and identify patterns.

🎤 Interview Answer

"CloudWatch Logs Insights provides a query-based way to search and analyze CloudWatch log data, which is useful during troubleshooting and incident analysis."

QUESTION 14

Can CloudWatch send notifications?

⭐⭐⭐⭐⭐

Yes. CloudWatch alarms can integrate with services such as Amazon SNS to send notifications.

CloudWatch Metric → Alarm → SNS → Notification
Example

If an EC2 CPU alarm enters ALARM state, an SNS topic can be used to notify subscribed endpoints.

QUESTION 15

What is the difference between CloudWatch and CloudTrail?

⭐⭐⭐⭐⭐ VERY COMMON
CloudWatch → Monitoring and observability.

CloudTrail → API activity and account activity auditing.
Easy Example

CloudWatch:
"Why is my EC2 CPU high?"

CloudTrail:
"Who performed this AWS API action?"

🎤 Interview Answer

"CloudWatch is primarily used for monitoring metrics, logs and application or infrastructure health. CloudTrail records AWS API activity and is mainly used for auditing and tracking actions performed in an AWS account."

QUESTION 16

What is a custom CloudWatch metric?

⭐⭐⭐⭐

A custom metric is application or system monitoring data that you publish to CloudWatch yourself.

💡 Example

Suppose your application has a metric called:

OrdersProcessed

Your application can publish that metric to CloudWatch for monitoring.

⭐⭐⭐ Medium Priority

QUESTION 17

What are CloudWatch dimensions?

⭐⭐⭐

Dimensions are name/value pairs that identify and distinguish metrics.

Example

An EC2 CPU metric can be associated with dimensions such as the instance identifier.

QUESTION 18

What is metric namespace?

⭐⭐⭐

A namespace is a container used to organize metrics. AWS services publish metrics into service-specific namespaces, and custom applications can use custom namespaces.

💡 Memory Trick

Namespace → Category
Metric → Measurement
Dimension → Identifier

QUESTION 19

What is metric retention in CloudWatch?

⭐⭐⭐

CloudWatch retains metric data for different periods depending on the resolution and age of the data. Older high-resolution data is aggregated into lower resolution periods over time.

For interviews, understand the main idea:

CloudWatch does not keep every metric data point forever at its original resolution.
QUESTION 20

What is an alarm threshold?

⭐⭐⭐

A threshold is the value or condition against which a monitored metric is evaluated.

Example 
CPUUtilization > 80%

If the configured evaluation criteria are met, the alarm can enter the ALARM state.

⭐⭐ Less Frequently Asked

QUESTION 21

What is high-resolution monitoring in CloudWatch?

⭐⭐

CloudWatch supports high-resolution custom metrics with shorter periods than standard one-minute metrics. These are useful when applications need more granular monitoring.

QUESTION 22

What is CloudWatch anomaly detection?

⭐⭐

CloudWatch anomaly detection uses statistical modeling to identify expected metric behavior and can help identify values outside the expected pattern.

Example

Instead of using only a fixed CPU threshold, anomaly detection can help identify unusual behavior based on historical patterns.

QUESTION 23

What is CloudWatch Contributor Insights?

⭐ BONUS

Contributor Insights helps identify top contributors to patterns in time-series data, such as the sources generating the most traffic or other activity.

🎯 Real-Time Interview Scenarios

SCENARIO 01

Your EC2 server CPU suddenly reaches 95%. What will you do?

⭐⭐⭐⭐⭐ VERY IMPORTANT

First, I would verify the CloudWatch CPU metric and understand when the increase started. Then I would correlate the metric with application logs and other infrastructure metrics.

CPU Spike → CloudWatch Metric → Check Logs → Identify Cause → Take Action
Possible causes

→ Traffic increase
→ Application process consuming CPU
→ Background job
→ Resource sizing issue
→ Unexpected workload

🎤 Strong Interview Answer

"I would first verify the CPU metric in CloudWatch and identify the time of the spike. Then I would check application and system logs, traffic metrics and running processes to determine the root cause. Based on the cause, I may optimize the application, scale the workload or increase capacity."

SCENARIO 02

You want an alert whenever EC2 CPU goes above 80%. How will you implement it?

⭐⭐⭐⭐⭐
EC2 → CPUUtilization → CloudWatch Alarm → SNS → Notification

I would create a CloudWatch alarm on the CPUUtilization metric with the required threshold and evaluation period, and configure an appropriate action such as SNS notification.

🎤 Interview Answer

"I would create a CloudWatch alarm on the EC2 CPUUtilization metric. I would configure the threshold and evaluation period and connect the alarm to SNS so the required team or endpoint is notified when the alarm enters ALARM state."

SCENARIO 03

Your application is failing, but CPU and memory look normal. What will you check?

⭐⭐⭐⭐⭐

I would not assume the infrastructure is healthy just because CPU is normal. I would check:

→ Application logs
→ CloudWatch Logs
→ Logs Insights
→ Load Balancer metrics
→ Error rates
→ Database connectivity
→ Recent deployments/configuration changes

🎤 Strong Interview Answer

"I would correlate infrastructure metrics with application logs. Normal CPU does not necessarily mean the application is healthy. I would use CloudWatch Logs and Logs Insights to identify errors and correlate them with recent deployments, dependencies and traffic."

SCENARIO 04

How would you monitor an application running on multiple EC2 instances?

⭐⭐⭐⭐

I would centralize application logs in CloudWatch Logs, monitor infrastructure metrics, create CloudWatch dashboards and configure alarms for important conditions.

EC2-1 ─┐
EC2-2 ─┼→ CloudWatch → Dashboard / Alarms
EC2-3 ─┘
SCENARIO 05

CloudWatch Alarm is showing INSUFFICIENT_DATA. What does it mean?

⭐⭐⭐⭐

It means CloudWatch does not currently have enough information to determine whether the alarm condition is true or false. I would investigate whether the metric is being published correctly and whether there is enough recent data.

🎤 Interview Answer

"INSUFFICIENT_DATA means the alarm does not have enough metric data to determine its state. I would check whether the metric is being published and whether the configured evaluation period and data points are appropriate."

🛠️ Useful CloudWatch CLI Commands

List CloudWatch alarms

aws cloudwatch describe-alarms

List metric information

aws cloudwatch list-metrics

Get metric statistics

aws cloudwatch get-metric-statistics

Describe alarm history

aws cloudwatch describe-alarm-history

List dashboards

aws cloudwatch list-dashboards

Describe dashboard

aws cloudwatch get-dashboard --dashboard-name MyDashboard

List log groups

aws logs describe-log-groups

List log streams

aws logs describe-log-streams --log-group-name MyLogGroup

Start a Logs Insights query

aws logs start-query
