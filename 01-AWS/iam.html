QUESTION 01

What is AWS IAM?

MOST FREQUENTLY ASKED

IAM stands for Identity and Access Management. AWS IAM is a service used to control who can access AWS resources and what actions they are allowed to perform. In simple words:

IAM = Authentication + Authorization + Access Control

Authentication answers:
"Who are you?"

Authorization answers:
"What are you allowed to do?"

👤 Identity → 🔐 IAM → 📜 Policy → ☁️ AWS Resource
User / Role → Permission → Action
💡 Real-Time Example

Suppose a DevOps engineer needs to restart an EC2 instance. We should not give unrestricted administrator permissions just because the engineer needs EC2 access. Instead, we can provide only the required permissions according to the job requirement.

🎤 Interview Answer

"AWS IAM is a service used to securely control authentication and authorization for AWS resources. It allows us to create identities, define permissions using policies and provide users or workloads only the access they require."

  • What is an IAM Role?
  • What is an IAM Policy?
  • User vs Role?
  • What is least privilege?
QUESTION 02

What are the main components of IAM?

MUST KNOW

The important IAM concepts are:

👤 Users — identities generally representing people or applications that need long-term credentials.

👥 Groups — collections of IAM users used to manage permissions for multiple users.

🎭 Roles — identities with permissions that can be assumed by trusted principals such as AWS services, users or federated identities.

📜 Policies — documents that define permissions.

👤 USER + 👥 GROUP + 🎭 ROLE + 📜 POLICY ↓ 🔐 PERMISSIONS
🎤 Interview Answer

"The main IAM concepts are users, groups, roles and policies. Users represent identities, groups help organize users and permissions, roles provide assumable permissions, and policies define what actions are allowed or denied."

QUESTION 03

What is an IAM User?

VERY COMMON

An IAM User is an identity created in an AWS account. A user can have credentials and permissions assigned through IAM policies. Historically, IAM users are commonly used for individual people or specific long-term credentials, although AWS generally recommends temporary credentials and federation where appropriate.

💡 Example

Imagine a company has a developer who needs to work with AWS. The organization can use centralized identity federation or other appropriate access mechanisms. If an IAM user is used, its permissions should follow least privilege and MFA should be enabled where applicable.

🎤 Interview Answer

"An IAM user is an identity in an AWS account that can be granted permissions to access AWS resources. For human access, organizations often prefer federation and temporary credentials, while IAM users can still be used for specific requirements."

QUESTION 04

What is an IAM Group?

VERY COMMON

An IAM Group is a collection of IAM users. Groups help simplify permission management. Instead of attaching the same policy individually to ten developers, we can put the users into a group and attach the required permissions to that group.

👤 Developer 1 ↘ 👥 DevOps Group ↗ 👤 Developer 2
DevOps Group → 📜 Required Policies
💡 Real-Time Example

Suppose 20 developers need read-only access to CloudWatch. Instead of managing 20 users separately, we can create a Developers group and attach the required policy to that group.

🎤 Interview Answer

"An IAM group is a collection of IAM users. Groups allow us to manage common permissions for multiple users centrally."

QUESTION 05

What is an IAM Role?

⭐⭐⭐⭐⭐ VERY IMPORTANT

An IAM Role is an identity that defines a set of permissions that can be assumed by a trusted principal. Unlike a typical IAM user access-key setup, a role does not require permanent credentials to be embedded in the workload. Roles are heavily used in DevOps and cloud architectures.

🖥️ EC2 → 🎭 IAM Role → 🔐 Temporary Credentials → 🪣 S3
💡 Most Important DevOps Example

Suppose an EC2 server needs to download files from S3. A bad approach is to put an IAM user's access key and secret key inside the EC2 server. A better approach is:

EC2 → IAM Role → S3 permissions.

AWS provides temporary credentials to the workload through the role.

🎤 Interview Answer

"An IAM role is an identity with permissions that can be assumed by trusted principals. Roles are commonly used by AWS services and workloads such as EC2 because they provide temporary credentials instead of requiring long-term access keys to be stored on the server."

🔎 Interviewer May Ask
  • Why use a role instead of access keys?
  • How does EC2 get credentials from a role?
  • What is a trust policy?
  • What is sts:AssumeRole?
QUESTION 06

What is an IAM Policy?

⭐⭐⭐⭐⭐ MUST KNOW

An IAM Policy is a JSON document that defines permissions. It answers questions such as:

What action?
On which resource?
Is it allowed or denied?

A policy commonly contains:
Effect → Allow or Deny
Action → API operation
Resource → AWS resource
Condition → Optional conditions

💡 Simple Policy Structure 
```

{
"Effect": "Allow",
"Action": "s3:GetObject",
"Resource": "arn:aws:s3:::my-bucket/*"
}
```

This example grants permission to retrieve objects from the specified S3 bucket path.

🎤 Interview Answer

"An IAM policy is a JSON-based permission document that defines which actions are allowed or denied on which AWS resources, optionally under specific conditions."

QUESTION 07

What is the difference between Authentication and Authorization?

BASIC BUT VERY IMPORTANT

Authentication means verifying identity.

It answers:
"Who are you?"

Authorization means determining permissions.

It answers:
"What are you allowed to do?"

💡 Easy Example

Logging into AWS with valid credentials:
→ Authentication

Being allowed to launch an EC2 instance:
→ Authorization

🎤 Interview Answer

"Authentication verifies who the identity is, while authorization determines what that authenticated identity is permitted to do."

⭐⭐⭐⭐ High Priority

QUESTION 08

What is the difference between IAM User and IAM Role?

VERY FREQUENT INTERVIEW QUESTION
👤 IAM User → Long-term identity

🎭 IAM Role → Assumable identity → Temporary credentials

An IAM User is a persistent identity within an AWS account. An IAM Role is an identity that can be assumed by a trusted principal and is commonly used to provide temporary credentials. In modern cloud architectures, roles are especially important for workloads and federated human access.

💡 DevOps Example

Developer workstation:
Use appropriate federated/temporary access.

EC2 → S3:
Attach an IAM role to EC2 rather than storing long-term access keys on the server.

🎤 Interview Answer

"An IAM user is a persistent identity, while an IAM role is an assumable identity that provides temporary credentials. Roles are preferred for AWS workloads because they avoid embedding long-term access keys in servers or applications."

QUESTION 09

What is the Principle of Least Privilege?

⭐⭐⭐⭐⭐ SECURITY

Least privilege means giving an identity only the permissions it actually needs to perform its task. We should avoid giving unnecessary permissions. For example:

If an application only needs to read S3 objects, giving it:
s3:GetObject is better than giving:
AdministratorAccess

💡 Real-Time DevOps Example

A CI/CD pipeline only needs permission to push images to a specific ECR repository. Instead of giving the pipeline full AWS AdministratorAccess, create permissions only for the required ECR actions and resources.

🎤 Interview Answer

"The principle of least privilege means providing only the minimum permissions required to perform a specific task. It reduces the potential impact of compromised credentials or applications."

QUESTION 10

What is a Trust Policy?

⭐⭐⭐⭐ IMPORTANT

A role has two important permission concepts:

Trust Policy → defines who can assume the role.

Permissions Policy → defines what the role can do after it is assumed.

WHO CAN ASSUME? → 🤝 Trust Policy

WHAT CAN THEY DO? → 📜 Permissions Policy
💡 EC2 Example

EC2 needs to use an IAM role. The role's trust relationship allows the EC2 service principal to assume the role. The permissions policy then determines what the role can do, for example access S3.

🎤 Interview Answer

"The trust policy of an IAM role defines which principals are allowed to assume the role. The permissions policy defines what actions the role can perform after it is assumed."

QUESTION 11

What is MFA in AWS?

SECURITY

MFA stands for Multi-Factor Authentication. It adds another authentication factor in addition to the primary credential. This provides an additional security layer if a password or credential is compromised.

💡 Example

Password alone:
❌ One factor

Password + authenticator-based MFA:
✅ Additional factor

🎤 Interview Answer

"MFA adds an additional authentication factor to strengthen account security. It is an important control for protecting privileged human access."

QUESTION 12

What is AWS STS?

HIGH PRIORITY

AWS STS stands for Security Token Service. It provides temporary security credentials that can be used to access AWS resources. STS is heavily involved when a principal assumes an IAM role.

👤 Principal → AWS STS → 🎫 Temporary Credentials → ☁️ AWS Service
💡 DevOps Example

A deployment system assumes an IAM role. STS provides temporary credentials. The deployment system then uses those temporary credentials to interact with AWS.

🎤 Interview Answer

"AWS STS is a service that provides temporary security credentials. It is commonly used with IAM roles and role assumption to provide short-lived access to AWS resources."

⭐⭐⭐ Medium Priority

QUESTION 13

What is a managed policy?

CONCEPT

Managed policies are standalone IAM policies that can be attached to multiple identities. There are two broad types:

AWS Managed Policies
Created and maintained by AWS.

Customer Managed Policies
Created and managed by the customer.

🎤 Interview Answer

"Managed policies are standalone IAM policies that can be attached to multiple identities. AWS managed policies are maintained by AWS, while customer managed policies are created and maintained by the organization."

QUESTION 14

What is an inline policy?

MEDIUM

An inline policy is a policy embedded directly into a single IAM identity such as a user or role. It has a one-to-one relationship with that identity. Inline policies can be useful when the permission should be tightly coupled to one identity, although customer managed policies are often easier to reuse and manage centrally.

🎤 Interview Answer

"An inline policy is embedded directly into a specific IAM identity and has a one-to-one relationship with that identity."

QUESTION 15

What is an ARN?

COMMON

ARN stands for Amazon Resource Name. It uniquely identifies many AWS resources.

💡 Example 
```

arn:aws:s3:::my-bucket/*
```

IAM policies can use ARNs to specify which resources permissions apply to.

🎤 Interview Answer

"An ARN is an Amazon Resource Name used to uniquely identify AWS resources and is commonly used in IAM policies to specify resource-level permissions."

QUESTION 16

What is IAM Access Analyzer?

SECURITY

IAM Access Analyzer helps identify resources that are accessible from outside an intended trust boundary. It can help identify unintended external access and assist with analyzing and validating policies.

🎤 Interview Answer

"IAM Access Analyzer helps identify unintended external access to AWS resources and assists with analyzing resource policies."

QUESTION 17

What happens if an IAM policy has both Allow and Deny?

INTERVIEW TRICK

An explicit Deny overrides an Allow. This is one of the most important IAM evaluation concepts.

Allow + Explicit Deny ↓ ❌ DENIED
💡 Example

Suppose a user receives:

Policy A → Allow S3 access
Policy B → Explicitly Deny access to a specific bucket

The explicit Deny wins for the request covered by that Deny.

🎤 Interview Answer

"In IAM policy evaluation, an explicit Deny overrides an Allow."

🎯 Real-Time DevOps Scenarios

SCENARIO 01

An EC2 instance needs access to S3. How would you provide access securely?

⭐⭐⭐⭐⭐ VERY IMPORTANT

I would create an IAM role with the minimum required S3 permissions and attach that role to the EC2 instance. I would avoid storing long-term access keys directly on the EC2 server.

EC2 → IAM Role → Temporary Credentials → S3
🎤 Interview Answer

"I would attach an IAM role to the EC2 instance and grant the role only the required S3 permissions. This avoids storing long-term access keys on the server and follows least privilege."

SCENARIO 02

Your application is getting AccessDenied when calling an AWS API. How do you troubleshoot?

⭐⭐⭐⭐⭐ PRODUCTION QUESTION

I would troubleshoot from identity to permission. First identify the principal making the API call. Then check:

1. Which IAM user or role is being used?
2. Does the identity have the required action?
3. Is the resource ARN correct?
4. Are there conditions restricting access?
5. Is there an explicit Deny?
6. Are SCPs or permissions boundaries involved?
7. Is the request coming from the expected account, Region or network context?

🎤 Interview Answer

"For AccessDenied, I first identify the principal and API operation. Then I review identity and resource policies, resource ARNs, conditions and explicit Denies. In an organization, I would also check controls such as SCPs and permissions boundaries."

SCENARIO 03

A developer stored AWS access keys inside GitHub. What would you do immediately?

🚨 SECURITY INCIDENT

I would treat the credentials as compromised. The immediate priority is to stop unauthorized use and then investigate. Depending on the credential type and setup, I would revoke or deactivate the exposed credentials, investigate CloudTrail activity, rotate credentials where applicable, remove the secret from the repository/history as appropriate, and move the workload toward short-lived credentials such as IAM roles or OIDC-based federation.

🚨 Exposed Secret → 🔒 Revoke / Rotate → 🔎 Investigate CloudTrail → 🧹 Remove Secret → 🛡️ Use Short-Lived Credentials
🎤 Interview Answer

"I would treat the exposed credentials as compromised. I would immediately revoke or rotate them, investigate usage through logging, remove the secret from the source-control workflow, and replace long-lived credentials with short-lived role or OIDC-based authentication wherever possible."

SCENARIO 04

Why should we avoid giving AdministratorAccess to a CI/CD pipeline?

DEVSECOPS

Because a CI/CD pipeline is an automated workload. If its credentials are compromised, AdministratorAccess could allow an attacker to modify or delete a large portion of the AWS environment. The safer design is to give the pipeline only the permissions required for its deployment task.

💡 Example

If the pipeline only deploys to ECS and pushes images to ECR, it should not automatically receive permissions to modify unrelated IAM, billing, networking or production resources.

🎤 Interview Answer

"CI/CD pipelines should follow least privilege. Giving AdministratorAccess increases the blast radius if the pipeline credentials or runner are compromised. I would create a deployment role containing only the required permissions."
