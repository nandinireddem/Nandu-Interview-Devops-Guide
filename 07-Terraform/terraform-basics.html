⭐⭐⭐⭐⭐ 1. What is Terraform?

Terraform is an Infrastructure as Code (IaC) tool used to define, provision and manage infrastructure using declarative configuration files. It can manage resources across cloud providers and many other platforms through providers.
Interview answer: "Terraform is a declarative Infrastructure as Code tool. We define the desired infrastructure in configuration files, and Terraform creates and manages the required resources by comparing the desired state with the current state."

⭐⭐⭐⭐⭐ 2. Why Terraform?

  • Infrastructure can be managed as code.
  • Infrastructure changes can be version controlled.
  • Reduces manual configuration.
  • Provides repeatable infrastructure.
  • Supports multiple providers.
  • Supports planning before applying changes.
  • Helps maintain consistent environments.
  • Supports reusable modules.
Real-time: A company needs the same VPC architecture in Dev, QA and Production. Instead of manually creating resources three times, the team creates Terraform code once and supplies environment-specific variables.

⭐⭐⭐⭐⭐ 3. What is Infrastructure as Code?

Infrastructure as Code means defining infrastructure using machine-readable configuration files instead of manually creating resources through a graphical console.
Manual Infrastructure Infrastructure as Code
Manual console operations Configuration files
Difficult to reproduce exactly Repeatable
Harder to review changes Can use Git
Higher chance of human error Automation reduces manual work

⭐⭐⭐⭐⭐ 4. Declarative vs Imperative

Terraform is primarily declarative. You describe what the desired final infrastructure should look like, rather than writing every individual command required to create it.
Example: Instead of saying: "Create subnet → then create route table → then attach route table" Terraform configuration declares the desired resources and their relationships. Terraform determines the actions needed to reach that state.

⭐⭐⭐⭐⭐ 5. Terraform Architecture

Terraform Core reads configuration, state and dependency information and determines the required changes.

Provider acts as the integration layer between Terraform and an external platform such as AWS, Azure or GCP.

⭐⭐⭐⭐⭐ 6. What is a Provider?

A provider is a Terraform plugin that allows Terraform to interact with an external API or platform.

AWS Provider Example

terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 6.0"
    }
  }
}

provider "aws" {
  region = "ap-south-1"
}
Here Terraform uses the AWS provider to communicate with AWS APIs and manage resources such as VPCs, EC2 instances, IAM resources and many others.

⭐⭐⭐⭐⭐ 7. What is a Resource?

A resource represents an infrastructure object that Terraform creates, updates or manages.

Example

resource "aws_s3_bucket" "app_bucket" {

  bucket = "my-company-demo-bucket"

}
Here: aws_s3_bucket = resource type
app_bucket = local Terraform name

⭐⭐⭐⭐⭐ 10. terraform init

terraform init initializes the working directory. It downloads required providers and prepares Terraform for further operations. 
terraform init
When do you run it? Usually when starting a Terraform project, after changing provider requirements, or when initializing a copied/cloned configuration.

⭐⭐⭐⭐⭐ 11. terraform validate

Validates the syntax and internal consistency of Terraform configuration. 
terraform validate
It helps detect configuration problems before creating infrastructure.

⭐⭐⭐⭐⭐ 12. terraform plan

Terraform plan shows the proposed changes before Terraform applies them. It compares the configuration and current state and determines what actions are required. 
terraform plan
Real-time: Before production deployment, a DevOps engineer runs terraform plan and reviews whether Terraform will create, modify or destroy important resources.

⭐⭐⭐⭐⭐ 13. terraform apply

Terraform apply executes the planned changes and creates, updates or destroys infrastructure as required. 
terraform apply

Terraform normally asks for confirmation before applying changes unless automatic approval is explicitly provided.

⭐⭐⭐⭐⭐ 14. terraform destroy

Terraform destroy removes resources managed by the current Terraform configuration and state. 
terraform destroy
Never blindly run terraform destroy against a production workspace or state. Review the proposed changes carefully.

⭐⭐⭐⭐⭐ 15. Variables

Variables make Terraform configurations reusable by allowing values to be supplied from outside the resource definition.

variables.tf

variable "aws_region" {
  description = "AWS region"
  type        = string
  default     = "ap-south-1"
}

Usage

provider "aws" {
  region = var.aws_region
}

⭐⭐⭐⭐⭐ 16. terraform.tfvars

A .tfvars file can provide values for Terraform input variables. 
aws_region = "ap-south-1"

project_name = "nandu-project"

instance_type = "t3.micro"
The same Terraform code can use different variable values for different environments.

⭐⭐⭐⭐⭐ 17. Outputs

Outputs expose useful values from Terraform after resources are created. 
output "instance_public_ip" {
  description = "Public IP of EC2 instance"
  value       = aws_instance.app.public_ip
}
In a real project, outputs can expose values such as load balancer DNS names, VPC IDs, subnet IDs or instance addresses.

⭐⭐⭐⭐⭐ 18. Terraform State

Terraform state records information about resources Terraform manages and helps Terraform determine the relationship between configuration and real infrastructure. The default local state file is: terraform.tfstate
Terraform state can contain sensitive information depending on the resources being managed. Do not casually commit terraform.tfstate to Git.

⭐⭐⭐⭐⭐ 19. Why is Terraform State Important?

Terraform uses state to understand what resources it manages and to determine what changes are required during planning. Without correct state management, collaboration and infrastructure tracking become difficult.
Terraform Configuration
+
Terraform State
+
Real Infrastructure
↓
Terraform Plan

⭐⭐⭐⭐⭐ 20. Local State vs Remote State

Local State Remote State
Stored on local machine. Stored in shared remote backend.
Simple for learning. Better suited for team collaboration.
Risk of loss if not backed up. Can provide centralized storage and locking depending on backend.
For a production team, remote state is generally preferred so team members and CI/CD systems can work with a shared source of Terraform state.

⭐⭐⭐⭐⭐ 21. Terraform Backend

A backend determines where Terraform state is stored and, depending on the backend, how state locking and related operations are handled.

AWS S3 Backend Example

terraform {
  backend "s3" {
    bucket = "company-terraform-state"
    key    = "prod/terraform.tfstate"
    region = "ap-south-1"
  }
}
The exact backend configuration should follow your organization's current Terraform and AWS design, including appropriate state protection and locking strategy.

⭐⭐⭐⭐⭐ 22. What is Idempotency?

Idempotency means repeatedly applying the same desired configuration should not continuously create duplicate resources. Terraform checks the current state and determines whether changes are actually required.
If an EC2 instance already matches the Terraform configuration, running plan/apply again should normally result in no unnecessary change.

⭐⭐⭐⭐⭐ 23. Dependency Management

Terraform builds a dependency graph to determine the order in which resources should be created, changed or destroyed.

Implicit dependency

resource "aws_subnet" "app" {
  vpc_id = aws_vpc.main.id
}

Terraform understands that the subnet depends on the VPC because the VPC ID is referenced.

Explicit dependency

resource "aws_instance" "app" {

  depends_on = [
    aws_iam_role.app
  ]

}

⭐⭐⭐⭐⭐ 24. terraform fmt

Formats Terraform configuration files according to Terraform's standard formatting conventions. 
terraform fmt

⭐⭐⭐⭐⭐ 26. Terraform vs CloudFormation

Terraform AWS CloudFormation
Multi-provider IaC tool AWS-native IaC service
Uses HCL Uses YAML/JSON
Terraform state is important AWS manages CloudFormation stack state
Works across AWS, Azure, GCP and other providers Primarily AWS focused
Terraform is often preferred when an organization wants one IaC tool across multiple providers.

⭐⭐⭐⭐⭐ 27. Terraform vs Ansible

Terraform Ansible
Primarily infrastructure provisioning and management Primarily configuration management and automation
Declarative infrastructure model Automation/playbook model
Uses state Does not use Terraform-style infrastructure state
Creates cloud resources Configures systems/applications
Real-time combination: Terraform creates the AWS infrastructure. Ansible can then configure operating systems and applications on those instances.

⭐⭐⭐⭐⭐ 28. Terraform Lifecycle

The lifecycle block allows control over certain resource change behaviors. 
resource "aws_instance" "app" {

  # resource configuration

  lifecycle {
    create_before_destroy = true
  }
}
Common lifecycle arguments include:

create_before_destroy
prevent_destroy
ignore_changes

⭐⭐⭐⭐ 29. What is Drift?

Drift occurs when the real infrastructure is changed outside Terraform and no longer matches what Terraform configuration and state expect.
Example: Terraform created an EC2 security group allowing port 443. Someone manually changes the security group in the AWS Console. Now the real infrastructure differs from the Terraform-managed configuration. Running: 
terraform plan
can reveal changes Terraform wants to make to reconcile the infrastructure.

"Terraform is a declarative Infrastructure as Code tool used to provision and manage infrastructure. We define the desired infrastructure using Terraform configuration files. Terraform uses providers to communicate with platforms such as AWS. The typical workflow is terraform init, validate, plan and apply. Terraform maintains state so it can understand the resources it manages and determine the changes required to reach the desired state. In a real-time DevOps environment, I can use Terraform to provision AWS networking, compute, security and other infrastructure in a repeatable and version-controlled way. For team environments, I would use remote state with appropriate access control and state-protection practices, and I would review terraform plan output before applying production changes."
