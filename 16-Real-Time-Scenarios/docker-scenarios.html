1. Container Starts and Immediately Exits

Question

A Docker container starts but immediately stops. How would you troubleshoot it?

First check the container status: 
docker ps -a
Then check logs: 
docker logs <container_id>
Then inspect the container: 
docker inspect <container_id>
I would verify the container's main process and its CMD / ENTRYPOINT configuration. A container normally stays alive only while its main process (PID 1) is running.
⭐⭐⭐⭐⭐ VERY IMPORTANT

2. Container Is Running but Application Is Not Accessible

Container
↓
Application
↓
Container Port
↓
Host Port
↓
Client

Check

docker ps

docker port <container_id>

docker logs <container_id>

Also verify that the application is listening on the expected port and that the port is correctly published.

⭐⭐⭐⭐⭐

3. Port Mapping Is Wrong

docker run -d -p 8080:80 nginx

Here: 8080 = host port
80 = container port

If users access port 8080 on the host, Docker forwards the traffic to port 80 inside the container. Check the mapping with: 
docker port <container_id>
⭐⭐⭐⭐⭐ VERY IMPORTANT

4. Container Cannot Connect to Another Container

I would check whether both containers are connected to the same Docker network. 
docker network ls

docker network inspect <network>
Create a network if required: 
docker network create app-network
Run containers on it: 
docker run -d --name db --network app-network mysql
docker run -d --name app --network app-network myapp
Containers on the same user-defined network can communicate using container/service names.
⭐⭐⭐⭐⭐

5. Docker Container Cannot Reach the Internet

Check

docker exec -it <container> sh

ping 8.8.8.8

nslookup google.com
I would distinguish between:
  • General network connectivity problem
  • DNS resolution problem
  • Docker network configuration problem
  • Host firewall or proxy configuration
I would also inspect the Docker network: 
docker network inspect bridge
⭐⭐⭐⭐⭐ VERY IMPORTANT

6. Container Has High CPU Usage

docker stats

Then identify the process: 

docker top <container_id>
I would check application logs and determine whether the high CPU is caused by traffic, an application problem, a runaway process or insufficient resources.
⭐⭐⭐⭐⭐

7. Container Is Using Too Much Memory

docker stats

Check container configuration: 

docker inspect <container_id>
I would investigate application memory usage and, where appropriate, configure container resource limits. Example: 
docker run -d --memory=512m --cpus=1 myapp
⭐⭐⭐⭐⭐ VERY IMPORTANT

8. Image Build Is Failing

docker build -t myapp .
I would inspect the exact build step that failed. Common causes:
  • Incorrect Dockerfile syntax
  • Wrong base image
  • Missing files in build context
  • Incorrect COPY path
  • Package installation failure
  • Network or registry issue
  • Permission problem
I would fix the first meaningful error rather than focusing only on the final error message.
⭐⭐⭐⭐⭐

9. Dockerfile COPY Is Failing

docker build -t myapp .
I would verify:
  • File exists in the build context
  • Correct relative path
  • .dockerignore is not excluding the file
  • Correct capitalization
  • Build is being executed from the expected directory
⭐⭐⭐⭐⭐ VERY IMPORTANT

10. Image Is Too Large

I would reduce image size by:
  • Using a smaller base image when appropriate
  • Using multi-stage builds
  • Removing unnecessary packages
  • Cleaning package caches
  • Using an effective .dockerignore
  • Copying only required application files
Example: 
.dockerignore

.git
node_modules
*.log
.env
README.md
⭐⭐⭐⭐⭐

11. Container Cannot Pull Image from Registry

docker pull username/myapp:latest
I would check:
  • Image name
  • Image tag
  • Registry availability
  • Authentication
  • Repository permissions
  • Network connectivity
For private registries: 
docker login
⭐⭐⭐⭐⭐ VERY IMPORTANT

12. Container Data Is Lost After Container Removal

Container writable storage is ephemeral. For persistent data, I would use Docker volumes or an external storage system. Example: 
docker volume create app-data

docker run -d \
  --name app \
  -v app-data:/data \
  myapp
Check volumes: 
docker volume ls
⭐⭐⭐⭐

13. Docker Volume Is Not Mounting Correctly

docker inspect <container_id>
I would verify:
  • Volume exists
  • Correct source and destination paths
  • Mount mode
  • Permissions
  • Application is writing to the expected path
⭐⭐⭐⭐⭐ VERY IMPORTANT

14. Docker Compose Application Is Not Starting

docker compose ps

docker compose logs

docker compose config
I would first validate the rendered Compose configuration, then inspect individual service logs and dependencies. I would also check:
  • Environment variables
  • Ports
  • Volumes
  • Networks
  • Dependency configuration
⭐⭐⭐⭐⭐

15. Application Container Cannot Connect to Database

Application
↓
Docker Network
↓
Database Container
↓
Database Port
I would verify that both containers are on the same network, the application uses the database service/container name rather than an incorrect localhost address, and that the database is actually listening. For example, inside a Compose network: 
DB_HOST=db
DB_PORT=3306
Important: Inside a container, localhost refers to that same container.
⭐⭐⭐⭐⭐

16. Docker Daemon Is Not Running

Linux

systemctl status docker

systemctl start docker

systemctl enable docker

Check Docker

docker info
If the daemon is unavailable, Docker CLI commands that require the daemon will fail. I would check daemon status and logs.
⭐⭐⭐⭐

17. Container Logs Are Huge

docker logs <container_id>
I would identify why excessive logging is happening and configure appropriate Docker logging and rotation settings rather than allowing unlimited log growth.
⭐⭐⭐⭐⭐ VERY IMPORTANT

18. Container Works Locally but Fails in CI/CD

I would compare the environments. Check:
  • Dockerfile
  • Environment variables
  • Secrets
  • Build context
  • CPU architecture
  • Registry credentials
  • Network access
  • Runtime configuration
Interview Point: "The image should be treated as the same deployable artifact across environments. I would identify environmental differences rather than rebuilding different application logic for each environment."
⭐⭐⭐⭐⭐ VERY IMPORTANT

19. Security Vulnerability Found in Docker Image

I would:
  • Scan the image
  • Identify vulnerable packages
  • Update the base image
  • Upgrade vulnerable dependencies
  • Rebuild the image
  • Scan again
  • Prevent deployment if critical policy requirements are violated
Tools such as Trivy can be integrated into CI/CD pipelines.
