1. EC2 Instance Is Not Reachable

Question

An EC2 instance was working earlier, but now you cannot connect to it. How would you troubleshoot?

Answer:

First I would check whether the instance is in the running state. Then I would check:
  • Security Group inbound rules
  • Network ACLs
  • Route table
  • Internet Gateway or NAT configuration
  • Public IP / Elastic IP
  • Subnet configuration
  • Instance status checks
  • SSH service and OS-level firewall
I would then use logs and connectivity tests to identify whether the problem is at the AWS networking layer or inside the operating system.
⭐⭐⭐⭐⭐

2. SSH to EC2 Is Failing

ssh -i key.pem ec2-user@PUBLIC_IP

Check

  • Correct public IP
  • Correct username
  • Private key permissions
  • Security Group port 22
  • Route to Internet Gateway
  • Instance is running
  • SSH daemon is running
Interview Point:
"I would troubleshoot from outside to inside: public connectivity, Security Group, routing, instance status and finally the operating system's SSH service."
⭐⭐⭐⭐⭐

3. EC2 Has High CPU

Question

An application server suddenly reaches 95% CPU. What will you do?

I would first confirm the metric using CloudWatch and then check the processes consuming CPU inside the instance. 
top
ps aux --sort=-%cpu | head
uptime
Then I would determine whether the cause is:
  • Traffic spike
  • Application process
  • Infinite loop
  • Background job
  • Insufficient instance capacity
Depending on the architecture, I could scale vertically, scale horizontally using Auto Scaling, or fix the application causing the CPU spike.
⭐⭐⭐⭐⭐

4. EC2 Disk Is Full

df -h

du -sh /* 2>/dev/null

du -sh /var/* 2>/dev/null
I would identify which filesystem and directory are consuming the space. Then I would inspect logs, temporary files and application data. I would clean only safe files, rotate logs if required, and increase the EBS volume if the workload genuinely requires more storage.
⭐⭐⭐⭐⭐ VERY IMPORTANT

5. Application Cannot Access S3

Question

An application running on EC2 suddenly receives AccessDenied when accessing S3. What would you check?

EC2
↓
IAM Role
↓
IAM Policy
↓
S3 Bucket Policy
↓
S3 Object
I would check the IAM role attached to the EC2 instance, its permissions, the bucket policy, explicit denies, object ownership/access controls and the requested S3 action. I would also verify that the application is actually using the expected IAM role.
⭐⭐⭐⭐⭐

6. IAM User Gets AccessDenied

Question

A developer says they have an IAM policy but still receive AccessDenied. What do you check?

I would check:
  • Attached identity policies
  • Resource-based policies
  • Explicit Deny statements
  • Permission boundaries
  • Session policies
  • SCPs if AWS Organizations is being used
  • Correct AWS account and region
  • Exact resource ARN and requested action
Key Rule: An explicit Deny overrides an Allow.
⭐⭐⭐⭐⭐ VERY IMPORTANT

  • Health-check path
  • Health-check port
  • Security Groups
  • Application listening port
  • Application logs
  • Network connectivity
Interview Answer:
"I would start from the target group's health status, verify the health-check configuration and then move toward the instance and application layer."
⭐⭐⭐⭐⭐

8. Load Balancer Returns 502

A 502 generally indicates that the load balancer could not get a valid response from the target.

Check

  • Backend application is running
  • Target port
  • Target health
  • Security Groups
  • Application response
  • Listener and target-group configuration
⭐⭐⭐⭐⭐ VERY IMPORTANT

9. Auto Scaling Is Not Adding Instances

I would check:
  • CloudWatch alarm
  • Auto Scaling policy
  • Desired, minimum and maximum capacity
  • Launch template
  • Subnet availability
  • Instance launch failures
  • IAM permissions
  • Auto Scaling activity history
The first objective is to determine whether the scaling policy did not trigger or whether the new instance launch itself failed.
⭐⭐⭐⭐⭐

10. VPC Instance Has No Internet Access

EC2
↓
Subnet Route Table
↓
Internet Gateway
↓
Internet

Check

  • Public IP or Elastic IP
  • Route table
  • Internet Gateway
  • Security Group
  • Network ACL
  • Subnet configuration
For a private subnet, I would instead verify the NAT Gateway and its routing path.
⭐⭐⭐⭐⭐

11. Private Subnet Cannot Reach Internet

Private EC2
↓
Private Route Table
↓
NAT Gateway
↓
Public Subnet
↓
Internet Gateway
↓
Internet

Check

  • Private route table has a route to NAT Gateway
  • NAT Gateway is available
  • NAT Gateway is in a suitable public subnet
  • Public subnet route points to Internet Gateway
  • Security Groups and NACLs allow required traffic
⭐⭐⭐⭐⭐ VERY IMPORTANT

12. DNS Resolution Is Failing Inside VPC

Check

nslookup example.com

dig example.com
I would check VPC DNS support/hostnames, the configured resolver, route and network connectivity, security controls, and whether the problem affects one instance or the entire subnet/VPC.
⭐⭐⭐⭐

13. S3 Upload Is Failing

Check

  • IAM permissions
  • Bucket policy
  • Bucket name
  • Region
  • Object key
  • Encryption requirements
  • Explicit Deny
aws s3 cp test.txt s3://my-bucket/
⭐⭐⭐⭐

14. CloudWatch Alarm Is Not Triggering

I would verify the metric, namespace, dimensions, statistic, period, evaluation periods, threshold and alarm state. I would also verify that the resource is publishing the expected metric and that the alarm action is configured correctly.
⭐⭐⭐⭐⭐

15. Application Is Slow but EC2 Is Healthy

I would not assume the EC2 instance is the problem. I would investigate the complete request path:
User
↓
Load Balancer
↓
Application
↓
Database
↓
External Services
Then I would compare latency, CPU, memory, network and application metrics to identify the bottleneck.
⭐⭐⭐⭐⭐ VERY IMPORTANT

16. Production EC2 Instance Suddenly Stops

Approach

  1. Check instance state.
  2. Check system and instance status checks.
  3. Review CloudWatch metrics.
  4. Check CloudTrail for API activity.
  5. Check application and OS logs.
  6. Check Auto Scaling activity if applicable.
  7. Determine whether it was infrastructure, application or human action.
Interview Tip:
Always mention evidence collection before making a production change.
⭐⭐⭐⭐⭐

17. How Would You Secure an AWS Production Environment?

I would use:
  • Least-privilege IAM
  • IAM roles instead of long-lived credentials
  • Private subnets for internal workloads
  • Security Groups with restricted access
  • Encryption at rest and in transit
  • CloudTrail for auditing
  • CloudWatch for monitoring
  • Secrets Manager or Parameter Store for secrets
  • Regular patching and vulnerability scanning
  • Backups and disaster-recovery planning
