⭐⭐⭐⭐⭐ 1. What is Amazon EKS?

Amazon EKS is a managed Kubernetes service provided by AWS. AWS manages the Kubernetes control-plane infrastructure while customers manage workloads, worker capacity and cluster configuration according to the chosen architecture.

Control Plane Data Plane
Runs Kubernetes control components. Runs application workloads.

API Server, scheduler and controllers are part of the Kubernetes control plane. Worker nodes run Pods and container workloads.

⭐⭐⭐⭐⭐ 8. IAM vs RBAC

IAM: Controls AWS-level identity and permissions.

Kubernetes RBAC: Controls authorization to Kubernetes resources.

Interview Answer:
"IAM determines who can access AWS/EKS and what AWS permissions they have, while Kubernetes RBAC determines what an authorized identity can do inside Kubernetes."

⭐⭐⭐⭐⭐ 15. Real-Time Scenario

VERY IMPORTANT

Question:

Your application is running on EKS. Suddenly traffic increases 10x. How will you handle it?

Interview Answer:

"First, the load balancer distributes the increased traffic to the application. HPA can detect increased resource utilization and increase the number of Pod replicas. If the existing nodes do not have enough capacity, a node provisioning mechanism such as Cluster Autoscaler or Karpenter can add compute capacity. Once the new nodes are ready, pending Pods are scheduled. I would monitor the application using metrics and logs and verify that the system has recovered."

⭐⭐⭐⭐⭐ 16. Real-Time Failure Scenario

Question:

A Pod is running but users cannot access the application. How do you troubleshoot?

Step 1: Check Pod status.

Step 2: Check application logs.

Step 3: Check Service.

Step 4: Check Endpoints / EndpointSlices.

Step 5: Check DNS.

Step 6: Check Ingress / Load Balancer.

Step 7: Check Security Groups and NetworkPolicies.

Step 8: Check AWS networking and routing.
