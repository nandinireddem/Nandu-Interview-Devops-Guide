⭐⭐⭐⭐⭐ 2. What is AWS VPC CNI?

The Amazon VPC CNI plugin is the networking plugin used by EKS to provide Kubernetes Pods with networking integrated with the AWS VPC.

↓

⭐⭐⭐⭐⭐ 3. How Does a Pod Get an IP?

With the AWS VPC CNI, Pods can receive IP addresses from the VPC networking space using the networking resources available to the node.

Worker Node
↓
VPC CNI
↓
VPC Networking Resources
↓
Pod IP
Interview Point:
Pod IP capacity is therefore influenced by the networking resources available to the worker node and subnet.

⭐⭐⭐⭐⭐ 12. Security Groups in EKS

AWS Security Groups control network traffic for AWS network interfaces and resources associated with them.

Example:
An application load balancer should be allowed to communicate with the application targets on the required port, while unrelated sources should not be granted unnecessary access.

⭐⭐⭐⭐⭐ 13. NetworkPolicy

Kubernetes NetworkPolicy can restrict network communication between Pods and other network endpoints, depending on the network plugin and policy implementation.

Pod A
↓
NetworkPolicy
↓
Allowed → Pod B
Denied → Pod C
Important:
NetworkPolicy and AWS Security Groups operate at different layers and should not be treated as replacements for one another.

⭐⭐⭐⭐⭐ 15. How Do Pods Communicate?

Pods can communicate through Kubernetes networking. In an AWS VPC CNI setup, Pod networking integrates with the AWS VPC network. Kubernetes Services provide stable endpoints for groups of Pods.

⭐⭐⭐⭐⭐ 18. EKS Networking Troubleshooting

Scenario: Pod cannot reach another service.

Check in order:
  1. Is the Pod Running?
  2. Does the target Service exist?
  3. Does the Service selector match the Pods?
  4. Are endpoints / EndpointSlices populated?
  5. Is DNS resolution working?
  6. Are NetworkPolicies blocking traffic?
  7. Are AWS Security Groups or routing involved?
  8. Check CNI health and node networking.
  9. Check application listening port.

⭐⭐⭐⭐⭐ 19. Pod Cannot Access Internet

Check:
  1. Pod IP / node networking.
  2. Subnet configuration.
  3. Route table.
  4. NAT Gateway for private subnets.
  5. Internet Gateway path.
  6. Security Group rules.
  7. NACL rules where applicable.
  8. DNS resolution.
  9. VPC CNI health and IP availability.

⭐⭐⭐⭐⭐ 20. Pod IP Exhaustion

In VPC CNI networking, available IP capacity can become a scaling constraint.

Possible causes:
  • Subnet has insufficient free IP addresses.
  • Node has reached its available Pod networking capacity.
  • High Pod density.
  • VPC CNI configuration or instance networking limits.
