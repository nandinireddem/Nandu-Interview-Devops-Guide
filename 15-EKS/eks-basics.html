Amazon EKS Basics

High-priority Amazon Elastic Kubernetes Service fundamentals for Cloud & DevOps interviews.

⭐⭐⭐⭐⭐ 1. What is Amazon EKS?

Amazon EKS, or Amazon Elastic Kubernetes Service, is a managed Kubernetes service provided by AWS. AWS manages the Kubernetes control plane infrastructure, while the customer manages workloads and worker compute according to the chosen EKS architecture.

Simple Interview Answer

"EKS is AWS's managed Kubernetes service. AWS manages the Kubernetes control plane, while I deploy and manage my applications on worker nodes or other supported compute options."

⭐⭐⭐⭐⭐ 2. Why Do We Use EKS?

  • Run containerized applications using Kubernetes.
  • Reduce operational effort for the Kubernetes control plane.
  • Integrate Kubernetes with AWS services.
  • Support scalable and highly available workloads.
  • Use Kubernetes orchestration, deployments and services.
  • Integrate with CI/CD and DevOps tooling.

⭐⭐⭐⭐⭐ 4. EKS Control Plane

The EKS control plane contains the Kubernetes components responsible for managing the cluster state and coordinating workloads.

Important Components

  • Kubernetes API Server
  • etcd
  • Scheduler
  • Controller Manager
AWS operates the EKS control-plane infrastructure for the managed EKS service. As a user, you interact with it primarily through the Kubernetes API and AWS APIs/tools.

⭐⭐⭐⭐⭐ 5. Kubernetes API Server

The API Server is the main entry point to the Kubernetes control plane.

kubectl
↓
Kubernetes API Server
↓
Kubernetes Resources

Example

kubectl get pods

The kubectl command communicates with the Kubernetes API Server.

⭐⭐⭐⭐⭐ 6. What is etcd?

etcd is a distributed key-value store used by Kubernetes to store cluster state and configuration data.

Interview Answer:
"etcd stores Kubernetes cluster state, such as resource configuration and metadata. The Kubernetes control plane uses it as its backing data store."

⭐⭐⭐⭐⭐ 7. What is the Kubernetes Scheduler?

The scheduler determines which suitable node should run a newly created Pod.

Pod Created
↓
Scheduler
↓
Select Suitable Node
↓
Pod Runs on Node

It considers factors such as resource availability, scheduling constraints, affinity and taints/tolerations.

⭐⭐⭐⭐⭐ 8. What are Worker Nodes?

Worker nodes provide compute capacity where Kubernetes workloads run.

EKS Cluster
↓
Worker Node
↓
kubelet + Container Runtime
↓
Pods
↓
Containers

⭐⭐⭐⭐⭐ 9. EKS Managed Node Group

A managed node group is a group of EC2 worker nodes that EKS helps provision and manage as part of the cluster.

Benefits

  • Automated node provisioning.
  • Integration with EKS lifecycle operations.
  • Scaling support.
  • Managed node update workflows.

⭐⭐⭐⭐⭐ 10. EKS with Fargate

AWS Fargate can provide serverless compute for supported EKS Pods, so you don't manage the underlying EC2 worker nodes for those Pods.

EKS
↓
Pod
↓
AWS Fargate
↓
AWS Managed Compute

Managed Nodes vs Fargate

Managed Node Group Fargate
Uses EC2 worker nodes. Runs supported Pods on serverless compute.
You manage node-level configuration and capacity. No EC2 worker node management for those Pods.
More control over node configuration. Less infrastructure management.

⭐⭐⭐⭐⭐ 11. What is a Pod?

A Pod is the smallest deployable unit in Kubernetes.

Node
↓
Pod
↓
Container
↓
Application

A Pod can contain one or more containers that share networking and storage resources within the Pod.

⭐⭐⭐⭐⭐ 12. What is kubelet?

kubelet is the Kubernetes node agent that runs on worker nodes. It communicates with the Kubernetes control plane and makes sure the assigned Pods and containers are running as specified.

Remember:
API Server → Control Plane
kubelet → Worker Node Agent

⭐⭐⭐⭐⭐ 13. What is kube-proxy?

kube-proxy is a Kubernetes component traditionally responsible for implementing service networking rules on nodes.

In AWS EKS, networking behavior also depends on the AWS VPC CNI and the Kubernetes networking configuration.

⭐⭐⭐⭐⭐ 14. How Does kubectl Connect to EKS?

Developer
↓
kubectl
↓
kubeconfig
↓
EKS Kubernetes API Server
↓
Cluster Resources

Common Command

aws eks update-kubeconfig \
--region ap-south-1 \
--name my-eks-cluster

This configures kubeconfig so kubectl can connect to the specified EKS cluster using AWS authentication integration.

⭐⭐⭐⭐⭐ 15. EKS Cluster vs Kubernetes Cluster

Self-Managed Kubernetes Amazon EKS
You manage the Kubernetes control plane. AWS provides the managed Kubernetes control plane.
You handle control-plane infrastructure. AWS handles the underlying control-plane infrastructure.
You manage infrastructure integration yourself. EKS integrates with AWS services.
More operational responsibility. Reduced control-plane operational burden.

⭐⭐⭐⭐⭐ 16. What is an EKS Cluster?

An EKS cluster is the Kubernetes environment running on AWS. It includes the managed Kubernetes control plane and the compute resources used to run workloads, such as managed node groups, self-managed nodes or Fargate depending on the architecture.

⭐⭐⭐⭐⭐ 17. EKS and VPC

EKS integrates closely with AWS VPC networking.

The exact networking model depends on the EKS configuration, but AWS VPC networking is a major EKS interview topic.

⭐⭐⭐⭐⭐ 18. EKS Authentication vs Authorization

Authentication Authorization
Who are you? What are you allowed to do?
Identity verification. Permission evaluation.
AWS IAM can participate in EKS authentication. Kubernetes RBAC controls Kubernetes permissions.
Easy Interview Line:
IAM helps establish identity/access from the AWS side, while Kubernetes RBAC determines what an authenticated identity can do inside Kubernetes.

⭐⭐⭐⭐⭐ 20. Real-Time Scenario: Node Is Not Ready

Interview Approach:
  1. Check node status.
  2. Run kubectl describe node.
  3. Check kubelet/node conditions.
  4. Check CPU and memory availability.
  5. Check networking and CNI status.
  6. Check node IAM permissions.
  7. Check system and Kubernetes events.
  8. Check whether the node can communicate with the control plane.

⭐⭐⭐⭐⭐ 21. Real-Time Scenario: Pod Stuck in Pending

Possible Causes:
  • Insufficient CPU or memory.
  • Node selector mismatch.
  • Affinity rules.
  • Taints without matching tolerations.
  • Insufficient available nodes.
  • Storage or volume constraints.
First Command: 
kubectl describe pod <pod-name>
