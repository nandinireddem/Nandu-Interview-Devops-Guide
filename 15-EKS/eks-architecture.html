⭐⭐⭐⭐⭐ 2. EKS Control Plane

The EKS control plane runs Kubernetes control-plane components required to manage cluster state and workloads.

Component Responsibility
API Server Entry point for Kubernetes API requests.
etcd Stores Kubernetes cluster state.
Scheduler Selects suitable nodes for Pods.
Controllers Continuously reconcile desired and actual state.
Interview Point:
AWS manages the underlying EKS control-plane infrastructure. You interact with the Kubernetes API rather than managing the control-plane servers yourself.

⭐⭐⭐⭐⭐ 15. How Does a Request Reach a Pod?

Interview Answer:

"A user first resolves the application domain through DNS. The request reaches an AWS load balancer, which forwards traffic to the Kubernetes Service or its backend targets. The Service then routes the request to an appropriate Pod, where the application process handles the request."

⭐⭐⭐⭐⭐ 16. How Does a Pod Get Network Connectivity?

In a typical AWS VPC CNI setup, the CNI plugin assigns networking from the VPC to Pods using available VPC IP resources. This allows Pod traffic to integrate with AWS VPC routing and security controls.

⭐⭐⭐⭐⭐ 17. EKS Architecture Interview Scenario

Question:

"Design a highly available EKS architecture for a production application."

Answer:
  1. Create an EKS cluster across multiple Availability Zones.
  2. Use private subnets for worker nodes where appropriate.
  3. Deploy multiple worker nodes across Availability Zones.
  4. Use an internet-facing load balancer for public traffic.
  5. Use Kubernetes Services to distribute traffic to Pods.
  6. Use managed node groups or another appropriate compute model.
  7. Use appropriate IAM and Kubernetes RBAC controls.
  8. Use NetworkPolicies where supported and required.
  9. Use persistent storage through appropriate CSI drivers.
  10. Add monitoring, logging and alerting.
