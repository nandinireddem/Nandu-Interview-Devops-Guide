Networking Security

High-priority networking security concepts for Cloud and DevOps interviews, with practical AWS and Kubernetes examples.

⭐⭐⭐⭐⭐ 1. What is Network Security?

Network security is the practice of protecting network resources, systems and data from unauthorized access, attacks and unwanted traffic.

In Cloud and DevOps, network security commonly involves:

  • Firewalls
  • Security Groups
  • Network ACLs
  • VPNs
  • Private Subnets
  • Encryption
  • Network segmentation
  • Least privilege

⭐⭐⭐⭐⭐ 2. Firewall

A firewall controls network traffic based on configured rules.

Incoming Traffic
↓
🔥 Firewall
↓
Allowed → Application

Denied → ❌ Blocked

Rules can consider source, destination, protocol, port and direction.

⭐⭐⭐⭐⭐ 3. AWS Security Group

An AWS Security Group acts as a virtual firewall for supported resources such as EC2 network interfaces.

Important properties:
  • Stateful.
  • Controls inbound and outbound traffic.
  • Rules are allow-based.
  • Can reference another Security Group as a source or destination where supported.

⭐⭐⭐⭐⭐ 4. Network ACL

A Network ACL is a subnet-level network traffic control mechanism.

Important properties:
  • Stateless.
  • Supports allow and deny rules.
  • Associated with subnets.
  • Rules are evaluated in rule-number order.

⭐⭐⭐⭐⭐ 5. Security Group vs NACL

Security Group Network ACL
Resource / network-interface level Subnet level
Stateful Stateless
Allow rules Allow and deny rules
No explicit deny rules Explicit deny possible
Commonly used for resource-level protection Commonly used for subnet-level filtering
Interview Shortcut:

Security Group → Stateful → Resource level
NACL → Stateless → Subnet level

⭐⭐⭐⭐⭐ 11. Encryption in Networking

Encryption protects data by transforming readable information into a form that unauthorized parties cannot easily understand.

Two Important States

Data in Transit Data moving across a network.
Data at Rest Data stored on disks, databases or storage systems.

⭐⭐⭐⭐ 14. Kubernetes Network Security

Kubernetes networking can be protected using several controls.

  • NetworkPolicies
  • RBAC
  • Pod security controls
  • Restricted container privileges
  • Secure ingress configuration
  • Private cluster networking where appropriate
NetworkPolicy:
Can restrict which pods or namespaces are allowed to communicate with other workloads, depending on the network plugin and policy support.

⭐⭐⭐⭐⭐ 16. SSH Security

SSH is commonly used for secure remote administration.

Port

TCP 22

Security Practices

  • Prefer key-based authentication.
  • Restrict SSH source networks.
  • Avoid exposing SSH to the entire Internet unnecessarily.
  • Use bastion hosts or managed access mechanisms where appropriate.
  • Keep systems updated.

⭐⭐⭐⭐⭐ 17. Real-Time Scenario: EC2 Port 22 Is Open to Everyone

Question:

"An EC2 Security Group allows SSH from 0.0.0.0/0. Is that a good security practice?"

Answer:
"No. It exposes the SSH service to the entire Internet. I would restrict the source to a trusted IP range or use a more secure management approach such as a bastion host or AWS Systems Manager where appropriate."

⭐⭐⭐⭐⭐ 18. Real-Time Scenario: Database Is Publicly Accessible

Approach:
  1. Identify why public access is required.
  2. Remove unnecessary public exposure.
  3. Place the database in private subnets where appropriate.
  4. Restrict inbound access to only required application sources.
  5. Review route tables and network controls.
  6. Monitor and verify the new configuration.

⭐⭐⭐⭐⭐ 19. Security Incident: Unexpected Open Port

Steps:
  1. Identify the service using the port.
  2. Determine whether the port is required.
  3. Check the source of the traffic.
  4. Review Security Group / firewall rules.
  5. Restrict or remove unnecessary access.
  6. Check logs for suspicious activity.
  7. Document the remediation.
