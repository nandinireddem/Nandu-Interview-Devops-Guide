Networking Architecture

Understand how real-world cloud applications communicate across VPCs, subnets, routing components, NAT and load balancers.

⭐⭐⭐⭐⭐ 1. What is Network Architecture?

Network architecture describes how network components are organized and connected so that applications and systems can communicate securely and reliably.

In Cloud and DevOps, architecture commonly includes:

  • VPC / Virtual Network
  • Subnets
  • Route Tables
  • Internet Gateway
  • NAT Gateway
  • Load Balancer
  • Security Groups / Firewalls
  • Application and Database tiers

⭐⭐⭐⭐⭐ 3. VPC

A VPC, or Virtual Private Cloud, is an isolated virtual network where cloud resources can be deployed. 

VPC
CIDR: 10.0.0.0/16

        |
        +--------------------+
        |                    |
   Public Subnet        Private Subnet
   10.0.1.0/24          10.0.2.0/24
Interview Answer:
"A VPC provides an isolated networking environment in the cloud where I can define IP ranges, subnets, routing and network security controls."

⭐⭐⭐⭐⭐ 4. Public Subnet vs Private Subnet

Public Subnet Private Subnet
Has a route toward an Internet Gateway. Does not have a direct route to the Internet Gateway.
Can contain resources that need direct Internet reachability. Commonly used for application and database resources.
Example: public load balancer. Example: private application server or database.
Important: A subnet being called "public" does not automatically make every resource inside it publicly reachable. Routing and security controls also matter.

⭐⭐⭐⭐⭐ 5. Route Table

A route table contains rules that determine where network traffic should be sent. 

Destination       Target

10.0.0.0/16       local
0.0.0.0/0         Internet Gateway

For a private subnet, a common outbound route is through a NAT Gateway instead of directly through an Internet Gateway.

⭐⭐⭐⭐⭐ 6. Internet Gateway

An Internet Gateway provides a path between a VPC and the public Internet when the required routing and addressing configuration exists.

⭐⭐⭐⭐⭐ 7. NAT Gateway

A NAT Gateway allows resources in a private subnet to initiate outbound Internet connections without requiring those resources to have public IP addresses.

Private EC2
↓
Private Route Table
↓
NAT Gateway
↓
Internet Gateway
↓
🌍 Internet
Interview Question:
Why do we use NAT Gateway?

Answer:
"We use a NAT Gateway to allow private resources to access external services or download updates without giving those resources public IP addresses."

Why use a Load Balancer?

  • Distribute incoming traffic.
  • Improve availability.
  • Support horizontal scaling.
  • Perform health checks.
  • Provide a single entry point for clients.

⭐⭐⭐⭐⭐ 10. Security Groups vs Network ACL

Security Group Network ACL
Applied to supported network interfaces/resources. Applied at subnet level.
Stateful. Stateless.
Rules control allowed traffic. Rules can allow or deny traffic.
Commonly used for instance-level access control. Commonly used for subnet-level filtering.

⭐⭐⭐⭐⭐ 15. Real-Time Scenario

Question:

"Your EC2 instance in a private subnet cannot download packages from the Internet. How will you troubleshoot?"

Answer:
  1. Check whether the subnet is actually private.
  2. Check the subnet's route table.
  3. Verify that the default route points to a NAT Gateway.
  4. Check whether the NAT Gateway is available.
  5. Verify the NAT Gateway is in a subnet with Internet connectivity.
  6. Check security controls.
  7. Check DNS configuration if the problem is hostname resolution.
  8. Test connectivity from the instance.

⭐⭐⭐⭐⭐ 16. Real-Time Scenario: Application Not Reachable

Check in this order:
DNS → Load Balancer → Listener → Target Group → Target Health → Security Group → Route Table → Application Port → Application Logs

This layered approach helps identify whether the issue is DNS, load balancing, routing, security or the application itself.
