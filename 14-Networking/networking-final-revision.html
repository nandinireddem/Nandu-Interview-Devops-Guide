⭐⭐⭐⭐⭐ 1. Networking Fundamentals

Concept Quick Answer
IP Address Identifies a network interface or endpoint within an IP network.
Public IP An address used for public network reachability when routing and security allow it.
Private IP An address used within private network ranges and not directly routable on the public Internet.
TCP Connection-oriented transport protocol with reliable, ordered delivery.
UDP Connectionless transport protocol with lower overhead but no built-in delivery guarantee.
DNS Resolves domain names to IP addresses and other DNS records.
HTTP Application-layer protocol commonly used for web communication.
HTTPS HTTP protected by TLS.

⭐⭐⭐⭐⭐ 5. Public vs Private Subnet

Public Private
Has a route toward an Internet Gateway. Does not have a direct route to an Internet Gateway.
Common for internet-facing load balancers. Common for application and database resources.
Can support resources with public addressing. Resources can use private addressing and controlled outbound paths.

⭐⭐⭐⭐⭐ 6. Internet Gateway vs NAT Gateway

Internet Gateway NAT Gateway
Provides VPC connectivity to the Internet when routes and addressing permit it. Provides outbound Internet access for private resources.
Used by public subnet routing. Commonly used by private subnet routing.
Does not itself make a resource public. Does not provide unsolicited inbound Internet access to private instances.

⭐⭐⭐⭐⭐ 7. Security Group vs NACL

Security Group:
Stateful → resource/network-interface level → allow rules.

NACL:
Stateless → subnet level → allow and deny rules.

⭐⭐⭐⭐⭐ 12. Scenario: Application Not Reachable

Interview Answer:

"I would troubleshoot layer by layer. First I would verify DNS resolution, then network connectivity and routing. Next I would check whether the required port is listening and whether firewall or Security Group rules allow the traffic. If a load balancer is involved, I would check the listener, target group and target health. Finally, I would check the application logs."

⭐⭐⭐⭐⭐ 13. Scenario: Private EC2 Cannot Access Internet

Interview Answer:

"I would verify the subnet route table and confirm that the default route points to a NAT Gateway. Then I would verify that the NAT Gateway has a valid path through the Internet Gateway, and check Security Groups, NACLs and DNS configuration."

⭐⭐⭐⭐⭐ 14. Scenario: Load Balancer Target Unhealthy

Check:
  1. Target instance or pod is running.
  2. Application is listening on the expected port.
  3. Health-check path is correct.
  4. Security Groups allow load-balancer traffic.
  5. Network routing is correct.
  6. Application returns the expected health-check response.
  7. Review application and load-balancer logs.
