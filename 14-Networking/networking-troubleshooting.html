Interview Tip:
Don't randomly run commands. Troubleshoot layer by layer and identify exactly where communication is failing.

⭐⭐⭐⭐⭐ 2. ping

The ping command is commonly used to test basic network reachability using ICMP. 

ping 8.8.8.8
ping 192.168.1.10

What does it tell us?

  • Whether a destination responds to ICMP.
  • Approximate round-trip time.
  • Packet loss.
Important:
A failed ping does not always mean the application is unreachable. ICMP may be blocked while TCP traffic is still allowed.

⭐⭐⭐⭐⭐ 3. nslookup

Used to test DNS resolution. 

nslookup google.com

If DNS resolution fails, investigate DNS configuration before assuming there is an application connectivity problem.

⭐⭐⭐⭐⭐ 4. dig

dig provides detailed DNS query information. 

dig example.com
dig example.com A
dig example.com MX

Useful Information

  • DNS server used
  • Answer records
  • TTL
  • Query status

⭐⭐⭐⭐⭐ 5. curl

curl is extremely useful for testing HTTP/HTTPS connectivity and APIs. 

curl http://example.com

curl -I https://example.com

curl -v https://example.com
DevOps Use Case:
When an application is not responding, curl helps determine whether the HTTP endpoint itself is reachable and what response the server returns.

⭐⭐⭐⭐⭐ 6. ss

ss displays socket and network connection information. 

ss -tulnp
Option Meaning
-t TCP
-u UDP
-l Listening sockets
-n Don't resolve service names
-p Show process information where permitted

⭐⭐⭐⭐⭐ 7. ip addr

Displays network interfaces and their IP addresses. 

ip addr

Use it to check whether the expected interface has an IP address and whether the interface is up.

⭐⭐⭐⭐⭐ 8. ip route

Displays the system's routing table. 

ip route
Interview Question:

"What do you check if a server cannot reach another network?"

Answer:
"I first verify the routing table to make sure there is a valid route toward the destination."

⭐⭐⭐⭐⭐ 9. traceroute

Shows the network hops taken toward a destination. 

traceroute example.com

On Windows, the equivalent command is: 

tracert example.com

It can help identify where traffic appears to stop or experience unexpected delay.

⭐⭐⭐⭐⭐ 10. Test a Specific Port

Sometimes the network is reachable but a particular service port is not accessible.

Linux

nc -zv 10.0.1.10 8080

Windows PowerShell

Test-NetConnection 10.0.1.10 -Port 8080
Key idea:
Ping tests basic ICMP reachability. A TCP port test checks whether a specific service port can be reached.

⭐⭐⭐⭐⭐ 12. Application Not Reachable

Scenario:
An application is running on port 8080, but users cannot access it.

Troubleshooting:
  1. Check whether the application process is running.
  2. Check whether port 8080 is listening.
  3. Check the server's IP address.
  4. Check local firewall rules.
  5. Check cloud Security Group / firewall rules.
  6. Check subnet route table.
  7. Check Network ACL where applicable.
  8. Check load balancer listener and target health if a load balancer is used.
  9. Test using curl or a TCP port test.

⭐⭐⭐⭐⭐ 13. EC2 Cannot Access Internet

Scenario:
An EC2 instance cannot download packages or access an external website.

Check:
  1. Does the instance have network connectivity?
  2. Is the subnet public or private?
  3. Check the route table.
  4. For private subnets, verify NAT Gateway configuration.
  5. Verify NAT Gateway has a working path to the Internet Gateway.
  6. Check Security Group rules.
  7. Check Network ACL rules.
  8. Check DNS resolution.

⭐⭐⭐⭐⭐ 14. DNS Works but Website Doesn't

DNS
↓
IP returned successfully
↓
TCP connection
↓
Port 80 / 443
↓
HTTP response

If DNS resolves correctly, the next step is to test TCP and HTTP connectivity rather than repeatedly checking DNS. 

curl -v https://example.com

Test-NetConnection example.com -Port 443

⭐⭐⭐⭐⭐ 15. Connection Refused vs Timeout

Connection Refused Connection Timeout
Host is reachable but the connection was rejected. No response was received within the expected time.
Possible service not listening. Possible routing or firewall issue.
Wrong application port is another possibility. Security Group, NACL or network path may be involved.

DNS not resolving DNS records, resolver, DNS configuration

Port unavailable Service listening, firewall, Security Group
Website unavailable DNS → TCP → LB → Application

Load balancer unhealthy Health check → target port → security rules
Kubernetes service failing Pods → Service → Endpoints → Ingress
