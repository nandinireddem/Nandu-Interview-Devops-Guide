1. Give Me Your Project Introduction

"My project is an end-to-end Cloud and DevOps implementation focused on automating the application deployment lifecycle.

The source code is maintained in GitHub. Whenever changes are pushed, the CI/CD pipeline is triggered.

Jenkins handles the build, testing and Docker image creation. The Docker image is pushed to a container registry and then deployed to Kubernetes running on AWS.

Terraform is used to provision the required infrastructure, while Prometheus and Grafana are used for monitoring and visualization."

⭐⭐⭐⭐⭐

3. What Happens When Developer Pushes Code?

The developer pushes the code to GitHub.

GitHub sends an event through the configured webhook to Jenkins. Jenkins receives the event and starts the pipeline.

The pipeline checks out the latest code and executes the defined CI/CD stages.

⭐⭐⭐⭐⭐

4. Explain Your Jenkins Pipeline

pipeline {

    stages {

        stage('Checkout') {
            steps {
                // Checkout source code
            }
        }

        stage('Build') {
            steps {
                // Build application
            }
        }

        stage('Test') {
            steps {
                // Run tests
            }
        }

        stage('Docker Build') {
            steps {
                // Build Docker image
            }
        }

The pipeline is divided into logical stages so that each phase can be identified and troubleshot independently.
⭐⭐⭐⭐⭐ VERY IMPORTANT

5. Why Do You Build a Docker Image?

The Docker image packages the application and its dependencies into a consistent artifact. The same image can then be promoted through environments instead of rebuilding the application differently for each environment.
⭐⭐⭐⭐⭐

6. How Is the Docker Image Tagged?

I would prefer an immutable tag such as a Git commit SHA or release version instead of relying only on latest. Example: 
myapp:1.0.0
myapp:<git-commit-sha>
This makes it easier to identify exactly which version was deployed.
⭐⭐⭐⭐⭐ VERY IMPORTANT

7. How Does Kubernetes Get the Image?

Container Registry
↓
Kubernetes Node
↓
Container Runtime
↓
Application Container
↓
Pod
The Kubernetes workload specifies the container image. The cluster pulls the image from the configured container registry when creating the Pod, subject to the required registry access.
⭐⭐⭐⭐⭐

8. Explain Your Kubernetes Deployment

apiVersion: apps/v1
kind: Deployment

spec:
  replicas: 3

  selector:
    matchLabels:
      app: myapp

  template:
    metadata:
      labels:
        app: myapp

    spec:
      containers:
      - name: myapp
        image: myapp:1.0.0
        ports:
        - containerPort: 8080
The Deployment defines the desired state of the application. For example, with three replicas Kubernetes attempts to maintain three application Pods. If a Pod fails, the controller can create a replacement.
⭐⭐⭐⭐⭐ VERY IMPORTANT

9. How Does Terraform Help Your Project?

Terraform manages the infrastructure as code. For example, the infrastructure can include:
  • VPC
  • Subnets
  • Security groups
  • EKS cluster
  • Node groups
  • IAM-related resources
Terraform allows infrastructure changes to be reviewed, version-controlled and reproduced.
⭐⭐⭐⭐⭐

10. How Do You Handle Terraform Changes?

Terraform Code

↓
terraform plan
↓

terraform apply

Infrastructure Updated
I use terraform plan to review the proposed changes before applying them. This helps prevent unexpected infrastructure modifications.
⭐⭐⭐⭐⭐ VERY IMPORTANT

Prometheus collects metrics from the monitored targets. Grafana connects to Prometheus as a data source and displays those metrics in dashboards. This helps identify resource and application-level problems.
⭐⭐⭐⭐⭐

12. What Happens If a Deployment Fails?

I first identify the failing layer. For Kubernetes I would check: 
kubectl get pods
kubectl describe pod <pod-name>
kubectl logs <pod-name>
kubectl get events
Then I determine whether the issue is related to the image, configuration, secrets, resources, networking or application startup.
⭐⭐⭐⭐⭐ VERY IMPORTANT

13. What Was Your Troubleshooting Method?

I follow a layer-by-layer approach instead of changing multiple things at the same time.
Application
↓
Container
↓
Kubernetes
↓
Network
↓
Cloud Infrastructure
↓
CI/CD
I start with logs and the first meaningful error, then move towards the underlying infrastructure if required.
⭐⭐⭐⭐⭐

"I built an end-to-end DevOps pipeline for deploying a containerized application on AWS.

The code is maintained in GitHub and Jenkins automates the CI/CD workflow. The application is tested, containerized using Docker and the image is pushed to a registry.
