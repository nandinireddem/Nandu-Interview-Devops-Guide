Project Interview Questions

High-priority project questions, follow-ups and interview-ready answers for DevOps interviews.

⭐⭐⭐⭐⭐ VERY FREQUENT

1. Explain Your Project.

I worked on an end-to-end Cloud and DevOps project focused on automating application deployment. The source code is maintained in GitHub. Jenkins automates the CI/CD pipeline, Docker is used for containerization, Terraform provisions infrastructure, and Kubernetes manages the deployed containers. Prometheus and Grafana are used for monitoring and visualization.
⭐⭐⭐⭐⭐ VERY FREQUENT

2. What Was Your Role?

My role was focused on the DevOps implementation. I worked on:
  • Cloud infrastructure
  • Terraform automation
  • Docker containerization
  • Jenkins CI/CD
  • Kubernetes deployment
  • Monitoring
  • Troubleshooting
⭐⭐⭐⭐⭐

3. Why Did You Choose AWS?

AWS provides a broad set of cloud services for compute, networking, storage, security and managed Kubernetes. It also allowed me to implement the project using real cloud infrastructure instead of only local environments.
⭐⭐⭐⭐⭐

4. Why Docker?

Docker packages the application and its dependencies into a portable image. This provides consistency between development, testing and deployment environments and makes container-based deployment easier.
⭐⭐⭐⭐⭐ VERY FREQUENT

5. Why Kubernetes Instead of Docker Alone?

Docker can run containers, but Kubernetes provides orchestration for multiple containers. Kubernetes provides:
  • Scheduling
  • Self-healing
  • Scaling
  • Service discovery
  • Rolling updates
Therefore Kubernetes is more suitable for managing applications at scale.
⭐⭐⭐⭐⭐ VERY FREQUENT

6. Why Terraform?

Terraform allows infrastructure to be defined as code. It makes infrastructure:
  • Repeatable
  • Version controlled
  • Reviewable
  • Automated
It also reduces manual configuration through the cloud console.
⭐⭐⭐⭐⭐ VERY FREQUENT

7. Why Jenkins?

Jenkins automates the CI/CD lifecycle. It can automatically build the application, run tests, create Docker images, push them to a registry and trigger deployment.
⭐⭐⭐⭐⭐

8. What Happens When Code Is Pushed?

Developer → GitHub → Webhook → Jenkins → Build → Test → Docker → Registry → Kubernetes
The Git push triggers Jenkins through the configured integration. Jenkins checks out the latest code and executes the pipeline stages.
⭐⭐⭐⭐⭐ VERY FREQUENT

9. What If the Jenkins Pipeline Fails?

I first inspect the Jenkins console output and identify the first meaningful error. Then I determine which stage failed and troubleshoot that layer. For example:
  • Git → credentials or repository
  • Build → dependency or code issue
  • Docker → Dockerfile or daemon
  • Registry → authentication or permissions
  • Kubernetes → manifest, RBAC or image issue
⭐⭐⭐⭐⭐ VERY FREQUENT

10. What If the Pod Is Not Starting?

I would check: 
kubectl get pods
kubectl describe pod <pod-name>
kubectl logs <pod-name>
kubectl get events
I would look for image-pull failures, configuration errors, resource issues, scheduling problems or application startup failures.
⭐⭐⭐⭐⭐

11. What If the Docker Image Cannot Be Pulled?

I would verify:
  • Image name
  • Image tag
  • Registry availability
  • Image existence
  • Registry credentials
  • Kubernetes image-pull permissions
A common error is ImagePullBackOff.
⭐⭐⭐⭐⭐

12. What If the Application Is Running but Not Accessible?

I would check the request path layer by layer:
User → Load Balancer / Ingress → Service → Pod → Container Port → Application
I would verify Service selectors, endpoints, ports, network configuration and application listening address.
⭐⭐⭐⭐⭐

13. How Do You Monitor the Application?

Prometheus collects metrics and Grafana visualizes them. I would monitor metrics such as:
  • CPU usage
  • Memory usage
  • Pod availability
  • Request metrics
  • Application performance
⭐⭐⭐⭐

14. How Do You Handle Secrets?

I would never hardcode passwords, tokens or cloud credentials in source code or Dockerfiles. Secrets should be stored using an appropriate secret-management mechanism and accessed only by authorized workloads. The principle is least privilege.
⭐⭐⭐⭐⭐

15. How Would You Roll Back a Failed Deployment?

First I would confirm that the new version is unhealthy. For a Kubernetes Deployment, I can inspect rollout history and use the appropriate rollback mechanism. The key objective is to restore the last known-good version quickly while investigating the root cause.
⭐⭐⭐⭐

16. How Would You Scale the Application?

At the Kubernetes workload level, I can increase replicas. For dynamic workloads, Kubernetes autoscaling can be used based on suitable resource or application metrics. At the infrastructure level, the worker capacity may also need to scale so the cluster has enough resources.
⭐⭐⭐⭐⭐

17. What Was the Biggest Challenge?

The biggest challenge was troubleshooting issues across multiple layers such as CI/CD, Docker, Kubernetes and AWS. Instead of making random changes, I learned to isolate the failure layer first, inspect logs and then fix the root cause.
⭐⭐⭐⭐

18. What Would You Change If You Built It Again?

I would improve the project with:
  • Better secret management
  • Automated vulnerability scanning
  • Centralized logging
  • Automated rollback
  • More comprehensive alerting
  • Stronger IAM least-privilege policies
  • Separate environments
⭐⭐⭐

19. What Happens If AWS Goes Down?

For a production-critical application, I would design for resilience rather than assuming a single environment is enough. Depending on the business requirement, this could include multi-AZ architecture, backups, disaster recovery and potentially multi-region strategies. The correct design depends on availability requirements and cost.
⭐⭐⭐⭐⭐ FOLLOW-UP

20. If I Remove Jenkins, Can the Project Still Work?

Yes. Jenkins is the CI/CD automation tool. The application can still run without Jenkins, but the automated build and deployment workflow would need another CI/CD solution or manual execution.
⭐⭐⭐⭐⭐ FOLLOW-UP

21. If I Remove Kubernetes, Can Docker Run the Application?

Yes. Docker can run the application directly on a host. Kubernetes becomes valuable when we need orchestration features such as scaling, self-healing, service discovery and rolling deployments across multiple workloads.
⭐⭐⭐⭐⭐ FOLLOW-UP

22. What Is the Difference Between Terraform and Jenkins?

Terraform manages infrastructure. Jenkins automates CI/CD workflows. They can work together, but they solve different problems.
