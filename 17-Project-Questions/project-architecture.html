Interview Explanation:

The architecture starts with the developer pushing application code to GitHub. Jenkins detects the change and starts the CI/CD pipeline.

The pipeline performs build and testing activities and creates a Docker image. The image is pushed to a container registry.

The container image is then deployed to Kubernetes running on AWS. Prometheus collects metrics and Grafana provides visualization.

5. Why Separate Infrastructure and Application Deployment?

Infrastructure and application deployment have different responsibilities. Terraform: creates and manages infrastructure. CI/CD: builds and deploys the application. This separation makes the architecture easier to maintain and reduces unnecessary infrastructure changes during application deployments.
⭐⭐⭐⭐⭐ VERY IMPORTANT

6. Why Kubernetes?

Kubernetes provides the orchestration layer for containers. It manages:
  • Pod scheduling
  • Service discovery
  • Scaling
  • Self-healing
  • Rolling deployments
  • Desired-state management
This is more suitable for managing multiple application instances than manually running Docker containers.
⭐⭐⭐⭐⭐

7. How Does Kubernetes Achieve High Availability?

Multiple replicas can run simultaneously. If one Pod fails, Kubernetes can create another Pod based on the desired state. A Service provides stable access to the application Pods.
⭐⭐⭐⭐⭐ VERY IMPORTANT

8. What Happens When a Pod Fails?

The Kubernetes controller continuously compares the actual state with the desired state. If a Pod managed by a Deployment fails, Kubernetes can create a replacement Pod to maintain the desired replica count.
⭐⭐⭐⭐

11. What If the New Deployment Fails?

I would first check: 
kubectl get pods
kubectl describe pod <pod-name>
kubectl logs <pod-name>
I would identify whether the problem is related to:
  • Image
  • Configuration
  • Secrets
  • Resources
  • Networking
  • Application startup
If the release is unhealthy, I would use the deployment's rollback capability where appropriate.

13. One-Minute Architecture Explanation

"The architecture follows a standard end-to-end DevOps workflow. The developer pushes code to GitHub, which triggers Jenkins.

Jenkins performs the CI stages such as build, testing and security checks. It then builds a Docker image and pushes it to a container registry.

The application is deployed to Kubernetes running on AWS. Terraform is responsible for provisioning the underlying cloud infrastructure.

For observability, Prometheus collects metrics and Grafana visualizes them through dashboards.

This gives us an automated, repeatable and observable deployment process."
